# Crypto H5 — partial-data and compact-layout evidence

This is the existing H5 visual-evidence owner, expanded for the same PR #8050. It is not a new CI runner or data publisher.

## What is being proved

The actual `scripts.build_crypto.build()` renders a controlled `crypto.cockpit/v1.decision` projection together with existing local research data. The real template and CSS are served on an isolated loopback fixture route. No production site, real user review, notification or trade is written.

| Scenario | Required visible meaning |
| --- | --- |
| `happy` | Known 60% total with a qualified BTC/ETH/alt breakdown and residual cash. |
| `zero` | Valid 0% crypto means 100% cash, not missing data. |
| `unavailable` | No usable canonical target; no numeric exposure, cash inference or asset bar. |
| `stale` | The prior decision belongs to another date; explain the mismatch and hide its old target. |
| `breakdown` | The valid 60% total and 40% cash remain known, but asset destinations are unavailable. |
| `zero-gap` | Valid zero remains all-cash without invoking class-model inputs that are missing. |
| `malformed` | A numeric-looking string is not coerced into canonical authority. |

## Receipts

`EVIDENCE.yml` retains the existing template ownership declaration. `manifest.json` is generated by `scripts/capture_page_evidence.py`, not manually constructed. The five distinct visual scenarios use desktop/mobile × EN/ZH × dark/light REST captures. `proof_summary.json` binds the exact source commit/file hashes and completed capture counts. Each PNG is checked against its manifest digest.

`browser_matrix.json` contains the independent semantic/geometry run: all seven scenarios at 320, 390, 768 and 1440 pixels, both languages and both themes. It checks nested card geometry, not merely document overflow, and measures explanatory text at no less than 14px. The screenshot matrix does not substitute for these assertions.

`before_mobile_fix.json` preserves the first two inner-card failures, which occurred despite zero page-wide scrolling. `source_merge_review.json` records the no-conflict merge simulation with the exact #7645 template head. These are real negative/result receipts, not a synthetic claim of participant testing.

The copied `render_crypto_h5_states.py` and `browser_check_crypto_h5.py` are the exact Studio fixture harnesses used. They reference the named M2 workspace and loopback fixture directory, do not run in normal CI, and do not invoke deployment. The product regressions remain in the existing `tests/test_crypto_wave2.py` owner and existing Vector/Crypto CI commands.

## Limitations

The decision examples are controlled, not current investment recommendations. Other page data is a local snapshot. Missing fixture font, icon, account and Terminal overlay resources are retained in network/error receipts; this is not complete production-shell or font-parity proof. The shared Crypto floating Brain control was not changed; its broader page placement remains separate from this H5 slice. No usability participant study, full accessibility certification or live deployment acceptance is implied.

The next release gate is exact-current-head PR CI/fences, independent acceptance/release ordering and combined-source regeneration with #7645 before testing the deployed route. Never merge generated HTML conflicts by treating them as another allocation authority.
