## (b) JS-mounted modules with no template anchor

These mount content via JS at runtime, with no Jinja template anchor:

1. **Live quote refresh on `nb-px` / `nb-chg` elements** — `templates/data_base.js` (alias `site/data_base.js`) rewrites `fetch()` to the R2 data plane when `window.DATA_BASE` is set. Mounted via `data-sym`, `data-mkt`, `data-bare` attributes, present everywhere inside the Markets isle (`mx5-mkt-grid` tiles). Also used by Holdings/Allocation across the rest of the site.
2. **`mx5OpenDlg` / `mx5CloseDlg` / `mx5TogglePop` / `mx5TogglePath` / `mx5CloseAllPopovers`** — inlined JavaScript at the bottom of `templates/dashboard.html.j2` (~line 1864+). Wires every isle surface to its corresponding dialog.
3. **`mxqm-glance` body** in the flip-context popover — populated from a JSON blob injected via `vm["flip_plain"]` and a wide rule-out table; no separate template.
4. **Heatmap mount** — `heatmap-scorecard` mount point receives its content from the lazy-loaded `heatmap.js`, with the inject stub `mmLoadHeatmap()` in `<head>`. Identical pattern across macro.html / macro_context.html / sector_central.html.
5. **Pull-back odds ring** — `riskdlg-odds-h` mount is populated from `engine/risk_radar.py` data, but the chart geometry is JS-rendered (not a Jinja partial).
6. **`mx5-aurora`** CSS-only background — no JS.
7. **Theme switch (dark / light) + i18n (EN / ZH)** — `localStorage`-driven `data-theme` and `data-lang` attribute setters in inline `<script>` in `<head>`, no template anchor.
8. **RR-calibration modal "RR-track-record"** — built entirely from a JS string-builder inside `_track_record_dlg.html.j2`, no Jinja anchor.
