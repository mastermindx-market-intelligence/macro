# Fable mode — execution entrypoint

Finish the assigned outcome with the least unnecessary coordination and context.
This is procedural support, not a role assignment, permission grant, lifecycle,
retry system, memory store or release authority. The current assignment, applicable
repository/host rules, protected procedure and real resource controls govern.

## Start once, then advance the work

Recover the requested outcome, accepted evidence, actual effects and next useful
action. Reuse the current compatible Mastermind procedure pin and compact frontier.
For substantial governed work, ACTIVE_EXECUTION owns continuation and finalization;
SESSION_RELIABILITY owns safe recovery. Do not reload the package after each phase,
tool call, unchanged status or unrelated merge. References below are navigation,
not a requirement to read every playbook before an ordinary repair.

Choose ordinary reversible implementation details under the current assignment.
No extra approval, design-signoff, pickup form or hierarchy relay is created by
this skill. A real reserved decision or platform-required consent remains real.
A role is not a permanently available model or conversation: an archived chat is
not a live receiver, active writer or waiting worker. Reconcile actual writer,
lease and effect state through the existing owner; do not demand a ghost's reply.

Execute the highest-value safe action, verify it proportionately, save a compact
material delta, then start the next safe ready phase. A passing test, plan, review,
PR or checkpoint does not complete an end-to-end mission. Conversely, do not invent
an unrelated deployment or project merely to keep a finished source task alive.
Acceptance follows the assigned effect and actual release controls.

## Evidence, delegation and failure boundaries

Use primary artifacts and discriminating checks, not plausible narrative. A
worker's report is a pointer to evidence; inspect what the next decision requires.
DO_NOT_REDO accepted work without a relevant source, dependency, behavior or
authority change. Reusing unchanged evidence is not a new claim that it ran now.
Two equivalent no-delta cycles require a changed diagnosis, tactic or in-scope
lane, not another identical test, report or status loop.

Delegate separable outcomes through the existing admitted Fabric when that lowers
total framing, review and repair cost. Preserve current native-model policy,
original root, grants, shared capacity and budgets; no new worker permission is
created here. Keep useful principal work moving while workers run. Do not duplicate
an active assignment or replace an uncertain operation. Every launched lane needs
one owner, one verified return binding and a real identity. A transport receipt,
queued job or terminal handle alone proves neither Worker START nor a wakeable
parent. No watcher is added merely to decorate safe foreground work.

An explicit permission or safety refusal ends that effect's retry. Never change
accounts, tools, models or carriers to obtain the refused effect. A known human-only
control needs no repeated probing. Diagnose ordinary technical failures within the
assignment; apply a boundary only to the action that depends on it. EFFECT_UNKNOWN
stays on its original carrier until reconciled. A new chat does not clear effects,
transfer a started job or displace a live source writer. Existing holds and real
review/release protections remain binding.

Sessions are not daemons. A genuine stop follows the governing procedure and leaves
the accepted result, unfinished obligation, actual blocker and exact next action
recoverable. Never claim background reasoning, automatic session creation, worker
consumption or all-account installation without observed evidence.
