Two details that make this worse than a phase bug, and are the reason it survived a
green test suite for so long:

1. **The count differs, not just the keys.** With anchor index 0 the engine opens a
   PARTIAL first bucket — row 0 alone — which offsets every later bar by one row.
   Partial buckets are a permanent feature of the canonical grid, not an edge case,
   and any test that only compares bar COUNTS on a full-history feed will miss this
   by one and may be written off as an off-by-one in the test.

2. **A full-history feed hides the phase half entirely.** Production US documents are
   IPO-complete after the full-history backfill, so feed-start phase coincidentally
   EQUALS IPO phase for those symbols and `basis` comes back as an honest index 0.
   The phase half of this defect therefore only bites truncated feeds — but the
   IDENTITY half (opening vs closing session key) bites every symbol, every bar.
   A reproduction attempted only on a full-history US name will show the identity
   defect and silently miss the phase defect.
