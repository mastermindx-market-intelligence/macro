# Macro Alert Center — continuation handoff

## Mission and why it matters

Turn the shared Macro Alert Center into a flagship **actionable market-intelligence desk**. The user should not decode machine metadata or read repeated helper prose. Within seconds they should see: **what changed, how much attention it deserves, why it matters, the one limitation that changes how to use it, and the next useful action**. Full evidence, clocks, validation receipts and history remain available behind interaction.

This is more than UI polish. The product must learn to express the real semantics of heterogeneous Macro engines without inventing a universal confidence score or a second intelligence plane. The moat is Mastermind's existing source-owned signals plus concise, accurate interpretation and evidence-return workflow.

## User journey

**Now:** Review first -> Watch next -> For awareness. Priority cards expose the change, implication, decisive limitation and specific next step. They should not drown the user in repeated source/date/sample/status labels.

**Inspect:** Takeaway first, then Evidence and History. Preserve original event clocks and known values. Show a separate current read only when an accepted source owner can actually provide it. Current source dashboard handoff must be labeled current, not historical.

**Explore / History:** power-user completeness, search/filtering, chronology, related observations and original firings. They must not steal acreage from the first decision loop.

**Mobile:** same hierarchy, not a squeezed desktop table. Full-screen detail, direct Back, no clipped CTA, minimal chrome.

## Deterministic versus model method

Deterministic/source-owned: alert identity/type/subject, tier, post-governance severity, canonical priority and components, event/source/record clocks, source action, source links, recurrence counts, coverage, validation rows and exact structured values.

Reviewed presentation logic: plain headline, compatible before/after/magnitude, implication, decisive limitation, specific next step and reassessment condition. Family-specific mapping must cite/derive from the owning source contract and abstain on unsupported shapes.

Model assistance, later and optional: evidence-bound comparison/explanation. It may not promote/rank alerts, mint event identity, turn sentiment into urgency, assert missing persistence/current state, or originate a trade/notification. Model outage cannot destroy the source-only product.

## Completion and production proof

Do **not** call this program complete when Figma is polished or a local presenter passes tests. Completion requires real canonical inputs through the current production build path to a visible deployed result; a primary user can understand the top changes and next actions; source/time/null/correction semantics remain truthful; dark/light + EN/ZH + mobile and failure states work; and the evidence return path is real. CI/merge/deploy/browser proof remain separate receipts.

## Stop / return conditions

Return to Sol/Chairman instead of guessing when: a source family has no accepted semantics for the implication/action you want to display; identity/time/current-state joins are ambiguous; two owners conflict; a requested feature would create a second event/score/private-monitor system; a model would become ranking/trading authority; effect state is unknown; or a current source-law change invalidates this handoff.

Otherwise, continue end-to-end through the next dependency rather than stopping at another document or mockup.
