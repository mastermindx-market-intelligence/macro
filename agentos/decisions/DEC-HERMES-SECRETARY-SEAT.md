# Hermes Secretary proposal: recorded scope and evidence boundary

This decision records the factual status of published source. Confidence is high
in that classification; it does not attest to the reported mandate, installed
integrations, account ownership or scheduled jobs.

## Reported November 6 context

The original DEC attributes a future Secretary role and autonomous setup request
to a Chairman conversation on November 6, 2026. That attribution is retained as
reported intent. The originating conversation or a separate canonical adoption
receipt is not supplied by this record.

The proposed work remains company operations support: channel and repository
monitoring within actual access, briefs, records, drafts and a proposed cadence.
The original references to a Hermes `secretary` profile, Slack account alias,
Linear access and cron cadence describe the proposal or reported setup. They do
not establish account binding, access, installation or job acceptance.

## Existing authority and delivery

Use the current Chairman assignment, existing action-specific admission and the
canonical owners for each actual operation. The portfolio A0-A7 taxonomy does
not itself authorize company actions; this DEC grants no capital, portfolio or
trading authority at any level. Reversibility alone is not an operating grant.

The supplied Grok contact convention remains the documented Grok identity and
channel/thread convention. It does not prove a shared Hermes identity or appoint
a new account owner. The existing Executive OS, Agent OS, GitHub, Linear and Slack
ownership boundaries continue to apply as described in the merged companion.

Separately evidenced appointments or grants retain their actual scope. This
source correction neither revokes them nor requires a new Chairman
acknowledgment for already-authorized work. Ordinary protected source delivery
uses the applicable repository rules and existing review policy.

## Evidence for later operational claims

A later source claim should bind the corresponding existing receipt: mandate or
adoption, admitted action and session, service/account identity, installed
integration, scheduler identity and timezone, or the actual execution/return.
Reuse valid original receipts and preserve live writers or uncertain effects.
Do not infer these facts from a model label, profile name, proposed cadence,
source merge or the fact that two documents cite one another.

The original revision remains linked above as historical provenance. Later
canonical evidence or a changed Chairman mandate can refine this classification
through ordinary source revision. The role proposal's publication and this
record's merge do not activate a runtime, install a cron job, send a message or
establish live integration proof.
