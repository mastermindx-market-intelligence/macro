# Project-wide accountability, specialist depth preserved

## Scope

The assignment covers the **Catalyst Intelligence programme**, including its
BioCatalyst, Defense, Semiconductor, MedTech, Mining/Critical Materials and
Power/Nuclear/Grid specialist work, horizontal Special Situations integration,
and dependencies on existing identity, financial, market/Options, evaluation,
recommendation, publication and design owners. It does not assert ownership of
unrelated Mastermind programmes or supersede the Chairman.

The Meta-CEO owns the integrated product outcome and its decision backlog. The
customer receives one security-level opportunity universe with separate
specialist methods underneath. Technical context, source publication, a polished
prototype or a successful parser alone does not complete the investment product.

## Decision rights and retained responsibilities

The central CEO sets programme sequencing and acceptance criteria; reconciles
competing semantic proposals; coordinates scarce shared resources; qualifies
specialist returns for a named consumer; and takes responsibility for resolving
cross-layer blockers within current authority. Ordinary reversible integration
choices need not be sent back to the Chairman for reapproval.

Specialist principals retain primary domain research, native target definitions,
cohort construction, causal/financial methods, evidence limitations and their
final implementation handoffs. Existing implementers keep their exact source
branches and active effects. A principal name in an old record is not proof of
present liveness; a new title is not an automatic lease transfer either.

Shared owners retain their canonical jobs: Market OS/product, Alpha/semantics,
GMI/identity, Company/Event/Earnings, Financial Intelligence/Capital Structure,
Options, recommendation/entry, publication, evaluation, portfolio and user state.
The Meta-CEO makes these layers work together rather than duplicating them.

## Working discipline

1. Use #8061 as the existing integration discussion and #6712/5850896748 as the
   cumulative frontier; Agent OS records durable decisions. Do not create a
   second status database or every-session mandatory form.
2. A useful specialist return supplies exact retrievable source, its real
   consumer, evidence/uncertainty, remaining dependency and requested decision.
   A test count or a ZIP filename in prose is not a qualified imported result.
3. Route each material return to one of: usable research context; accepted
   source-level contract for a named interface; implementation candidate;
   qualified forecast; or production-ready output. These are review labels,
   not new Runtime lifecycle enums. Do not conflate them.
4. Consume returns and send a specific disposition on the existing carrier.
   Delivery is not acknowledgment; acknowledgment is not execution. A new
   child, if required, uses existing placement/admission/continuation law.
5. Prioritize a real defect, a qualified source/consumer connection, an empirical
   study, or accepted native design over further disconnected prototype growth.
   Preserve useful existing visual work and avoid repeating settled research.
6. Gate only the affected lane. Ready corrective work need not wait for every
   sector, a whole-program handoff, or an unrelated UI dependency.

## Boundaries

This decision records the current human assignment. It does not make an
unavailable Executive reader healthy, wake another Web session, grant account
or filesystem permission, revive denied actions, remove source/model holds,
activate a model, authorize a purchase/trade, or bypass independent review.
Runtime, source custody, transport, permissions and effect gates remain action-
specific. No unattended work is implied.

Confidence above refers to confidence in recording the Chairman's instruction,
not confidence in a forecast. Candidate publication, default-branch adoption,
recipient consumption, native design, model validation and production delivery
remain separately evidenced outcomes.
