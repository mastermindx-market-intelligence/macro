# CI dependency constraints (F3, CI Lightning).
#
# WHAT THIS IS: the single freeze on every package the legacy CI jobs
# `pip install` at runtime. `.github/workflows/ci.yml` exports
# PIP_CONSTRAINT=$GITHUB_WORKSPACE/ci/constraints.txt for the ci-pack runner
# path (and the ci-plan / contract-delta control-plane installs), so an
# upstream release cannot change what CI installs between two runs of the
# same commit. That is the whole fix for the 2026-11-09 Playwright 1.65.0
# drift class: 44 failed runs / 229 job-hours in 48 h from one release.
#
# WHY THIS PATH: it lives OUTSIDE `.github/ci/` and `.github/workflows/`, so
# editing it is not a CI-definition change for the merge-on-green controller
# (`CI_DEFINITION_TREES`) and does not stale every armed PR's proof. It IS a
# planner GLOBAL_INVALIDATORS entry (`**/constraints*.txt` in
# scripts/run_ci_pack.py), which is correct and kept: a PR that changes what
# CI installs must run the full suite. There is no path that avoids the
# planner entry (the pattern matches the filename anywhere), and none should.
#
# VERSION PROVENANCE. Two tiers, marked per line:
#   [green-run] observed installed by a SUCCESSFUL full-suite main proof
#     (workflow_dispatch run 42558876818, 2026-11-08; retained pack logs for
#     ci-pack-7/ci-pack-10 record `Successfully installed <pkg>-<ver>`).
#   [pypi] not present in the retained pack logs (those jobs ran in packs
#     whose logs were not retained); pinned at the current PyPI resolution —
#     exactly what an unconstrained green run installs today — so the pin
#     freezes the passing set rather than changing it.
# The one deliberate exception is `playwright`: 1.65.0 (2026-11-09) is the
# known regression; 1.64.1 is the last version the native browser plan
# qualifies (scripts/ci_apt_native_plan.py::QUALIFIED_PLAYWRIGHT_VERSION),
# matching the explicit job pins in .github/ci/legacy-jobs.yml.
#
# ONE VERSION PER PACKAGE, always. Where the manifest pins one job explicitly
# (numpy==2.3.5, rjsmin==1.2.5) while other jobs install unpinned, the pin
# takes the explicitly pinned version and every unpinned job converges on it
# (the green run had resolved those unpinned jobs to numpy 2.5.4 / rjsmin
# 1.3.0; both pinned versions are individually green on main, and unifying
# removes the dual-version slot a `pkg==A,==B` constraint would need — pip 26
# refuses that form against an explicit `==A` requirement, so it is not an
# option at all).
#
# REFRESHING: bump versions deliberately (a PR touching this file runs the
# full suite by design). Refresh strategy: copy the `Successfully installed`
# versions from a green full-suite main proof.
#
# NOT covered: transitive dependencies (they follow the direct pins) and
# requirements/tiingo.txt's own `websocket-client>=1.8,<2` (that file is a
# pinned-in-repo requirements law; editing it is a global invalidator).
# The Playwright browser BINARIES are governed separately by
# scripts/ci_apt_native_plan.py (nativeDeps bundle), not by this file.
