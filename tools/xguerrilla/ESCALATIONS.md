# Questions and incidents use the existing owners

The harness has no active local escalation queue. Runtime binding is unavailable;
workers cannot acquire authority by creating files, answering their own question,
refreshing a health row or continuing a different role.

Use the existing GitHub source/evidence record and Agent OS durable continuity
for a source question or incident. Runtime admission and original action/effect
settlement belong to the existing Executive OS and action owners. A transport
message is not an approval or a START receipt.

For a future real integration, retain the canonical account, approved item,
original holder, receipt and profile ownership references. An uncertain action
must be reconciled with its original owner; do not create a replacement action,
queue, local lease, escalation folder or retry route.

The previous open/answered/superseded folder proposal is retained only in Git
history and is not installed or used by this source. RUNBOOK.md states the
current unavailable-runtime behavior. PILOT_PLAYBOOK.md preserves historical
planning context without authorizing execution.

Questions about actual credentials, platform permission or physical ceremonies
remain exact human controls when needed. Routine source repair is handled by the
assigned session without reviving old-chat or named-writer approval gates.
