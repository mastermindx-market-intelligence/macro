# Selection and current-source census

**Decision:** Financial Intelligence Fabric is the strongest eligible next project in the inspected portfolio. This is a reasoned ranking of execution difficulty and unfinished product depth, not a numerical proof that no unseen project is harder.

## 1. What was compared

The author enumerated **92 tracked workstream filenames** at Macro `44a45369617dbbd0afdcf161682679640352a554`, then read the relevant financial, earnings, capital, BioCatalyst, Market Memory, Research Vault, Rates, China and Defense records and searched their recent PRs. That is a portfolio filename census plus focused technical assessment—not a claim to have audited every line of 92 programs.

All current and earlier exclusions were retained: Single-Name Intelligence, Grey Deer Risk, Market OS/Mastermind OS, Options Intelligence, Prophet, Market Ontology, Executive OS, Subagent Fabric and GMI. “Financial Intelligence Fabric” refers to the existing accounting product, not the excluded worker Fabric or GMI Finance.

### Strongest counterargument

BioCatalyst or Market Memory may require more novel predictive research than financial parsing. The choice of FIF is not based on novelty alone. Its challenge is making **deterministic accounting truth, semantically valid comparisons and useful analyst delivery** reliable across the full product surface. A new current production census showing FIF already complete across its declared tiers, or that a live incumbent already owns the same remaining full mission, would change the placement decision. The present code and carrier evidence do not show that completion.

## 3. Findings that materially change the plan

### The workstream is stale, but the production gap is real

`WS-FINANCIAL-INTELLIGENCE-FABRIC` still says FIF-3A4R is accepted/on-main/not-built. **#7518 actually merged October 4, 2026**, at merge `4294fd498e8c31cb72424e34b8769a48b1f0afd2`, feature head `07426932618a3458388baa735f7da793fdef82ff`. Its confirmed implementation must be reused. The workstream needs a factual update after owner reconciliation, not a second implementation of the same feature. [S02, S04]

The API source then establishes a different unfinished fact. `_financial_query_provider` and `_financial_statement_provider` still construct golden AAPL providers. The revision and full-packet factories return unavailable providers. This is not just “needs more testing”: the production data/provider connection is absent from those inspected factories. No unobserved deployed configuration override is assumed, and this assessment did not call a live authenticated endpoint. [S08]

### The existing kernel is substantial

At the census pin, the forensics package contains **40 Python modules**. The inspected query kernel has 6,283 lines; lineage evidence 638; the API 1,029; disclosure comparison 2,801; deterministic detectors 442; statement service 321. These counts locate complexity and potential integration cost. They are not quality scores or a recommendation to rewrite large modules. [S06–S12, S17]

Useful existing seams include the raw occurrence ledger, metric governance, bitemporal query engine, packet/query/revision domain adapters, source-native parser, statement graph, identity binding, disclosure matcher and existing private endpoint. A new ledger or “universal financial AI service” would duplicate these owners rather than finish the missing product.

### A reported source-reference defect is still reproducible

The October 4 owner-repair comment on #7518 is not obsolete. Current `query.py` blob `529d9e7df8e6183848fea0a37280e938c0bd9238` and `lineage_evidence.py` blob `2aaac83a73121e55e38f07c1a7b8228691875149` are unchanged at the census pin. The query re-proves selected fields of `positive_evidence`, not the full closed payload supplied by the canonical builder. [S05–S07]

The fresh fourteen-trial experiment rebuilt valid receipt hashes. Nine altered evidence fields were accepted and disclosed while the numeric answer stayed the same. This demonstrates unreliable source-reference binding, **not a changed balance-sheet value, production breach or remote exploit**. Five already-checked controls failed as expected. [S28]

A second isolated process-local wrapper added full canonical evidence equality. It rejected all fourteen mutants and retained the four valid policy-response hashes exactly. This is experimental support for the proposed remedy, not a landed source fix or exhaustive test suite. Both hashes and limitations are packaged. [S29]

### The historical golden fixture remains only a golden fixture

The real parser in the isolated experiment produced 1,722 ledger events and 130 confirmation receipts from the two committed AAPL accessions. The delivery envelope explicitly remained `committed_golden_fixture`, `attested=false`, `production_issuer_service=false`. Reusing these as regression controls is correct; relabeling them as a production issuer service is not. [S12, S14, S28]

The three policy outcomes matter: latest-known can select a later confirmed reprint; as-reported preserves the original; latest-restated is missing without an eligible explicit revision. The pre-lineage system cutoff remains not evaluable. Scale must preserve these semantics, not swap in a newest-value rule.

## 4. Source and product boundaries

**SEC data products must be distinguished.** CompanyFacts APIs aggregate standard-taxonomy whole-entity facts. The SEC Financial Statement Data Sets were reprocessed to use rendered primary-statement data and added a `segments` field. Neither fact justifies claiming all SEC feeds are non-dimensional, or treating a bulk value as a complete source package with historical system admission. Source-product selection is per use case. [E01, E02]

**Source trust and semantic truth are different.** A retained filing hash does not prove that the chosen metric, denominator, period or dimension is appropriate. A consistent rounded duplicate is not automatically an explicit cross-filing confirmation; confirmation is not revision. Arelle is a potential independent validation oracle, not a replacement mapping authority. [E04–E06]

**The analyst route exists in the original architecture; current integration must be inspected.** The intended existing path is `fundamental_forensics.html` and its associated builder/templates. The legacy nine-metric/five-detector description belongs to the dated masterplan; it was not counted as a fresh live product test. The current Terminal path census returned no dedicated forensics-named path. Generic Company Intelligence reuse is possible but is not a proven FIF Terminal deployment. [S03, S18, S19]

**Legacy source recovery and attestation are lane-specific.** The Fundamental Forensics and Calcbench-parity records contain historical source/backlog/credential gates. They must be reconciled before the relevant source or trusted-history action. They do not justify rerunning old workflows blindly, reading secrets as part of planning, or stopping all independent gold/schema/product work. [S15, S16]

## 5. Risks and discriminating evidence

| Failure mode | Evidence that distinguishes a correct implementation |
|---|---|
| Valid hash over false evidence | Rehashed independent field mutants are rejected against the eligible ledger. |
| Current knowledge presented as historical | Source, system and policy clocks exclude facts/rules unavailable at the requested cutoff. |
| Comparative repetition called a restatement | Separate confirmation and revision relations, with latest-restated explicitly absent when appropriate. |
| Broad data coverage without semantic depth | Issuer/period/field manifests and refusal denominators, not headline ticker count. |
| One accounting formula used across unlike companies | BAC/CAT/SNOW stress cases with explicit applicability and independent domain review. |
| Golden data silently standing in for production | Separate delivery labels, real retained sources and installed source-to-browser evidence. |
| Polished model-generated accusations | Evidence-bound observation/hypothesis distinction, alternatives and measured false positives. |
| New infrastructure replacing existing owners | Exact source/service reuse map and no second ledger, graph, auth, queue or scheduler. |
| API and spreadsheet disagree | Canonical value/basis/cutoff/source roundtrip including actual Excel refresh. |
| Fleet adds context cost and conflicts | Bounded native coordinators, disjoint Fabric operators, shared budget and verified consumed returns. |

## 6. What remains unverified

No production browser/API journey, current paid-data entitlement, full pytest suite, broad issuer coverage, live native/Fabric hierarchy, deployment permission or final scientific/quality result was proven during authoring. Actual source custody and any newer repair must be checked by the receiving owner. The source pins and exact fresh experiment delimit what is known.

The authoring package contains a detailed first repair/production plan, an included-scope legacy map, 39 tasks, 54 acceptance cases, twelve pack contracts and reproducible diagnostics. These are proposed implementation obligations, not reports that the tasks ran. Publication of this package does not dispatch Fable or change the excluded projects.
