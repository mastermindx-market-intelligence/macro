## 5. P1 contract design

Keep engine.group_pulse as the sole observation producer. Add engine/group_member_observations.py only as a pure projector/serializer/validator over its existing in-memory panels and member sets. It owns no acquisition, membership decision, graph, clock, ledger, worker or independent source store.

Companion schema: group_member_observations.v1.
Machine-readable projection: site/basketdata/member_observations.json, under the existing publication family.
First real consumer: scripts/build_theme_detail.py plus templates/basket_detail.html.j2, bound to the same per-group legacy read.

A companion preserves strict v1 clients. Widening member_context.json is rejected because it belongs to a different interpretation. A new service/database is rejected because computation and consumption already exist.

Envelope: schema, authority=context_only, as_of, generated_at, source references, groups, projection_digest. Use the existing canonical JSON/hash utility. Digest self-fields are excluded consistently. A content checksum is a reference, not a new authority or identity system.

Group: existing group_id/kind, source membership reference/digest, member_count, complete member_keys/members, metrics, legacy_pulse_digest and coverage_details. The initial kind is current curated basket; do not relabel it a structural industry or canonical economic theme.

Per-member metric: value, canonical Data OS null_reason, domain estimability_reason, recipe_id, effective_at, source_ref, observations_available/required, included_in_aggregate. Meaningful false is an observation, not null. Do not use zero as absence. Keep source-native identity when canonical identity is unavailable; never mint an issuer from a ticker or describe ticker count as unique-company count.

Aggregate: recipe, unit, basis, benchmark reference, window/minimum observations, membership digest, exact observed member keys, excluded members/reasons, numerator member keys/count, denominator, value/null reason and cohort digest. Numerator must be a subset of observed members. Observed/excluded sets must account for the relevant population. Cohort alone is not the observation identity: recipe, source epoch, effective date and membership version also bind it.

Receipts are captured from actually consumed bytes or owner-returned normalized frames. A normalized-frame hash must be labelled as such, not claimed as a raw acquisition receipt. No post-compute re-read of a mutable source can establish what the earlier calculation consumed.

## 6. Clocks and corrections

P1 preserves current Group Pulse effective-date selection; it does not add an unrestricted historical-cutoff API. Each context leg keeps its actual date. One publication generation does not imply every pre-existing panel has the same effective date. In particular, a fresh member observation cannot quietly inherit an older decision-panel date.

A later common-cutoff feature must reuse the existing calendar owner and clip all data before computing dependent state, not select a historical row after current washout/stage computation. Current-membership historical backfill remains forbidden.

A new input vintage creates a new observation even when as_of is unchanged. The HUBB example must remain distinguishable. Improved coverage is not new market rotation. P1 does not invent a correction/event store; it retains existing source lineage and actual digests.

Coverage bounds for boolean predicates are [k/N, (k+N-n)/N] only where complete source membership N is known. They are missing-observation bounds, not statistical confidence or forecast probability. Publish true numerator counts; never reconstruct them from rounded percentages in production.
