## P1 design corrections

### 1. Bind original bytes, not cross-language object serialization

`engine/company_theme_exposure/contracts.py` at the source pin, blob `eb1b5136f220027c746eb086b3403b77e3bbdc13`, defines sorted finite UTF-8 JSON with a trailing newline. An executed Python/Node example parses equal values but serializes integer-looking floats, negative zero and exponent forms differently. Therefore:

```text
trusted expected digest -> SHA256(original response bytes) -> compare -> parse -> owner validation
```

Do not parse and reserialize in the browser to check the original wire digest. Do not treat a digest supplied only by the same untrusted body as authentication. The real adapter imports the existing owner utility. The preview's subset checks are not a replacement for the strict backend or proof of validator parity.

### 2. Separate transport, observation and presentation changes

A new delivery timestamp or translated display name must not create a new market observation. The lab preserves separate complete-wire and measurement/evidence checksums. Membership meaning uses owner identity references, not display-label spelling. Changed definition/mapping/identity remains a substantive owner-version change, not presentation.

A production adapter must keep timestamped legacy `pulse.json` hashes in pair/publication binding rather than the semantic observation checksum; otherwise every render becomes new evidence. These are checksums under existing publication/identity owners, not a second generation authority.

The executed fixed-date synthetic example changes from 14/21 measured successes (66.67%) to 14/22 (63.64%) when F024 becomes observable. All 21 common members retain 14 successes. Comparison identifies the entered member and returns INPUT_VERSION_CHANGE_NOT_A_NEW_SESSION, not market deterioration. The same-date R4 real-input reproduction is retained and was not repeated here.

### 3. Do not feed a larger display roster into existing scoring

At the source pin, `scripts/build_theme_detail.py:257-326`, blob `2592a094577cd9014a3006ffe89f9d84b294160c`, builds `members` from the supplied basket and calls `basket_score.act_now_stocks(members, th)`.

P1 must preserve that legacy/action list and the exact call arguments. Add a separately named complete inspection roster from owner-captured membership. Do not overwrite `members` with newly displayable unmeasured securities and accidentally change action output. Regression: capture the existing action function's before/after arguments and prove unchanged while inspection retains the extra member. This is a source-level integration hazard, not a demonstrated current scoring incident.

### 4. Hash-matching old files do not prove this invocation succeeded

The inherited Group Pulse hook is additive/fail-soft. If it fails, an old pulse and old companion may still agree by date/hash. The strict focused P1 builder must require a successful in-memory capture returned by THIS invocation, then pass that capture to the projector and existing detail render. A failed owner invocation returns nonzero before publication; it must not relabel old disk artifacts as a current result.

No new run/receipt ledger, retry owner or scheduler is needed. Preserve broad-lane behavior, strict focused-lane refusal and nightly-only episode advancement as explicitly tested boundaries.
