**Status:** proposed Fable review catalogue, not executed tests, approval, deployed software, email, or trading permission. Use the current source, original owner and eligible isolated fixtures before running anything. Natural production receipts must be witnessed; manual replay is not natural provenance.

## 1. Evidence stages are not substitutes

| Stage | Can prove | Cannot prove |
|---|---|---|
| Source and formal independent nonauthor review | Exact-head code/design is plausibly correct | Merge, deploy or production effect |
| Isolated synthetic test | Named failure invariant under its fixture | Historical market availability or actual customer delivery |
| Hosted exact-head CI/fences | Candidate passes listed source tests | Release, serving, authenticated consumer or consent |
| Protected merge/deploy receipt | Exact released build exists | The UI or model consumed current market sources |
| Authenticated real user/consumer | Source identity and claim reached actual client | Email was received, or prediction was accurate |
| Outbox/delivery path | Original event→effective consent→logical outbox→provider/recipient | Exactly-once physical SMTP for ambiguous outcomes |
| Prospective science scorecard | Specific registered forecast skill or negative disposition | Automatic capital policy/trading authority |

## 7. Reviewer/release receipt schema

For every source, UI, science or release wave, Fable should require:

1. **Identity:** original EW-Px.Ty, workstream, owner, parent operation, PR/branch, exact base/head and current writer/effect state.
2. **Provenance:** source refs/blob/hashes, observation and publication clocks, source-rights and component coverage, immutable correction ancestry.
3. **Real checks:** test names and actual run IDs, isolated versus hosted versus original natural/served, meaningful failed test and negative control, what was not exercised.
4. **Independent review:** nonauthor reviewer model/identity, reviewed exact head, formal gate verdict, remaining scope and whether child dialogue ended with STOP.
5. **Effect claim:** merged SHA, deployed version/origin, authenticated user/BFF/model prompt, consent activation/revocation, provider and inbox/deep-link receipts—only what actually happened.
6. **Held unknowns:** undelivered, malformed, rights, SMTP unknown, previously refused native host operation, unproven runner readiness. Do not turn UNKNOWN into PASS.
7. **Rollback:** owned mechanism to stop new admission/alert while retaining original history, consent revision, pending/uncertain mail and ledger. No destructive reset.
