### PA-01 — The current-page acceptance rule conflicts with the specification, and Today keeps a competing visual cue

**Severity:** Medium. **Class:** observed source contradiction plus native presentation ambiguity. **Disposition:** Open.

**Evidence.** `PRODUCT_UX_SPEC.md` §3 explicitly permits an unmapped specialist route to have **no** current primary job and prohibits a fallback to Today. `ACCEPTANCE_TESTS.md` N01 visits specialist families but requires “One primary global destination,” without the zero-current exception. `SOURCE_AND_DATA_CONTRACT.md` §3 identifies the existing Today fallback and competing market treatment as the behavior to improve. In A and C, Today remains semibold with the only blue primary-navigation icon; C separately fills and emphasizes Analysis. In C's export, nodes `709T-0`/`709S-0` retain the info-colored icon and weight 600, while `709K-0` identifies Analysis as selected. H retains the same blue Today icon (`710R-0`) while the Market overview shortcut has the selected fill.

**User consequence.** A builder can satisfy the literal N01 oracle by selecting a workspace on every specialist route, recreating the fallback the specification rejects. The retained Today emphasis also weakens confidence that the new visual system has eliminated competing location cues. This is not a claim that the design exports emit duplicate `aria-current` attributes; those semantics were not executed.

**Smallest closure.** Make N01 require **at most one correctly mapped primary current destination**, explicitly test zero for a route with no qualified primary mapping, and keep the actual product title/shortcut visible. Neutralize the inherited Today emphasis in non-Today native specimens unless F01/F03 define a distinct, non-current meaning for it. Review one mapped Company case, one market case, and one unmapped specialist case against the same rule. Preserve F03's admission boundary.

### PA-02 — Explicit compact mode has no concrete entry and exit path

**Severity:** Medium. **Class:** observed design/specification omission. **Disposition:** Open.

**Evidence.** `PRODUCT_UX_SPEC.md` §2 and the joint contract §2 call H an explicit user choice and prohibit automatic collapse to fit evidence. A and H show expanded and compact states, but neither image presents an identifiable collapse/expand action. H's exported rail contains logo, destination/shortcut icons, AI, All tools, and account, with no specified mode control. No source clause identifies a settings/menu path for selecting and reversing the mode. G07 preserves an already selected compact preference during resize but does not exercise choosing or leaving it.

**User consequence.** The width strategy relies on a choice a user cannot locate from the reviewable design. An implementer must invent its discovery, keyboard access, restoration, and persistence semantics; the user may end up unable to return to labels after choosing compact mode.

**Smallest closure.** Specify and depict the actual existing-owner control or settings path in both states, including its visible/accessible names and where focus lands after the transition. Identify the existing preference scope without inventing a new storage owner. Add one acceptance journey: expanded → explicit compact → open/close evidence → resize below and above the drawer boundary → expanded, with the chosen preference preserved and no automatic mode change. This is a design completion request, not a demand that static JSX implement a toggle.

**The data truth is generally careful.** A/E disclose an illustrative observation and partial coverage; C labels the value illustrative and says no filing citation is supplied; D separates transport/session/source information and limits interpretation of an at-ask print.
