## 3. Contradictions and corrections that matter

### 3.1 The missing contract is an acknowledgment, not the existence of `close()`

The actual widget exports `open`, `close`, `toggle`, `explain`, `setPrincipal`, `expand` and `mounted`. Terminal's [mastermindBrain.ts](https://github.com/mastermindx-market-intelligence/mastermind-terminal/blob/3cc8da8432d8d2d4e4cb597f49c4eaa95f1980c9/terminal/lib/mastermindBrain.ts) types only a subset. Its opener returns true after invoking `open`; that return value does not acknowledge visibility. `mounted` and `mm-brain-ready` establish installation readiness, not an open or closed state.

In `mm_brain.js`, `close()` tests whether focus was inside the widget before dismissal. Only in that case does it call `CFG.onClose`; a true callback result means the host restored focus and suppresses the launcher's fallback. Consequently that hook is not an all-path close notification. [BrainWidget.tsx](https://github.com/mastermindx-market-intelligence/mastermind-terminal/blob/3cc8da8432d8d2d4e4cb597f49c4eaa95f1980c9/terminal/components/BrainWidget.tsx) exposes no `onClose` prop or qualified visibility binding. Merely extending its TypeScript type would not close this gap.

The widget captures its configuration object once and survives host unmount. Existing host callbacks have ownership-aware binding/cleanup. Any future integration must preserve that discipline and the singleton; an unrelated global observer, private-class poll, parallel script injection or copied assistant state would create a second owner. [AnalysisBrainHost.tsx](https://github.com/mastermindx-market-intelligence/mastermind-terminal/blob/3cc8da8432d8d2d4e4cb597f49c4eaa95f1980c9/terminal/components/chrome/AnalysisBrainHost.tsx) additionally guards its context provider against stale/unmounted use.

### 3.2 F01 policy ownership does not transfer Brain service ownership to D06

The joint contract's sentence that D06 retains focused Terminal and “the single Brain owner” is too broad if read as assigning the widget lifecycle or service to D06. F01 owns shared-shell arbitration policy; F02 owns shared accessibility/component primitives; D06 owns focused Terminal composition and its consumer integration. The existing Brain/D14 owner retains widget lifecycle, request and context semantics. Terminal's host owner binds that actual interface. Preserve one assistant instance and its existing principal/request owners across these responsibilities.

The shared evidence inspector is a read-only source detail surface. Terminal's analytical reader is a different existing object. In [TerminalShell.tsx](https://github.com/mastermindx-market-intelligence/mastermind-terminal/blob/3cc8da8432d8d2d4e4cb597f49c4eaa95f1980c9/terminal/components/TerminalShell.tsx), `railW` starts at 360px, restoration and resize clamp to 300–520px, and the existing `mm.railW` owner persists the final width. D06 observed 360→460px resizing and independent reader scroll. That evidence does not qualify all persistence/rendering invariants, but it is sufficient to reject a silent replacement with F01's 320px dock.

### 3.3 Current Terminal coexistence differs from the proposed suspension policy

D06 observed Brain over a historical reader that remained present and consumed width. It observed composer focus after asynchronous opening, visible Close hiding Brain with BODY focus, and Escape behavior that did not match source panel closure. Those observations contradict any assertion that candidate.3 suspension, focus restoration or modal semantics already work. They do not prevent F01 from proposing those policies for shared-shell surfaces.

The widget's source Escape chain dismisses its slash palette, then context inspector, then stops a stream, then closes search, and only then closes the panel. Its document listener calls `preventDefault`, while the chart's window listener in [ChartPanel.tsx](https://github.com/mastermindx-market-intelligence/mastermind-terminal/blob/3cc8da8432d8d2d4e4cb597f49c4eaa95f1980c9/terminal/components/ChartPanel.tsx) has input/textarea and selected-menu exclusions but no general `defaultPrevented`/active-modal guard. This creates a source-derived event-ownership risk when focus is on other Brain controls. It is not a diagnosis of D06's served-script discrepancy. An outer “Escape always closes Brain” rule would also wrongly bypass the existing stream Stop and nested disclosure behavior.

### 3.4 Exact URL return and restoration of the analytical workspace are different promises

[originNav.ts](https://github.com/mastermindx-market-intelligence/mastermind-terminal/blob/3cc8da8432d8d2d4e4cb597f49c4eaa95f1980c9/terminal/lib/originNav.ts) binds `safeMacroHref`, `useFromMacro` and `backToMacro`. The last function uses the trusted embedded `terminal:close` path when available; otherwise it calls `window.location.assign`. Its earlier comment describing a browser-Back shortcut is stale relative to the function body. An accepted href round trip therefore does not prove native row, selection, scroll, focus or browser-history restoration.

D06 supplies new, bounded evidence: `/analysis?symbol=AAPL` → Terminal → Back to Analysis returned to that exact Analysis URL. A subsequent symbol-only HK entry retained the previous session origin. The source accounts for this through `mm.fromMacro` / `mm.macroHref`. Do not mark all return/history cases passed, promise that a direct-looking symbol entry clears origin, or add a competing return store. The older F01 Financials `ret` capture and the new D06 completed URL round trip have different coverage.

### 3.5 A selected reader bar is not the current Brain attachment contract

`ChartPanel.inspectVisualTime` updates `visualSelectedTimeRef` and the visual reader. Terminal's AI context revision, readout and native-observation binding use the existing locked-bar/replay path, including `lockedVLine`. D06 observed an Active chart AAPL disclosure without interval/bar acknowledgment. A generic symbol opener, an ambient context envelope, a visual selection and a qualified exact historical source are therefore distinct. “Ask about this bar” remains a D06/D14 interface requirement; it cannot be satisfied by renaming the symbol-only action.

## 4. Proposed normative clauses for the next versioned candidate

These clauses are proposed contract text, not statements that the current product satisfies them. Keep them in the existing F01 carrier. Because focus, slot and return semantics are governed by the contract's change rule, any adopted amendment must appear in the next candidate's explicit change list; it must not silently alter candidate.3 or inherit blanket F02 approval.

### Clause A — consumption and status

Consumers MAY use the cited candidate for source mapping, retention requirements, candidate composition and implementation planning. They MUST retain the stated qualification holds and identify which clauses are existing source behavior, bilateral candidate concurrence or a proposed change. Consumption is not a released foundation, permission to implement, native acceptance or production proof. The current design/research-only instruction remains in force.

### Clause B — unchanged geometry and domain minimum

For shared-shell candidate composition, retain the agreed 224px expanded rail at width ≥1200; 196px expanded rail at 860<width<1200; explicit 72px compact rail on desktop; and non-width-consuming navigation drawer at width ≤860. Retain 64px header above 860 and 56px at or below 860. Content gutters are 16px per side at width ≤600, 20px at 600<width<1200, and 24px at width ≥1200.

Shared evidence docks at 320px plus a 24px gap only when the measured remaining primary content is at least 640px or the domain's larger qualified minimum. Measure after actual navigation, gutters and reserved local chrome; apply the content inset once. Do not collapse the rail automatically to fit evidence. Otherwise use the proposed constrained modal variant: 440px at the represented 768/1024 widths and full viewport width with internal padding at width ≤600. This is provisional geometry, not a claim of deployed fractional-breakpoint parity.

The zero-extra-local-chrome arithmetic is unchanged: expanded 1255/1256 leaves 639/640px; actual compact 1095/1096 with 40px total gutter leaves 639/640px. The 1103/1104 calculation with a forced 48px inset is a separate fixture. Recompute at the 1200px rail/gutter step and at fractional widths; do not replace measurement with one viewport flag.

### Clause C — scope, owner and singleton

F01 MUST define shared-shell layer policy without assuming ownership of domain state, assistant requests or widget internals. F02 owns shared component and accessibility primitives. D06 retains the existing focused Terminal composition, native bridge variants, analytical reader and host integration. The existing Brain/D14 and Terminal host owners MUST jointly qualify any lifecycle binding. A shared-shell inspector MUST NOT replace Terminal's reader or impose its 320px geometry. Ordinary `/terminal`, native `shell=app`/`tray=1`/`dossier=1`, and the chart's own focus mode are distinct cases. Preserve the dossier exclusion and existing chart controls; do not add duplicate chrome or a second Brain.

### Clause D — lifecycle evidence

An invocation of `open()` or `close()`, a true opener result, `mounted`, or `mm-brain-ready` MUST NOT be represented as an acknowledged visible state. The existing `onClose` hook MUST be treated as conditional focus restoration, not an unconditional lifecycle event. Before automatic arbitration is enabled, the existing owners MUST identify a supported acknowledgment for the actual visible transition and its callback lifetime, failure and stale-owner behavior. This clause does not prescribe a new event, endpoint, visibility store or private-DOM polling mechanism. If the supported acknowledgment is unavailable, the transition remains unqualified.

### Clause E — evidence to Brain and back

Under an adopted shared-shell policy, invoking Ask from evidence MUST preserve the domain-owned evidence identity, selection and return anchor while suspending its presentation and releasing its width/focus trap. The host MUST distinguish the user's request to open Brain from the acknowledged receiver state. A failed or unavailable opening MUST leave the evidence reachable with a truthful outcome; it must not leave an unexplained hidden object or falsely report that Brain opened.

While Brain is open, moving to evidence or another blocking shell surface MUST use the qualified existing Brain close path and focus/lifecycle contract. Do not unmount the singleton, cancel an answer as a side effect, infer closure from a timeout, or queue an automatic destination opening. The user closes Brain through its visible control and invokes the desired surface through its existing trigger. Closing Brain does not automatically reopen evidence or shrink the chart. Explicit reopening MUST revalidate the retained identity and access/source generation against the domain owner and remeasure the layout.

This transition policy is for shared-shell evidence. Focused Terminal retains its incumbent reader behavior until D06 and the affected owners expressly adopt and qualify a Terminal-specific variant.

### Clause F — focus, modal and keyboard ownership

Only one blocking surface may own the active focus trap. A dock is nonmodal and leaves the main object available; a modal requires the adopted inert/scroll-lock/focus behavior across the actual host boundary. On close, restore a connected invoking control, or the domain's stable heading/fallback, only when the closing surface owned focus and the user's subsequent intent has not moved focus elsewhere. Do not steal focus from an intentional later action. Preserve identity and reconcile focus/inertness when changing between dock and modal; do not mount a second inspector.

Keyboard dismissal MUST preserve the active owner's internal priority. Brain's nested disclosure or stream Stop action must not also retire a chart tool, clear a selection, reset the chart or close an outer surface. Chart double-Escape applies only when the chart owns both events. Text entry, contenteditable and IME composition require explicit coverage. A visible Close remains available; its presence alone is not proof of keyboard or modal qualification.

### Clause G — request and save boundaries

Hiding, suspending, resizing or navigating a presentation MUST NOT imply cancellation, completion, persistence or deletion of an answer or domain object. Brain's existing request owner decides Stop/continuation semantics; the saved-object owner decides pending/dirty confirmation. Shell shortcuts MUST NOT discard an owner-controlled operation. No new request queue, lifecycle controller, return store or save authority is created by this contract.

### Clause H — context and historical evidence

An ambient company/symbol action MUST remain distinguishable from an exact source attachment. A historical bar action may claim an exact attachment only after the existing chart/Brain owners establish and expose the intended instrument, interval, bar/time basis and data/context generation. Visual reader selection, transient hover, locked AI selection and replay state MUST retain their separate owners. Changing symbol, timeframe, selection, principal or generation MUST not allow a stale attachment or response to masquerade as the current object. Missing point-in-time evidence remains unavailable; current calendar or quote data must not be substituted for it.

### Clause I — named return, history and identity

Named return MUST retain the existing accepted target, safe-origin gate and session-origin owner. Preserve the accepted path and its query/hash semantics through the existing transport without additional inner-query reserialization or a new return cache. Existing URL parsing may resolve relative URLs and perform normal URL lexical normalization; this contract does not promise byte identity for arbitrary invalid inputs. Keep Browser Back, the embedded parent-close path and the named-return action distinct.

`useFromMacro` gives fresh arrival signals precedence. An accepted `ret`/`return` wins within that resolution; a fresh `from=macro` flag without an accepted return can select a valid referrer or the existing origin fallback rather than the old cache. With no fresh signal, cached session origin can persist. Preserve that behavior unless the existing navigation owner expressly changes it. A named return label describes the accepted destination, not the selected instrument or proof of restored viewport state.

Named company entry MUST use its valid current route identity. Generic Terminal entry MUST not silently infer a company from an unrelated stale cursor. Invalid explicit identity MUST not fall back to a stale company. Preserve D07's route/resolver authority and all existing symbol, native, public and embedded grammars; this contract adds no generic timeframe/bar URL grammar, route admission or issuer mapping.

### Clause J — adoption and evidence

Each affected owner acknowledgment MUST bind the exact candidate source, specific clauses, affected variants and remaining conditions. Acknowledging an interface or a source fact is not independent design approval. Geometry concurrence MUST NOT be extended to new Brain, focus or return behavior without the affected owners' explicit response. No native hold, RIG finding, unresolved Paper effect or migration case is closed by this advisory.

## 7. Alternatives and final judgment

**Hold all consumer work until native acceptance:** this avoids provisional dependencies but needlessly blocks retention, arithmetic, source mapping and test preparation that can already be grounded in immutable evidence. Restrict the hold to release and affected behavior; keep those preparation lanes open.

**Treat exported `close()` plus `onClose` as sufficient and implement arbitration immediately:** this is tempting because the widget already has real methods. It fails on conditional callbacks, absent visibility acknowledgment, callback lifetime, served-asset uncertainty, active requests and demonstrated focus/Escape gaps. No added TypeScript declaration or arbitrary delay repairs those facts. Keep automatic arbitration held.

**Force every analytical side surface to the shared 320px inspector:** this would simplify a global layout table but erase an existing resizable Terminal reader and conflate domain evidence with assistant presentation. Preserve the focused Terminal exception and qualify its composition through D06. Wide-screen coexistence, if a domain later proposes it, needs its actual content minimum and owner review; it is not automatically licensed by spare pixels.

The smallest truthful forward step is a source amendment that preserves geometry, corrects lifecycle and ownership wording, records D06's exact-head response and limited return proof, and identifies the specific owner acknowledgments and tests above. Independent/native qualification and the original Paper effect remain held. This advisory is complete as a bounded input; root retains integration and all further action. No watcher, continuation runner, approval or canonical acceptance has been created.
