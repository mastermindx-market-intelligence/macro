## Proposed interaction and data scope

This makes the existing query/category contract explicit. It adds no endpoint, route admission, persistence layer or second directory store. F03/exporter/domain owners still qualify the proposed category mapping. F02 owns the eventual shared control primitive; F01 defines the behavior and retained scope. Numerical counts in this fixture are observations of the pinned/live input, never implementation constants.

The existing [ShellDirectory.tsx at Terminal3cc8da8](https://github.com/mastermindx-market-intelligence/mastermind-terminal/blob/3cc8da8432d8d2d4e4cb597f49c4eaa95f1980c9/components/chrome/shared-shell/ShellDirectory.tsx) owns `query`, `category` (initial `all`) and `limit` (initial48). Its query/category effect resets the limit to48. A future recovery action uses that existing category owner without changing query; any proposed-category presentation still needs the exporter mapping qualification. The current component does not implement this native proposed facet/control, and source presence is not served-build proof.

The category control must expose its selected value, expanded state and the explicit All categories option. Use the existing F02 qualified keyboard/menu primitive; do not create a competing focus owner. Every result retains its canonical route and distinct task. A nonzero query count outside the selected category must offer the same visible reset even when the selected category has zero matches. Loading/unavailable-data states must not display retained counts as current results. Errors and no-match states remain distinct under the main specification.
