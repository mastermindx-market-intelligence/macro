## Launch order and useful concurrency

1. Start P00 and the three foundation sessions. F01 and F02 work together and freeze shell/system v1 early. F03 prepares the directory and exact allocation; actual Paper edits wait for qualified access.
2. Any product session can immediately inspect its live/source/Paper inputs and write retention/data/build contracts. Final composed candidates depend on F01/F02. Start Macro, US/Prophet, Terminal, Company and Options as representative foundation consumers.
3. Run other market, research, personal, public and internal sessions concurrently as capacity permits. The plan assumes no specific account/session concurrency limit. Each assignment is independently bounded, with exact shared-contract owners.
4. QA01 reviews representative cross-product journeys early and final integration after all returns. The user returns to the commissioning session for that re-audit before implementation.

D08 owns the common Options contract and integration; D08A–D08D are independently dispatchable bounded content sessions with disjoint existing page targets. D08 does not launch them. They can inspect sources immediately and compose after the common contract freezes. A blocked P00/F03 return is useful progress but cannot be consumed as qualified writing or completed organization.

Refer to the exact artboard crosswalk before writing. No source-only, rejected, held or archive input is automatically eligible as the new production reference.
