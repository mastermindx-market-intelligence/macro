## Return protocol

1. Capture the origin before leaving. Reuse the existing shell’s navigation/history state. Private list names, membership and account identifiers stay in owner-local state and out of article URLs and referrers.
2. Maintain article → claim/source and planner → article as separate return levels. Closing a source uses the conditional-focus rule to return to its connected invoking claim or qualified fallback. Returning to planner restores its origin. Authentication callbacks cannot overwrite the planner origin. Browser Back follows actual entries, with no fixed “go back twice” implementation.
3. Reconcile the original subject and list before showing its private context. If the list vanished, show “The original list is unavailable. Choose a list.” After an account change, suspend the prior private origin. A different account receives its own list chooser. Restore the original private snapshot only for its qualified owner.
4. Restore the original read batch so a row beyond the first 50 remains reachable. Preserve shown data during reread using the existing freshness and failure rules. After layout settles, restore the same `data-event-id` and relative position for the explicit return action. Preserve any intentional later focus under the shared conditional-focus rule.
5. When the same qualified event has moved, restore to its current row and announce the old/new date. With null or unresolved period, use “Schedule date changed from …” and preserve `confirmation=unstated`. The fallback `next` identity cannot prove whether the next report rolled over or the prior event moved.
6. If the source now returns past/no-date, or the listing left the list, keep a clearly labeled origin notice and focus that notice near the agenda heading. Offer Open Company and any already-qualified original article. Preserve current coverage counts. The old row supplies return context only.
7. On revoked member access or unavailable revision, retain the planner origin and permitted public article. If the selected protected claim disappears, focus the gate/status notice and announce the reason. A successful same-subject continuation restores an eligible claim once.
8. Reload/direct-entry recovery is limited to what the existing owner actually retains. If origin state is absent, use the real article archive navigation. Same-tab persistence and new-tab behavior require the real browser proof before acceptance.

The incumbent dialog restores focus to its opener on unmount. It presently has no published origin snapshot for the deeper journey. The model’s reschedule memory is in-tab only, and past dates become a no-date state.
