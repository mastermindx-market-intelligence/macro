# Product and build contract template

Replace every placeholder with observed evidence or an explicit unresolved dependency. This is a specification template, not a pre-approved product.

## Identity and status

Session / product / primary owner / source commit / Paper file-page-artboards / shell version / system version / predecessor / RIG state / implementation state / last reviewed date.

## Product description

Who is using this? What question are they trying to answer? What should they understand or accomplish? What belongs elsewhere? Describe the normal-data complete journey and the useful missing-data alternative. List proposed new features separately from retained existing behavior.

| UI field or claim | Existing producer/API/schema | Entity and time basis | Type / unit / currency | Freshness / cache | Null/zero/stale/partial | Access / mutation owner |

Document calculations and model/forecast status. Source unknown means unresolved; it is not permission to invent an endpoint. Include correction/revision, pagination, conflicts, deduplication and readback where relevant.

## Composition and state matrix

Record viewport and available content width, shell/inspector state, component variants, theme/locale, keyboard/touch/reduced-motion, complete normal journey and exception coverage. Each state has actual copy and a meaningful next step. Explain any non-applicable state. Reference exact editable boards for all materially changed shell, hierarchy and interaction work. An unchanged actually approved reference can be reused; source-backed specimens and raster captures support the evidence and cannot substitute for the assigned Paper updates.

## Builder instructions

1. Existing entry points, template regions and reusable components.
2. Replacement boundaries and shared contracts owned by another session.
3. Backend and data work required before a UI feature can work.
4. Integration sequence, preserving old routes and return contracts.
5. Meaningful acceptance tests and source-truth checks.
6. Performance/accessibility budget and real measurement plan.
7. Migration, compatibility, rollout and rollback.
8. Open decisions with named owner and interim behavior.

## Review and return

Exact before/after evidence, independent product/taste findings, rationale revealed after first pass, changes made, actual RIG state, remaining blockers and the next owner. Do not use a screenshot filename or page title as proof of acceptance.
