## What the rationale establishes

The author is explicit that this is a partial shared-component candidate, that domain functions remain with their owners, and that the static sheets are authored compositions. `SYSTEM_CONTRACT.md` §1 and `CONTINUITY_AND_GATES.md` F02-G14 do not claim that these slices already replace or preserve the complete running workspaces. This supports the first pass's separation between **a weaker depicted comparison** and **unproved feature deletion**.

The rationale also reinforces several findings. The exemplar table calls the sector comparison, annual statement comparison and twelve-column Options tape the primary objects. The type contract specifies 13px analytical table body, 40px dense rows and quiet selected fill with text weight. The frozen sheets do not consistently realize those decisions. (`SYSTEM_CONTRACT.md` §§1–3.)

The recorded Paper/browser/font limitations explain the missing qualification evidence. They do not explain why the directly drawn comparison starts so late, why Options uses 11px data text, or why the selected row lacks the intended treatment. These remain repairable design decisions within the existing specimen scope.

### VTC-001 — UPHELD

The proposed primary object is explicitly the table in each analytical exemplar. The author also says the primary chart/table should remain immediately identifiable and the selected financial object should be placed first. These intentions do not change the frozen Options tape's late start around y=722 or the Macro/Company tables beginning around y=804/y=842. (`SYSTEM_CONTRACT.md` §§1–2.)

The general analytical sequence in §2 still places the metric strip and chart before local controls and the comparison table. That is an overly uniform rule when the declared primary task is reading a tape. The rationale does not demonstrate why those supporting objects need this much vertical precedence.

F01's ownership of the final shell is respected. It does not make F02's shared reference neutral about task hierarchy: these supplied sheets visibly teach a composition, and the proposed component minimums are intended to influence the joint decision. No pending shell handshake requires this amount of introduction above the rows.

**Closure condition remains:** Show a comparison-first analytical reference at the negotiated content width, with the table readable and useful earlier. Recover space from supporting material before shrinking raw values. A different ordering is appropriate when a chart actually is the primary task; this finding does not impose one universal table-first rule on all archetypes.

### VTC-002 — UPHELD

The mobile ordering is intentional. `SYSTEM_CONTRACT.md` §6 explicitly sequences title/date, primary value/caveat, supporting metrics, chart/values action and then comparison rows. That explains the design choice but does not justify its effect in a view whose declared primary object is the sector comparison.

The contract also distinguishes the 44px important-control target from row typography and permits a larger hit area around a smaller visual mark. It does not require an Evidence button to create a separate 80px row. (`SOURCE_AND_DATA_CONTRACT.md` §5.2.) The three displayed rows after more than 1,000px of setup remain an insufficient demonstration of dense mobile comparison.

`PAPER_BUILD_PLAN.md` F02-P11 asks for one clear vertical hierarchy rather than a scaled desktop. The frozen mobile order needs further task-specific work to meet that aim.

**Closure condition remains:** Show useful adjacent comparison rows earlier at 390px while retaining touch access, the explicit caveat and complete-row evidence. Change the phone ordering rule where necessary so the contract and reference agree. Do not achieve density by removing required fields or reducing touch reachability.

### VTC-003 — AMENDED; major remains

**Facts upheld:** The current screenshot depicts five financial series over 2010–2026 and five visible table periods. The proposed Company sheet depicts one revenue series over five years and three table periods. The latter gives less longitudinal information at once.

**Amendment:** The required repair should be read as a **bounded shared-component density and history stress example**, not a demand that F02 finish the whole D07 Company workspace. The rationale makes the implementation and composition ownership explicit, and the candidate is not authorized as a full domain redesign. The source contracts retain historical paging, annual/quarterly mode, definitions, citation precision and identity with their current owners. (`SYSTEM_CONTRACT.md` §1 and `SOURCE_AND_DATA_CONTRACT.md` §§2.1, 9–10.)

That scope distinction does not withdraw the finding. A promise that history remains reachable does not show that the common table/chart treatment can carry a useful longer comparison. The first pass already avoided claiming that the functions were deleted.

**Amended closure condition:** Add a realistic, bounded Company example that demonstrates the shared patterns under longer-period and multi-measure comparison, with adequate raw periods, units, long labels and unknown/non-comparable fields. Its relationship to the existing deeper view must be clear. The focused five-bar revenue chart may remain a complementary example. F02 does not need to reproduce every Company tab, route or dataset to resolve this visual finding.

T06 remains **WORSE for the depicted comparison**, with actual domain-capability preservation **UNKNOWN**.

### VTC-004 — UPHELD, with stronger contract evidence

The frozen Options data text is 11px with 10px headers; row text baselines are 31px apart. The author contract specifies 13px analytical table body, a 40px dense-row target and 11–12px only for quiet chart/secondary metadata. It explicitly says that secondary size is not for the primary answer. (`SYSTEM_CONTRACT.md` §3.)

The readability criticism therefore does not depend only on preference. The table is presented below a generous overview while its most important content uses a smaller role than the proposed system itself allows.

The contract's 40px row target should not become an instruction merely to make the long screenshot taller. The header/supporting region must become more economical at the same time. Density is useful information per working view, not the smallest text or the smallest row height alone.

**Closure condition remains:** Use the appropriate sustained-reading type and a restrained row-tracking treatment in a native-scale table, with enough useful rows available in the initial work area. Contract and artifact should agree on what dense mode means.

### VTC-005 — UPHELD

`SYSTEM_CONTRACT.md` §3 specifies quiet fill plus text weight for selection, distinct from the keyboard focus outline. `INTERACTION_STATES.md` treats row evidence as a stable row/field/source selection and requires the inspector to retain that identity across responsive changes.

The frozen Macro table indicates its inspected row only with bold sector text. The open inspector's title is good, but the selected context still requires deliberate matching. The rationale makes the intended distinction between selection and focus clearer; it supplies no new visual cue in the existing plate.

The observation that the top-level value and selected sector value coincide is still an ambiguity to resolve through clear scope, not a claim that the data binding is wrong.

**Closure condition remains:** Use a quiet whole-row selected treatment and clearly label which observation the headline/chart describes. Do not use focus styling as the persistent selection indicator. Correct binding and return behavior still require separate execution evidence.

### VTC-006 — AMENDED; minor remains

The revealed interaction contract already specifies appropriate user-facing wording:

- Saved: **“Saved. {object} is confirmed.”**
- Plan required: **“This source requires an eligible plan.”**

The confirmation/readback and restricted-payload requirements appear separately in the retained-content/recovery column. (`INTERACTION_STATES.md`, Copy and recovery matrix.)

This changes the diagnosis from a general flaw in the proposed copy contract to a **mismatch between the normative copy and the static state sheet**. The frozen sheet still uses “Readback confirmed,” “saved object generation” and client-payload wording. The technical obligations are valid; their presence as investor-facing message text is unnecessary.

**Amended closure condition:** Bring the state sheet into line with the existing plain-language copy contract, retaining precise owner confirmation and access rules in annotations or implementation documentation. No weakening or redesign of write authority is requested.
