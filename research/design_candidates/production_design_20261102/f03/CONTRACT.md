## 2. Product definition and complete user journeys

The directory serves a builder joining an existing product family, a designer tracing a prior decision, and a returning session reconciling changes. It brings the source contract, exact Paper identity, owner and evidence state together. It must not make a visually polished reference look approved merely because its name contains a revision or “Current Build.”

**Builder journey.** Start at the assignment directory, search a product/route/exact ID if useful, select its assignment, then follow the directly exposed Paper reference or source contract. That is one family choice plus one destination choice. Alternatively, Paper references finds an exact returned Read me board ID or full Paper URL directly, exposing that page and its pinned contract without another assignment choice. Candidate selection, RIG receipt and shell/system version remain explicit. Eight observed returns are supplied; other contracts and approved-candidate mappings remain unobserved. Requirements links are never mislabeled finished contracts.

**Lineage journey.** Search an exact page/artboard or choose a family. Its entry distinguishes candidate, historical, source-only, rejected, held, redirect and unexpanded roles. Known redirect destinations and original archives are exposed as recorded relationships. Unknown successor or rejection-receipt evidence remains explicit with a named owner. A designer can inspect the exact original source without browsing the giant canvas first. Existing redirects stay at their original locations. A recorded historical destination is not promoted to an approved current candidate.

**Returning-session journey.** Open Changes & gaps to see the two live target additions, dedicated allocation gaps and foundation/capability dependencies; use Route coverage to see the 348 canonical IDs separately from nine source deltas. Each route carries its repository, owner, delegated slices, template, access shell and payload tier. Full raw fields remain in the JSON projection and assignment entry. Unknown source, live writer and per-route candidate mappings are unresolved rather than synthesized.

The source artifact adds exact-ID search, assignment filters, a portable text fallback and explicit evidence states. These are F03 review-directory improvements, not proposed customer financial features. It does not implement customer navigation, data refresh, watchlist writes, alerts, trading, billing or a second task system.
