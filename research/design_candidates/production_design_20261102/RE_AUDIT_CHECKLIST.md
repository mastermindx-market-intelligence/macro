# Independent re-audit and implementation-entry checklist

The Chairman will return after the design sessions. This checklist defines what that re-audit must prove. It does not certify any current candidate as ready.

## Evidence required from each session

| Gate | Required evidence | Failure consequence |
| --- | --- | --- |
| Source and scope | Exact source pins, assigned route/query families, Paper IDs, baseline and overlap decision | Unqualified coverage remains open |
| Capability retention | Every existing feature dispositioned, accessible successor for relocations, valid removal decision | Product regression blocks acceptance |
| Primary task | Complete normal-data journey with useful first view and next step | Beautiful error states cannot substitute |
| Shell integration | Frozen shell/system versions and actual content-width compositions | Standalone old-header reference is incomplete |
| Interaction truth | Route/history/focus, controls, state transitions, no false save or success | A functional ambiguity blocks build readiness |
| Data and backend | Real producers/schema/clock/identity/units/access; proposed dependencies labeled | Missing truth cannot be solved by visual approval |
| Responsive and access | Actual mobile/tablet/narrow content, keyboard/touch/zoom, theme/locale evidence | Empty frame or inherited older variant does not pass |
| Builder feasibility | Exact code entry points, reusable boundaries, shared-template owners, migration/rollback and acceptance cases | Bare mockup is returned for specification |
| Reference review | Independent product and taste findings, frozen targets, resolved conditions and real RIG state | No self-approval or invented receipt |
| Organization | Current candidate discoverable, old links/archives/comments preserved, route crosswalk updated | F03 reconciliation required |

## Cross-product journeys

1. **Macro to action research:** regime/event → sector/theme → exact company → chart/options → evidence → saved investigation/watch → return. Preserve region, listing, clock and source context.
2. **Discovery to monitoring:** filter universe → compare → inspect → save view or condition → activate only when explicitly requested → revisit changed data. Check duplicates, uncertain save and session expiry.
3. **News to research:** headline/brief → disagreements/primary source → Company/Hub → saved reading → return to reading position and review state.
4. **Global to local:** US/China/HK/Canada/International → local market/country/issuer → unsupported-feature state where applicable. No US-parity fiction or cached-data relabeling.
5. **Public to product:** search/public article/shared chart → entitlement/login → correct beta deep link → back/public path. Check anonymous access, SEO/canonical assumptions and route aliases.
6. **Phone and keyboard:** repeat a high-value journey at 320/390 and at zoom, with long Chinese labels, visible focus, contained table/chart overflow and access to every local view.
7. **Internal boundary:** internal OS/admin routes remain correctly scoped; mixed historical registry metadata receives an explicit audience decision, not silent promotion or exclusion.

## Independent review procedure

Use separate product-regression and visual/taste judgments. First pass receives ONLY the user/business job, production-before artifact, proposed-after artifact and capability/task manifest. Designer rationale, implementation constraints and data limitations are withheld until first-pass findings freeze; then reveal them and record second-pass amendments. Access limitations are evidence gaps, not advance justifications. Reviewers inspect the actual frozen artifacts rather than accept the designer's scorecard. Rework changes invalidate affected findings/receipts; unaffected accepted areas can retain their evidence.

Freeze mutable Paper work operationally: record exact file/page/artboard IDs and observation time; commit supported candidate exports/captures, annotations/specifications and verification screenshots as one immutable source artifact set; bind RIG manifest/receipts to its required SHA/digests. A Paper snapshot guard or token hash is not a document revision. Subsequent canvas changes require affected evidence to be regenerated and re-reviewed. Preserve RIG predecessor continuity with explicit disposition of every inherited blocker/authority condition.

Apply the existing RIG mechanism and its real statuses. Full review is required for material hierarchy changes, flagship redesigns and canonical-reference replacement. The lightweight path remains available for genuinely local cleanup. Do not invent extra gates merely to keep work waiting, and do not waive existing required evidence to accelerate a release.

Record the result per family as **ready for reference approval**, **revise**, or **blocked by named dependency**, alongside the formal RIG state. Do not average a serious missing capability or data-truth failure into a high overall score. A family can be approved while another remains blocked; shared-foundation defects affect every dependent family.

## Handoff to implementation after approval

An approved reference needs an implementation packet citing the actual RIG receipt, exact Paper revision, full builder contract, route/source/data map, retained capabilities, meaningful test cases, performance targets and rollout/rollback. Then implement and validate real interactions, accessibility, data integrity, access and production performance. Design acceptance, merged code, deployed release and served production proof are four separate facts.
