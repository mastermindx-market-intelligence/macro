## Implemented contract

The new module lives under **engine/entry_radar/replay/**. It imports the existing all-false
authority vocabulary and owns no persistence. The CLI writes only an explicitly requested
research artifact, or stdout. It cannot write to a runtime data/ or ledger path.

The input boundary requires a declared pre-outcome candidate list; stock, SPY, QQQ and sector
bindings; stable identity/basis receipts; a frozen owner calendar; per-minute revision IDs,
receipt hashes, true UTC start/end and observed known_at; prior-session daily context; and
the actual incumbent's owner/input/code receipt. These are consistency checks on supplied
receipts, not cryptographic verification of an upstream owner's claim.

Canonical bar law:

1. Anchor 15m/30m windows to the supplied regular-session open.
2. Select only completed intervals ending no later than the decision cutoff.
3. Require every exact one-minute start in the interval; do not forward-fill.
4. Require each constituent minute to be complete and actually known by the cutoff.
5. Select the latest visible revision; conflicting same-clock revisions refuse the interval.
6. Aggregate open/maximum high/minimum low/last close/sum volume.
7. Set aggregate known_at to the maximum constituent receipt time.
8. Keep unavailable OHLCV and eligibility null. Do not convert a refusal to a measured nonfire.

Each frame includes a snapshot digest over visible inputs. A separate full-bundle digest
identifies the entire reproducible run and may change when future data changes. The earlier
frame must not change merely because a later bar, later daily close or later correction is added.

The supplied calendar controls RTH and early closes; this module adds no second calendar.
A diagnostic 120-minute coverage endpoint is capped at the session close and marked censored.
**No launch/MAE label or early-versus-wait economic policy is computed.** A later registered
policy comparison must bind the same episode-origin endpoint for all policy decisions.

No registered detector ID/spec exists yet. Existing detector/event/lifecycle vocabularies are
closed and differ from the proposed research-state labels; mapping is a later owner contract
decision. No C4/F1 workaround was introduced.
