Status: source-only synthetic conformance; **not an enrolled stock experiment, market-label run, forecast or executable order policy**. Parent RS Pullback / WS:LIVE-ENTRY-RADAR, originally #8649 (merged). The daily W5 preregistration and `outcomes.py` remain unchanged. This separately versioned module lives under the same existing replay owner and creates no event store, publisher, indicator catalogue, trial database, registry or financial authority.

## Interface and existing owners
`engine.entry_radar.replay.rs_pullback_launch_labels.build_label_panel(bundle, scales, evaluation_at)` reuses the ordinary `build_input_panel` to bind each original issue and the existing `_aggregate` function to select future minute revisions. Calendar interpretation and identity/basis/receipt refusals are not rewritten. Only `SYNTHETIC_CONFORMANCE` input is currently supported. `OBSERVED_MARKET` raises an explicit not-enrolled error; passing a synthetic-looking receipt cannot authorize a market trial.

`scales` is keyed by candidate ID. Each fixture identifies a positive true-range Wilder ATR14 30-minute unit, price basis, source ref/digest, origin, completed asof and known time. Completed asof must be strictly before origin; origin must be in the original session and no later than issue; known time must lie between asof and origin. This checks consistency of supplied fixture provenance—it neither calculates ATR nor authenticates an observation. A missing scale retains an unscored candidate rather than borrowing another candidate's unit.

The native Phase1 clock uses Python datetime microseconds. This new interface refuses nonzero sub-microsecond input clock digits instead of truncating them into earlier availability. This is an explicit input-format limit, not nanosecond support. Unsupported precision anywhere in the synthetic bundle, including future clock fields, rejects that bundle; supported future payload revisions are otherwise invisible before their known times.

## Target semantics
The price reference is the reported open of the first one-minute interval whose start is **strictly later** than issue. Issue14:00:00 and14:00:59 both use14:01; issue14:01:00 uses14:02. This is a defined trade-price convention, not an executable quote or fill claim. The120-minute horizon begins at that reference interval; it is not the earlier Phase1 diagnostic endpoint of issue+120.

The source calendar is frozen at issue. A reference leaving less than120 minutes before that known close is `SESSION_REMAINDER_ONLY`; its primary `launch` and `low_in` remain null. A reference after the close is not rolled forward to another day. All declared candidates, including unavailable and noneligible ones, remain in output. The kernel does not calculate a success rate or silently select a statistical population.

For a fixed origin scaleA0, upper=E+1A0 and lower=E−.5A0. A first reported open beyond one barrier precedes that minute's later reported prices. When open is inside and both high/low cross the barriers, path order is `ORDER_AMBIGUOUS`, not guessed adverse-first or favorable-first. A lone barrier hit is upper-first or lower-first. Results retain the observed minute interval and maximum known time of the required prefix; no exact intraminute timestamp is invented. A complete path with neither hit is non-launch, not censoring. Earlier missing/invalid minutes block first-event classification; later missing minutes do not erase an already observed terminal first event.

Full-horizon low-in is separate: minprice>=E−.25A0. A later breach after an upper-first event still falsifies low-in. A witnessed breach can falsify it on incomplete data, but incomplete benign data cannot prove it. Exact MFE/MAE are returned only for a complete requested path. For session-remainder-only rows those extrema describe only the explicitly shorter path, not the primary horizon. No stop-return, PnL, calibrated probability, live score, sizing or promotion is computed.

Through the public native owner that condition is unreachable: any frame refusal makes the frame unavailable, and attachment is never called. A native test verifies that original refusal bytes survive. The reviewer also alternately claimed an execution-confirmed concern and no execution; only its static contribution is accepted.

Its clock-format observation prompted additional direct tests. Five timestamp spellings actually accepted by the unchanged native owner (space separator, lowercase t, compact date/time, comma fraction, fractional UTC offset) escaped the first literal-T guard. A direct reproduction retained all five wrong accepts before repair. It now defers string acceptance to the existing owner and checks all decimal-dot/comma components, including UTC offsets, for significant digits beyond supported microseconds. Valid alternative spellings at representable precision stay supported, and invalid numeric price strings stay with the normal OHLCV refusal rather than becoming timestamp errors.
