## 1. Outcome and material decisions

The intended user can start at the Healthcare theme, understand a material development, distinguish clinical or operational progress from retained business economics, inspect the strongest counterevidence, identify the next discriminating observation, and return to existing market/company research. The machine preserves source scope, units, clocks, corrections, rights and unresolved identities. It does not create holdings, price targets, entry signals or trade authority.

R8 resolves an implementation ambiguity: **an existing private object store is available as source infrastructure, but an existing GMI private-assertion product binding has not been established.** The distinction is actionable. Reuse Research Vault transport primitives and extend the existing native GMI evidence admission/publication boundary through one shared owner change; do not repurpose a neighboring owner's object or create a second Healthcare evidence service. That is the recommended design amendment, subject to shared-owner review, not a newly authorized binding.

Two domain branches are now specified for that review: `REPORTED_ECONOMIC_RIGHT` and `REPORTED_SUPPLY_STATUS`. These are proposed enum additions to the same Robotics `theme_graph.curation_assertion.v1`, not installed contracts. The semantic requirements below are firm research requirements; exact native wire enrollment still belongs to the shared owner.

R8 also reproduces a rights-reader cache behavior that matters for a future persistent API: same-path policy changes are not observed by an already-warm reader until its cache changes. Therefore an assertion's original review cannot be the only authorization fact the serving path checks. Policy revision and refresh behavior must be proved as part of the shared route.

The first slice remains existing `glp1_obesity` / `obesity_glp1`, not because it is an investment recommendation but because R2/R3/R7 provide a difficult, useful economic test. Full twelve-family Healthcare ambition remains visible. Product depth is not measured by the number of entities we can list.

## 3. Binding contract the shared owner must prove

A future binding must identify the existing GMI evidence owner, admitted private Research Vault instance, writer identity and permitted lane, native schema, immutable revision key, source-retention pointer, read accessor, effective rights policy, current-generation publication mechanism and all public export exclusions. These are required receipt fields, not a new runtime schema minted by this document.

There is **one authoritative native statement revision**. A private retained source, a native assertion and a derived view are different objects, not competing copies of the same current truth. A public-safe shell or explicitly approved redacted projection is non-authoritative and must not contain the protected body. Avoid making one assertion simultaneously authoritative in repository parquet and private storage. Migration or tiering of the current native evidence owner needs an explicit precedence rule, round-trip evidence and old-reader compatibility.

The existing `EVIDENCE_COLUMNS`/schema extension must remain real. Do not redefine `curation_assertion` as an opaque string pointing to a second ungoverned ledger. Whichever storage binding is accepted must round-trip the native payload through the same reader contract. If the physical location changes for an opted-in subtype, the K1 physical-reader/pointer binding must tell that truth; an old repository-parquet pointer is not a private-source receipt.

### Proposed admission/publication order

1. Acquire only permitted source bytes through the incumbent source owner and retain the exact body/locator and clocks under the existing private retention arrangement. A web result or this research ZIP is not that receipt.
2. Construct a candidate source-scoped assertion; validate its shared schema and domain branch; keep source quotation, original paraphrase and analyst inference distinguishable.
3. Resolve required identity through the incumbent owner. A source-only counterparty can remain unbound if the dependent stock feature is omitted. A required security-subject composition cannot.
4. Record the actual review/admission decision and current rights-policy revision. A model draft does not self-admit. The `mastermind_curated` legacy basket family is not a blanket permission for external source bodies.
5. Produce canonical assertion bytes and an immutable native revision. Different assertions from one source require different selectors; changed bytes at the same URL/date require a different revision; duplicate publication of identical reviewed content reconciles to the same identity.
6. Stage outside public repository/site paths. Verify every required immutable object, length and digest through the strict bounded read interface. A failed read, missing object, permissions error or oversized body is not an empty successful generation.
7. Publish through the incumbent GMI generation mechanism using exact-predecessor semantics supplied by the existing storage owner. Reuse that mechanism once; do not create a parallel per-theme publication plane. A predecessor conflict requires reconciliation, not unconditional overwrite.
8. A write timeout after dispatch is effect-unknown until the exact native key and predecessor are reconciled. A later successful read can establish what happened; inventing another generation or operation identity cannot.
9. Serving authenticates first, then binds one native generation and one effective policy revision for the request. Body validation and policy eligibility precede exposure. Derived responses carry exact source/assertion/method/policy identities and do not independently own current truth.

No production operation above was executed in R8. The order is the acceptance contract for the proposed binding.

## 4. Policy freshness is part of correctness

The inspected `engine/theme_graph/rights.py` decorates `_load(path)` with `lru_cache(maxsize=8)`. `load_registry` keys the result by path. The module documentation says enforcement uses the current registry, but a fresh function call does not necessarily read fresh file bytes. [S08]

An offline probe imported the **complete unmodified module only after its Git blob matched** `63ba2b60e9be6615208fab5b53b1fbcb44f4f433`. Synthetic policy files established:

- First allowed read → overwrite the same path with `internal_only` → the warm module still allows emission.
- First missing-file read → create an allowed policy at that path → the warm module still refuses.
- Explicit cache invalidation observes both changes. Unknown families and unknown classes refuse. A separately read immutable policy path observes its own refusal.

These are two manifestations of the path-cache design and six control observations, not eight defects. A deliberately changed source copy was refused before import. No live traffic, cloud credentials, production registry or deployment was touched. The test does not show that a real production process missed a revocation; deployment might restart or otherwise invalidate the reader. That behavior was not measured.

**Required resolution:** the shared owner must bind rights enforcement to an effective policy revision and prove its invalidation/reload behavior. Options include immutable revision-specific inputs or an existing release/reload boundary; choose one within the existing owner. Do not create a second policy watcher. A cache TTL without a defined revocation/availability contract does not establish immediate revocation. Evidence should state the actual bound, not promise instantaneous worldwide invalidation.

Test a warm process and a policy transition, not only a fresh module. Test grant arrival as well as revocation so the design does not create a permanent false-denial state. The same request must not use one policy for a source receipt and another for the dependent narrative without exposing that mismatch. Previously displayed data cannot be made unread by a server; future responses and retained UI state still need the agreed revocation/logout behavior.

## 5. Three separate permissions

**Upstream rights:** whether the exact fields and intended use may be acquired, retained, transformed, displayed or redistributed.

**Product audience:** whether an entitled user may access a particular Mastermind output. A free source can be part of an entitled product; an entitled user does not cure missing upstream rights.

**Execution permission:** whether this writer/request has the organizational, lane, custody and technical permission to perform the operation. A storage credential is not a curation decision.

The official openFDA licensing page generally supplies a public-domain/CC0 posture but explicitly carves out GMDN content for certain commercial ontology/mapping and AI-training uses; its terms also reserve exceptions for some private third-party works and impose service constraints. The drug-shortage documentation is the relevant selected dataset route. [S13–S15] That supports a bounded field-purpose review, not a platform-wide ban and not an unrestricted all-FDA-content label. No GMDN content is required for this first drug-shortage workflow.

Source policies may change. Record the policy text/version reviewed, what data fields and uses it covers, retention restrictions and the next review trigger. A current use-policy observation is not a legal conclusion about every record on another website. The existing registry remains the authority for internal admission; no second Healthcare rights catalog is created by the research examples.

## 6. Proposed shared branch: REPORTED_ECONOMIC_RIGHT

Keep the shared envelope: source and immutable locator; review and curation revision; source-scoped subject/object; statement mode; scope; observation; temporal applicability; limitations; correction; all-false authority. Add a closed predicate-specific body to the same union. Do not add arbitrary model-authored predicates.

| Proposed semantic field | Meaning / validation requirement |
|---|---|
| `parties` | Source-native party labels and distinct roles: grantor, grantee, payer, payee, developer, commercializer or cost bearer. Optional canonical binding must carry actual resolution evidence. A label is not a security ID. |
| `asset_scope` | Source-native asset/formulation/indication labels and version limits. Avoid a new product registry; unknown formulation remains unknown. |
| `grant_scope` | The actual granted activity and territory. Development/commercialization rights do not imply manufacturing, exclusivity or every indication. |
| `economic_basis` | Royalty on a stated sales base, profit/loss share, milestone, fixed fee, cost reimbursement, or another reviewed closed basis. The value and denominator travel together. |
| `rate_terms` | Exact numeric/range terms only when disclosed; otherwise a qualitative source description with numeric value null and a reason. Do not infer midpoint royalty tiers. |
| `trigger_terms` | Sales thresholds, achievement conditions, repayment completion, effective dates or other disclosed conditions. Unknown trigger is not an unconditional rate. |
| `cost_obligations` | Costs or losses borne and their scope, separately from receipts. A royalty payer's cost-of-sales treatment is not proof of the payee's earnings margin. |
| `recognition_scope` | Which entity reports the amount, fiscal period, currency, gross/net basis and whether the source gives cash, accrual or contractual entitlement. |
| `applicability` | Contract validity interval when known, source-observation date and amendment/correction state. A reporting-period end is not an invented original contract date. |
| `limitations` | Undisclosed tiers, unverified retained contribution, counterparty identity, territorial supplements and other conclusion-specific gaps. |

For the R7 Lilly/Chugai example, preserve worldwide commercialization/development participation and the stated net-sales royalty basis; exact tiers, security look-through and company materiality stay unknown. Do not manufacture an earnings estimate or a Chugai stock link. This reuses the already-researched source example; R8 did not acquire its complete contract or a new upstream retention receipt.

A contract may allocate upside and downside differently. Never encode `40%` without defining 40% of what, who pays or receives it, which costs are shared and which territory/period applies. Never add the product's commercial sales to the licensor's royalty as though the sum were independent end-market demand. Licensor revenue can be a genuine separate company revenue stream while still referring to the same underlying treatment sale.

### Intended comparison keys

Compare like-for-like asset/formulation, indication where material, territory, counterparty/role, contractual base, period and source revision. A change from sales royalties to a profit share is a change of mechanism, not a numeric rate increase. A new disclosure can change what Mastermind knows without changing the contract itself. Represent those separately.

## 7. Proposed shared branch: REPORTED_SUPPLY_STATUS

This branch records evidence about availability; it is neither a clinical-approval object nor a bottleneck score. Preserve at least the source/native record key, jurisdiction, drug/form/strength/presentation scope, national regulatory status, manufacturer-reported availability, record-update time, source-generation value, acquisition interval, completeness/absence basis, and status interpretation limits.

Use separate dimensions in the proposed read model, not a new workflow state machine:

- acquisition: qualified complete observation / partial / failed / unknown;
- source observation: current / resolved / discontinuation / mixed / unrecognized / no matching record observed;
- freshness: eligible / stale / unknown under the accepted owning freshness policy;
- coverage: which queried molecules/presentations were observed, missing, excluded or unrecognized;
- economic inference: unavailable or an explicit separately evidenced, attributed hypothesis.

The display labels above are research semantics, not installed enums. Final code contracts must be closed and reviewed. The regulator's raw status survives even when the UI presents a clearer label. [S16]

### Meaning that must survive aggregation

A `Current` national status is not overridden by `Available` manufacturer-presentation information. Mixed current/resolved molecules stay mixed. A discontinued product is not silently normalized into the resolved machine band. A row with an unrecognized status is observed-but-unclassified, not no records. A missing molecule is not resolved. A resolved shortage does not quantify spare capacity, price, margin, or a profitable supplier opportunity.

The national FDA observation and a pharmacy's local supply experience may answer different questions. The first slice is not a patient treatment-availability service and must not recommend medical substitutions. [S16]

### What acquisition completeness can and cannot prove

Require successful pagination with declared query, stable processing rules, count and duplicate checks, source metadata, start/end observation time and an explicit cap-exhaustion/error result. A later-page failure cannot advance an authoritative current generation. Keep the last qualified generation available with its own age and failed-refresh context, not relabeled as newly collected.

However, matching record counts and source `last_updated` do **not** mathematically prove a transactionally atomic upstream snapshot when the source provides no snapshot token. The owner must label that limitation and retain the acquisition interval. Do not claim an exact instantaneous national census merely because every requested page returned.

On a later qualified complete observation, a no-longer-listed key can remain in historical evidence but must not remain a current observation without an explicit basis. The FDA FAQ describes finite display retention for resolved and discontinued listings; source absence therefore needs semantics, not deletion of history or invented resolution. [S16] The API's broad coverage description is not itself a guarantee that every historic state is recoverable. [S15]

Legacy overwritten cache rows cannot be repaired into point-in-time history by adding a fresh timestamp today. Start truthful forward retention through the incumbent owner and label historical limitations. Do not create a second FDA archive or reassign source custody from this plan.

## 8. K1, identity, and correction integration

At this pin the legacy GMI evidence binding uses `theme_evidence_id`, `engine.theme_graph.store.read_evidence`, a repository-parquet pointer, and `published_at`, `effective_at`, `computed_at` clocks. [S10] It cannot be advertised as the complete new private assertion simply because the old receipt validates.

The shared curation subtype must explicitly bind its actual native reader/pointer and each new upstream, observed, retained, reviewed, curation-publication and business-valid clock. Preserve date/datetime grain and unknown timezone. Unknown upstream publication is not curation publication. Do not repurpose old clock meanings to fit a new field. Where a breaking binding change is required, use the existing contract's versioning law rather than weakening validation.

Keep K1 pointer-only. The full assertion body stays with its native owner. A thematic section may present valid native-subject blocks side by side; that does not make them one successfully resolved security-subject recipe. Optional stock links can degrade independently. Required stock enrichment still needs the accepted owner-produced bridge and a compiler path that actually consumes it. A CIK or syntactically plausible `co:` identifier is insufficient.

Corrections append an exact successor and preserve predecessor reference, reason and known clocks. Distinguish: changed source bytes; corrected source interpretation; amended contractual reality; an analyst changing the economic hypothesis; and a pure metadata correction. These may have different business-valid consequences. Retracting a source removes the dependent current conclusion; it does not silently erase the historically recorded observation. Rights restrictions govern whether an old body remains displayable; correction history is not a rights bypass.

Same-URL/date changes, two independent statements in one source, and copied issuer releases require discriminating cases. A filing and release sharing an upstream are not automatically two independent confirmations. R1–R7 research identifiers remain document-local and cannot enter native storage as fabricated accepted IDs.
