# W1 official Treasury lifecycle feasibility and executable casebook

**As of:** 2026-10-08. **Scope:** bounded read-only U.S. official-source research under the parent Sovereign Auction program; no repository, collector, production, account, or organizational-owner changes. **Disposition:** contemporary lifecycle intake is feasible; a latest-record historical backfill is not a point-in-time announcement archive. No forecasting or trading conclusion is established.

## Decisive findings for the first implementation

1. **Do not use FiscalData `record_date` as publication or knowledge time.** Its current dictionary says “The date that data was published,” yet all 14 sampled auctions dated October 1–13 have `record_date == issue_date`. On October 8 the three October 13 auctions already have `record_date=2026-10-15`. The earliest three rows sampled similarly use issue dates. Preserve the raw field and flag the semantic conflict. This is direct original-API counterevidence, not a speculation about release lag. [Dictionary](https://fiscaldata.treasury.gov/datasets/treasury-securities-auctions-data/); exact query, raw bytes and digest in `SOURCE_RECEIPTS.json`, source `fiscaldata_october_dates`.
2. **Endpoint names do not establish lifecycle stage or vintage.** The observed `/announced` default response has 250 rows, of which 247 contain result filenames. `/auctioned` returns 250 rows, all with future maturities; this snapshot excludes the sampled matured CMB. `/upcoming` contains only three already announced future Bills. None is a complete 30-day tentative schedule or a historical first-release archive. These are observed snapshot characteristics, not a claim that undocumented server limits will always stay 250.
3. **Actual deadlines change within the same instrument class and can be amended.** October 13, 2026: 13/26-week Bills close 11:30 ET, the 6-week Bill closes 13:00 ET. December 24, 2025: 4/8-week Bills close 10:00 ET; 17-week Bill and 7-year note close 11:30 ET. A 5-year TIPS auction's deadline changed from 13:00 to 11:30 between its April 10 and April 15, 2025 notices. A class-based default is insufficient. [October special notice](https://www.treasurydirect.gov/instit/annceresult/press/preanre/2026/SPL_20261008_1.pdf); [December notice](https://www.treasurydirect.gov/instit/annceresult/press/preanre/2025/SPL_20251218_2.pdf).
4. **CUSIP can change between announcement and result.** The February 25, 2025 5-year note was announced as 91282CMQ1 and issued as an unscheduled reopening of 91282CGQ8. The API preserves both `announcedCusip` and `originalCusip`. An auction episode therefore needs announced/issued identity aliases, while distinct reopening auctions sharing a security remain distinct episodes. [Official FAQ and examples](https://www.treasurydirect.gov/help-center/faqs/reopenings-faqs/).
5. **The official XML and API units differ.** The October 1 Bill is `OfferingAmount=100.000` in current announcement XML and `$100,000,000,000` in its PDF and JSON. Other XML cash amounts are already dollars. Unit mappings must be field- and schema-specific; never multiply every XML monetary value by a billion. [Announcement XML](https://www.treasurydirect.gov/xml/A_20260929_3.xml); [PDF](https://www.treasurydirect.gov/instit/annceresult/press/preanre/2026/A_20260929_3.pdf).
6. **Prepare for an imminent schema migration without pretending it already happened.** Treasury's amended October 5 specification describes field renames, separate competitive/noncompetitive close dates, explicit CMB flags, inside/outside-offering allocation fields and unscheduled-reopening aliases. It removes the legacy result XML `ReleaseTime`; the implementation date remains unfinalized in this notice. A separate October 6 notice tentatively dates page reorganization to October 19 and says API/XML/PDF URLs remain unchanged. Preserve observed schema and use explicit adapters; do not infer field migration dates from page migration dates. [API specification](https://www.treasurydirect.gov/files/auction/auction-file-%26-api-specification-changes.pdf), pp. 1–9; [URL notice](https://www.treasurydirect.gov/files/auction/treasurydirect-url-changes.pdf), p. 1.

## Instrument and event-time casebook

Competitive deadlines below are explicitly ET in the official notices; the accompanying expected JSON converts them with America/New_York. Result clocks come from original result XML at **minute** precision. The ET interpretation of those raw result clocks is consistent with notice deadlines and retrieved HTTP metadata, but the inspected XML/XSD does not encode its timezone. Preserve that qualification: the fixtures contain raw result clock strings, not an asserted UTC result-release timestamp. Issue dates are official issue/settlement dates; a passed date is not a receipt that an individual purchaser completed delivery.

## Proposed W1 contract for the existing event/data owner

This is an implementation recommendation, not a second store, calendar, lifecycle controller, or approved release.

**Separate three identities.** Preserve a tentative schedule-slot identifier and its source edition before CUSIP exists; bind it to a stable auction episode only on a sufficiently exact official match. Preserve `announced_cusip`, `issued_cusip`, original issue date, event-specific issue date and reopening status. Preserve an immutable source-observation/revision identifier based on content digest. A new amendment revises an episode; a new reopening auction creates another episode even when CUSIP matches. A changed auction date or unscheduled CUSIP is an alias event supported by a notice, not an instruction to drop history. Ambiguous joins should surface a conflict.

**Classify using official fields with conflict checks.** Current JSON separates `securityType` (Bill/Note/Bond) from `type` (Bill/CMB/Note/Bond/TIPS/FRN); it also supplies `cashManagementBillCMB`, `tips`, and `floatingRate`. Preserve raw values; accept documented Yes/No or Y/N representations by source adapter. Conflicting explicit class/flags produce an unknown/conflict state. Missing flags are unknown; neither empty strings nor FiscalData's literal `"null"` become numeric zero or Boolean false. Current nominal term and original term serve different comparison cohorts.

**Represent source phase and physical phase independently.** Tentative schedule, early CUSIP release, offering announcement, amendment, competitive result, postponement/cancellation and issue-date passage are distinct evidence. A future official announcement is not a result merely because the raw API provides a schema containing result fields. A deadline that has passed without results means waiting/unknown results. An API endpoint failure never means zero auctions. Future results must remain null. Passing issue date can be projected as `ISSUE_DATE_PASSED`; a cash-settlement assertion needs its own evidence.

**Preserve publication precision and local availability.** Keep date-only `announcement_date`, notice release/embargo clock where printed, competitive/noncompetitive cutoff, result release interval, scheduled issue date, source-update raw timestamp, HTTP metadata, ingestion start/completion, local first-seen and digest separately. For legacy result `ReleaseTime=11:32`, preserve a minute interval and timezone-evidence basis; after its timezone interpretation is qualified, use the conservative upper boundary for an as-of eligibility decision. Do not fabricate seconds. The document's release stamp supports a historical public-information reconstruction with an explicit evidence grade, not proof the system observed it at the time. Revisions inherit their own release evidence; unknown amendment time cannot be replaced by original announcement time. The later schema's removed release clock must yield missing publication time unless another verified official field/document supplies it.

**Use original vintages for past information sets.** Keep the originally published announcement and each later amendment with `supersedes`/field-level changes in the already authorized artifact owner. Never take final coupon, current deadline, result bidder shares, current `updatedTimestamp`, or issue-date `record_date` from a retrospectively fetched row and backdate them to its announcement date. A current future event can be safely shown as known by the current receipt; retrospective reconstruction must disclose its evidence basis and gaps.

**Use explicit measurement semantics.** JSON monetary strings here are USD; the sampled legacy XML OfferingAmount is billions of USD. Preserve discount rate for Bills/CMBs, real yield for TIPS, high discount margin/spread for FRNs, nominal yield for ordinary coupons. Current bidder-share denominator is competitive accepted; `primaryDealer + direct + indirect == competitiveAccepted` holds in the captured examples. The future allocation schema needs its own inside/outside-offering reconciliation. Indirect bidders are not a foreign-ownership proxy; Treasury publishes foreign participation separately in Investor Class Auction Allotments. [Auction FAQ](https://www.treasurydirect.gov/help-center/faqs/auction-faqs/), direct/indirect bidding sections.

**Expose honest schedule coverage.** On capture, the tentative source has 34 auction rows for October 8–November 7 inclusive; three completed on October 8 and 31 are future by event date. The early-CUSIP source has six rows and the current future-announced source three. These are different universes. A 30-day display must show tentative events without invented sizes/times, merge official announced terms as available, remove already-past events from upcoming display, and retain correction history. CMBs can be announced outside the regular long-range calendar, so “all publicly announced eligible events observed” is supportable; knowing every future CMB before announcement is not.

## Negative fixtures and acceptance checks

1. **Amendment leakage:** decision Apr11 2025 must not use the Apr15 TIPS deadline. Current API announcementDate stays Apr10; this is the adversarial input.
2. **Publication substitution:** future issue-date FiscalData `record_date`, API `updatedTimestamp`, and HTTP Last-Modified must not become official release timestamps.
3. **Result leakage:** post-auction result-bearing `/announced` row passed to an earlier decision snapshot cannot expose result variables.
4. **Identity alias:** Feb25 announced CMQ1 and issued CGQ8 reconcile to one episode; distinct VP9 auction dates remain multiple episodes.
5. **Deadline defaults:** 6-week Bill Oct13 closes 13:00; FRN Sep23 closes 11:30; holiday Bills Dec24 close 10:00. No universal cutoff survives.
6. **Mixed XML row shape:** quarterly holiday nodes share auction wrapper but contain no AuctionDate. Never crash or publish a holiday as an auction.
7. **Schema/units:** legacy XML `100.000` versus JSON `100000000000` normalizes equally; normalizing `CompetitiveAccepted` with the same billion multiplier must fail validation.
8. **Old missingness:** historical TIPS has empty deadline, XML path and competitive-accepted fields. No defaults, zero demand or foreign-share inference.
9. **Phase regression:** weekly early-CUSIP source retains past auctions; receipt order alone must not downgrade an observed result to tentative.
10. **Coverage/outage:** empty source response, retrieval failure, unsupported schema and a known no-event interval are separate states; last good data cannot silently be relabeled current.
11. **Correction safety:** source bytes changing at an existing URL create a new digest/revision; do not mutate prior PIT records. A changed file timestamp without changed bytes does not imply a changed financial fact.
12. **No premature economics:** large gross offered amount is not net private cash, reserve drain, a forecast probability, or trading eligibility; result-present does not supply a licensed pre-close WI quote.

## Historical feasibility verdict and remaining limits

**Feasible now:** source-linked contemporaneous all-class intake, official clocks where documented, tentative/announced/result distinctions, reopening aliases, original-notice reconstruction for selected historical episodes, and deterministic context with explicit missingness.

**Partially feasible historically:** Treasury's query page describes TIPS from 1997 and other types from July 1998 with expanded fields in April 2008. Direct sampling finds additional older sparse rows: FiscalData earliest issue dates in 1979 and TreasuryDirect non-TIPS rows in January 1997. Thus the page's date statement is not a proof that earlier rows do not exist; it also does not grant those rows complete fields or reliable historical vintages. The 1997 sample has missing clocks and bidder components. [Official query page](https://www.treasurydirect.gov/auctions/auction-query/); raw sources `treasury_1997_tips`, `treasury_2008_transition`, `fiscaldata_earliest`.

**Not proven:** exhaustive historical amendment/cancellation coverage, complete first-release intraday announcement archive, stable public API service limits, guaranteed source publication seconds, all predecessor quarterly schedule editions, actual cash delivery to every holder, or any incremental predictive benefit. Contemporary capture must begin under the existing data owner; historical limitations do not block the honest W1 product.
