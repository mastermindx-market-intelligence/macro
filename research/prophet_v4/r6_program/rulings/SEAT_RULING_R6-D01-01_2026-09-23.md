## Ruling
**D01 is resolved by composition (a): an explicit, versioned validity contract on the last-completed-session receipt, with a hard freshness ceiling.** (b) intraday re-emission is REJECTED — `engine/signal_gate.py` is a close-only statistic and running it on a partial bar changes what was validated. (c) binding from the Prophet Live armed pack is DEFERRED to a later wave and owes its own validation study before it may gate an entry. (d) do-nothing is rejected because `owner_confluence_gate_may_be_waived: False` makes the whole B4 vertical inert.

Census facts this ruling rests on (all OBSERVED): the sole writer stamps `as_of` from the last COMPLETED daily close; 13/13 committed samples have `as_of < date(emit.at_utc)`; a same-session receipt before a 14:00Z decision is unreachable from the writer's inputs; the consumer today RAISES on session mismatch instead of degrading to UNKNOWN; the producer already lags `expected_last_session()` by one session in 5 of 13 samples.

## Contract: `signal_gate.validity/v1` (frozen spec, amended R6-D01-01a after the Opus red-team — both build units implement exactly this)
Additive top-level key `validity` on `site/factordata/signal_gate.json`. `as_of` and `emit` are unchanged in meaning and format; **no date relabeling** — `source_session` must equal `as_of`. Verdict rows may gain ONE additive key, `asof` (the tape date the per-name verdict was computed on — the artifact already computes it and `buy_signal` currently strips it), so that per-name tape staleness is visible to the consumer.

```
"validity": {
  "schema": "signal_gate.validity/v1",
  "source_session": "<as_of, ISO date, or null when the producer has no as_of>",
  "emitted_at": "<emit.at_utc, byte-identical>",
  "expected_last_session": "<lib.nyse_calendar.expected_last_session(emitted_at)>",
  "lag_sessions": <SIGNED int: sessions from source_session to expected_last_session; 0 = fresh; >0 = stale; <0 = source AHEAD of the settled calendar>,
  "settled": <bool: source_session <= expected_last_session; false means the source bar may be partial>,
  "valid_for_decision_sessions": ["<the single NYSE session immediately after source_session>"],
  "expiry_session": "<that session>",
  "lineage_token": "<emit.pair_id — a tamper/lineage check; v1 carries NO revocation semantics>"
}
```
- Session arithmetic uses `lib.nyse_calendar` only (`expected_last_session`, `sessions_between`/`sessions_apart`, `session_n_forward`); no second oracle. There is NO `expiry_utc`: `lib.nyse_calendar` does not model early closes, and the close instant belongs to the B4 session policy (`engine/prophet_entry_policy.py`), which already confines decisions to RTH.
- Freshness is stated, never enforced by the producer: a lagging (`lag_sessions >= 1`), ahead (`lag_sessions < 0`, `settled: false`) or null-`as_of` receipt is STILL emitted with its state told honestly — never suppressed, never relabelled, never a crash inside the gate write (a crash there skips the gate write while the board write proceeds: the 2026-08-12 pair skew).
- Per-verdict `asof`: emitted as the ISO date of the last bar the per-name verdict used; a verdict whose tape date the producer cannot determine carries `asof: null`.

## Consumer law (`_bind_owner_confluence`, amended R6-D01-01a)
`owner_confluence = PASS` iff ALL hold: (1) `validity.schema == "signal_gate.validity/v1"`; (2) `validity.source_session == as_of` and is a non-null ISO session date; (3) `market_session ∈ valid_for_decision_sessions` AND `lib.nyse_calendar.session_n_forward(source_session, 1) == market_session` (the consumer recomputes; it does not trust the list alone); (4) `validity.emitted_at == emit.at_utc` and `emitted_at <= decision_clock`; (5) freshness recomputed by the consumer from `source_session` and `emitted_at` with `lib.nyse_calendar`: `source_session == expected_last_session(emitted_at)` — i.e. neither stale nor ahead/unsettled (the producer's `lag_sessions`/`settled` are cross-checked, never trusted alone); (6) `lineage_token == emit.pair_id`; (6b) `emit.writer == "build_stock_library"` (the incumbent check is kept); (7) the symbol's verdict row exists, is well-formed and `is_buyable` is true; (7b) `verdict.asof == source_session` (a frozen per-name tape — Russell cache stalls, the >20 % frozen-name breaker in `build_stock_library`, a `data/stocks` name ≤ 7 days behind — is UNKNOWN `confluence_tape_stale`, never PASS).
Any other condition — a missing `validity` block, a legacy artifact, a null source session, a session mismatch, an expired window, stale or ahead/unsettled source, a token or writer mismatch, a missing/malformed/stale-tape verdict — yields `UNKNOWN` with a typed reason; **the adapter never raises on artifact content** (B4 then fails closed to `UNAVAILABLE_DATA`). The PASS receipt names `source_session`, `verdict.asof`, the pair id and `emit.at_utc` (`signal-gate-pair:<pair_id>@<source_session>`); it never claims a same-session verdict.
Caller obligation (B4 runtime composition, not the adapter): load the artifact from its single canonical path at decision time and record the fetch instant in the runtime receipt; supersession within one session (a push render re-emitting the same `as_of` with a name demoted) is an accepted v1 residual bounded by the next-session-only window. `source_health` (hardcoded PASS today) must not be counted on to cover confluence tape staleness — (7b) is the only guard.
The accepted rule is a versioned field inside the hashed strategy identity: `engine/prophet_strategy_definition.py` gains `owner_confluence_source_session_rule = "next_session_only/v1"`. The `psd:` definition id changes by construction; that bump is intended. No test pins the id (red-team grep on #7581's head and on main); the single literal, `orch/audits/macro_PR-7535.mm.md:18`, is a historical audit record and stays untouched.
Accepted residuals (recorded, not built): `_PAIR_EMIT_STAMP.at_utc` is taken at module import, not at write time — a replay whose `decision_at` falls between import and write could pass (4) for an artifact that did not yet exist; replay-only, noted for the B4 replay harness.
