## Contract: `signal_gate.validity/v1` (frozen spec — both build units implement exactly this)
Additive top-level key `validity` on `site/factordata/signal_gate.json`. `as_of`, `verdicts`, `emit` stay byte-identical in meaning and format; **no date relabeling** — `source_session` must equal `as_of`.

```
"validity": {
  "schema": "signal_gate.validity/v1",
  "source_session": "<as_of, ISO date>",
  "emitted_at": "<emit.at_utc>",
  "expected_last_session": "<lib.nyse_calendar expected last completed US session at emitted_at>",
  "lag_sessions": <int: sessions between source_session and expected_last_session; 0 = fresh>,
  "valid_for_decision_sessions": ["<the single NYSE session immediately after source_session>"],
  "expiry_session": "<that session>",
  "expiry_utc": "<that session's scheduled close instant, UTC (holiday/shortened close aware)>",
  "revocation_token": "<emit.pair_id>"
}
```
- Session arithmetic uses `lib.nyse_calendar` only (the incumbent session-existence owner); no second oracle.
- Freshness ceiling: a receipt is fresh only when `lag_sessions == 0`. A lagging receipt is still emitted (never suppressed, never relabelled) and states its lag honestly.

## Consumer law (`_bind_owner_confluence`)
`owner_confluence = PASS` iff ALL hold: (1) `validity.schema == "signal_gate.validity/v1"`; (2) `validity.source_session == as_of`; (3) `market_session ∈ valid_for_decision_sessions` AND `lib.nyse_calendar` agrees that `market_session` is the next session after `source_session`; (4) `emitted_at <= decision_clock`; (5) `lag_sessions == 0`; (6) `revocation_token == emit.pair_id`; (7) the symbol's verdict row exists and is well-formed and `is_buyable` is true.
Any other condition — including a missing `validity` block, a legacy artifact, a session mismatch, expiry, lag ≥ 1, a token mismatch — yields `UNKNOWN` with a typed reason; **the adapter never raises on artifact content** (B4 then fails closed to `UNAVAILABLE_DATA`). The PASS receipt names `source_session` and the pair id (`signal-gate-pair:<pair_id>`); it never claims a same-session verdict.
The accepted rule is a versioned field inside the hashed strategy identity: `engine/prophet_strategy_definition.py` gains `owner_confluence_source_session_rule = "next_session_only/v1"`.
