Consequences the seat binds:
1. **Go-live of any live-plane unit is an `EXACT_HUMAN_GATE`** (operator env arm). Build units ship staged; the seat never sets `ENTRY_RADAR_LIVE_ENABLE` or flips `PAYWALL_ENABLED`.
2. **A B4 policy change has no runtime toggle by design.** B05/B12 must not add one; a shadow read, if needed, is a separate display-tier artifact with its own validity discipline, never a switch that selects which policy is authoritative.
3. **`ENTRY_OPEN` is never persisted.** Today no producer writes the B4 state to `site/` or `data/`, so the "restore a cached old ENTRY_OPEN" hazard does not exist; it is forbidden to create it. Any future B4 cache must carry the same next-session validity + lineage discipline as `R6-D01-01a` and must read through the authenticated path (the stale-CDN-variant trap the live plane already documents).
4. **Rollback does not un-advance ledgers, grades, origination receipts or user state** — a revert only changes what a NEW card says. Release adjudications must treat forward ledgers as irreversible.
5. **Entitled-user proof is a real-session act.** `ux-evidence` authenticates only through a live CDP session; `capture_page_evidence.py` is anonymous-only by law. The B20 acceptance gate therefore includes one authenticated `ux-evidence` run (seat host or operator); no synthetic login is ever built.
