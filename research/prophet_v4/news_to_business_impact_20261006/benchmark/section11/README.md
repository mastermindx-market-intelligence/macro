# Section 11 registration

`registration.json` is the freeze that DEC:NEWS-IMPACT-SECTION11-REPORT clause 13 requires
before any GLM output exists. It is generated by
`engine/news_impact/section11_registration.py` and holds ids, enums, counts, seeds and
sha256 pins only: no filing text, no labeled values.

## What it freezes

- **System under test** (clause 1, 4): the qwen family. `cheap_extractor_no_frontier` is
  qwen3.7-plus on prompt-v1.2 through producer stage one and validate_event;
  `proposed_cascade` adds qwen3.8-max only on deferred, quarantined or
  classify_event-disagreement cases. The W2 fam_b returns are labels and are never reused
  as system output.
- **Gold** (clauses 1-3): MiniMax-M3 (the accepted W2 fam_a drafts) and GLM, which drafts
  every critical slot of every v2_match case. The third family on a MiniMax/GLM
  disagreement is named in rank order (deepseek-v4.1-flash via go, then
  deepseek-v4-flash-0731 via bailian); qwen, MiniMax, GLM and MiMo are excluded. A slot
  with no third value is null_printed and counted.
- **Populations** (clause 8): `v2_match` is the 74 gated_v2 cases the v2 census routed
  MATCH (T1 34, T2 36, T3 4, every fold historical), with the shortfall against 200 per
  template. The 12-case label queue is listed separately. gated_v3 is a rule, not a list:
  it runs on or after 2026-10-20 as frozen in `../issuer_fallback/README.md`.
- **Critical slots**: 142 slots across the v2_match cases (T1 34 x 3 fields, T2 36, T3 4).
  Queue cases take their slots from `results_w2/v2_queue`, the others from `results_w2`.
- **Draws** (clauses 5, 6): the frontier_only_audit subset is drawn now with seed 20261021,
  ceil(10%) of each template-polarity cell, 13 of 74 cases, and is never widened. The
  gold-agreed seat audit uses seed 20261022 and is drawn by
  `section11_draws.gold_agreed_audit_draw` once GLM and MiniMax agreement is known and
  before any system score is read.
- **A3 registration**: `eval_receipt.make_registration` in confirm mode, pinned to the
  endpoints registry, the prompt-v1.2 sha256, the gated_v2 tape and t_prospective
  2026-10-15T00:00:00Z.
- **Operator tap** (clause 13): the cascade.v1 `lanes_require_operator_tap` lanes and the
  measurement-run slot caps, copied from the contract.
- **Inputs**: every file the registration reads, with its sha256. Five of them (the
  endpoints, cascade and two A6 schemas, and the prompt-v1.2 template) must match the
  shas the code holds, or the build refuses with FROZEN_INPUT_CHANGED.

## Commands

```
PYTHONPATH=. python3 -m engine.news_impact.section11_registration --check
PYTHONPATH=. python3 -m engine.news_impact.section11_registration --out <scratch path>
```

`--check` rebuilds the registration and compares it with the committed file. CI runs the
same comparison in `tests/test_news_impact_section11.py`.

## Changing it

The build refuses, with a named code, when a count it froze moves: MATCH counts per
template, the queue size, the critical-slot counts, a duplicate or unknown id, a field that
is not critical, or a forbidden key or word. Editing any pinned input changes its sha256
and fails the CI comparison. Once GLM output exists, a change means a new
`registration_version` with a DEC record that says why; the committed file is never
regenerated in place to match new inputs.
