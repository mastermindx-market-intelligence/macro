## What happened

The S1FIX lane made the S1 residual runner abstain on non-finite
closes and count the drops (`residual/s1_data.py`,
`residual/s1_decomposition.py`). Integrated into INT3, a full S1
regeneration then differed from the sealed v1.1 receipts on four
files, every difference in `code_tree_sha`.

`run_s1.py` stamps
`code_tree_sha = git rev-parse HEAD:research/single_name_intelligence/residual`
into each `results/P0x.json` and `REPORT.md`. The runner directory is
therefore sealed code: any edit under `residual/` changes the stamp,
and the regenerated bytes no longer equal the sealed bytes. Earlier
drift on this check was misread as numerical noise; it was the stamp.

| runner | residual tree |
| --- | --- |
| v1 | `44377b14` |
| v1.1 (sealed) | `f9f4bf6442a948b7500228f9f963fc50a2ac7168` |
| v1.1 + S1FIX | `307a2d61` (not sealed) |

## Decision

S1FIX is correct and is deferred, not dropped. It ships only as the
next registered S1 runner version, the way v1 became v1.1.
Registration is R1-gated, so INT3 reverts the cherry-pick. The fix
stays on its lane branch
`claude/sni-s1fix-20261013-20261013T122448Z` at `c0349286`.

## Guard

`tests/test_sni_seal_full_check.py::test_schk_10_residual_tree_is_the_sealed_v1_1_runner`
asserts that the v1.1 receipts carry exactly one `code_tree_sha` and
that `HEAD:research/single_name_intelligence/residual` equals it. The
next edit to `residual/` fails that test by name instead of
surfacing as seal drift.

`seal_full_check.py` also now loads `residual/build_seal.py` by file
path (`schk_09`), so an `event_response/` module on `sys.path` cannot
shadow the S1 builder.
