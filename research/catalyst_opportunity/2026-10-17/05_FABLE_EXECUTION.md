## 2. Proposed delivery structure

Use up to six **logical responsibility lanes**, not six mandatory concurrent principal sessions:

| Lane | Responsibility | Appropriate role |
|---|---|---|
| A | Source, rights, identity and temporal data | Bounded data-integration operator with domain-owner inputs |
| B | Event semantics, specialist economics and exposure | Domain suborchestrator with separable specialist workers |
| C | Market/theme discovery, Radar and timing | Quant/market-data implementation operator |

| E | Terminal/BFF, user workflow and notifications | Product/frontend-backend integration operator |
| F | Runtime, security, reliability and release evidence | Operations/integration operator with consequential independent review |

A single qualified operator can own more than one lane when overhead is lower. A suborchestrator may delegate only within actual conserved-root depth, budget and descendant limits. There is no assumed unlimited concurrency, no multiplication of allowances and no duplicate writer for a shared module. Reserve capacity for review and repair. Native Sol children are not substitutes for economical Fabric labor merely because a native spawn tool exists.

Each worker packet contains the exact operation, source pin, allowed paths, inputs, output, failure/refusal behavior, positive and hostile tests, proof level, actual economic limits, next action and return target. Return concise evidence and artifacts, not a transcript. Fable adjudicates the integrated result against the user's original job.
