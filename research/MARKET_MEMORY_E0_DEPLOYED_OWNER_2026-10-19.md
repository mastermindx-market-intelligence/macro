# Market Memory E0 deployed owner and reserved access

Source decision, 2026-10-19. Scope: the existing Market Memory evaluation obligation. Rebased source base 2f1fd99a8ae295c4aeec2ca3726aa498a7545e97. Existing E0 control/domain contracts and frozen protocol stay unchanged. No actual study is admitted by this record.

Research Factory's E0 validators establish record consistency and domain joins. They do not implement an installed admission owner or durable reservations. Its generic JSONL ledger accepts caller paths and tolerates torn lines; it is unsuitable as the sole reservation authority. Reusing it as an access grant would repeat the previously rejected design.

Use one deployed administrator entry point under /opt/macro, analogous to the existing price-metadata inspector's explicit trust boundary. Protected source installation plus the authenticated OS administrator invocation supplies authority; self-consistent JSON, Python types and file hashes do not. The entry point has fixed production paths, verifies its installed source closure and current source registration, and accepts immutable study/operation identities rather than caller paths, owner flags or arbitrary import/loader names. No signing key or new identity service is introduced. A caller who can replace root-owned deployed code is outside this boundary, just as for the existing owner.

Extend the existing Research Factory data namespace with private Market Memory E0 study state. Read-only deployment inspection found /opt/macro/data/research_factory is a real root-owned0755 directory, not a symlink. New study directories must be0700 and records0600. This is an implementation of the already-declared E0 access/reservations contract, not a new candidate lifecycle, scheduler, service, memory database or generic execution queue. Existing candidates/transitions/paper-monitor and W6A refusal rules remain untouched.

Admission must authenticate current installed selection of the exact frozen registration, independent closure, publication and installation objects; resolve all existing domain references; verify the independent-review identities and result; and establish initial current access state under the deployed owner. A versioned deployed selection is the administrator's admission act. A metadata record never self-selects itself. Absent or inconsistent selection refuses before private study or label I/O. The actual records and closure remain pending their existing prerequisites; source implementation does not fabricate them.

An operation binds study, installation epoch, registration/publication digests, task/condition/source scope and immutable operation ID. Reserve budget durably before the first potentially label-bearing read or provider call. A repeated operation with changed intent is a conflict. A repeated pending operation is an unresolved effect, not permission to execute again. A completed operation returns only its retained exact result after current authorization. Lost responses do not consume a second look or replay a provider.

Storage uses one per-study process-shared directory lock, bounded strict canonical state, immutable journal events/results, and an atomic durable selected-state pointer. It records reservations and completion in the existing owner's namespace. Each journal event chains to its predecessor; counters are derived from unique operations, never caller counters. At most 1,024 looks yield 2,049 small events rather than quadratic cumulative snapshots. Result contents are hash-checked on explicit read; accounting reads inspect their metadata without disclosing them. Symlink, hardlink, owner/mode, malformed/torn/oversized state, binding drift and orphan publication fail closed. Publication must fsync bytes and directory entries before returning a new reservation. A crash with a pending operation preserves its reserved budget. Recovery may only consume qualified retained output for that same operation; uncertain label access cannot be replayed or refunded.

The installed owner performs current authorization before reservation/first read, before result persistence and before disclosure, including cached completion. Time comes from the actual owner clock; caller cutoffs describe research, not current authorization. Revocation, expiry, contaminated study or source/installation changes prevent new reads and disclosures. Existing reservations are retained for reconciliation, not silently erased.

First source slice: isolated reservation implementation and adversarial tests; then the fixed installed owner and its real consumer composition. No production activation until one proportionate independent review and protected release. Source checks, installation, first admitted read, retained output, and study acceptance remain separate. No old exporter/review is relaunched; no frozen Ubuntu0 result is collected.

The current domain resolver intentionally always reports domain_metadata_complete=false and operational_admission=false. It understands task bindings but lacks payload contracts for interval splits, reviewer independence, allocation, outcomes, baselines and metrics/access semantics. Reference closure must not be relabeled semantic completeness. The storage slice is usable by a later qualified installed owner; no current application entry point or actual study selects it.

The executable baseline preparation now composes the existing sealed contextual retrieval owner. No-memory keeps the same query identity and selects zero historical contexts; this is a condition assignment, not an abstention. Recency uses source measurement session descending, then context ID ascending, over exactly the numerically eligible representatives from the fixed method. It inherits the original earliest-revision choice, missing-coordinate exclusions, query/source cutoffs, purge/embargo, denominator and k. Fixed L1 retains the original selection unchanged. This is a pre-label implementation choice for the existing recency condition; the eventual registration must pin its source digest. No new method or challenger is introduced.

Condition selections retain exact context/capture/query/packet identities, source sessions, original membership and fixed-selection digests. The original retrieval owner rechecks the whole compared population on every disclosure, including unreturned candidates. The bundle is source-selection metadata for the trusted study executor, not a blinded model/reviewer prompt; that executor still owes separated condition packets and preregistered blinding. Joint preparation runs shared qualification and fixed math, so its elapsed time cannot be reported as isolated no-memory or recency cost. No synthesis, source-content fetch, annotation or numerical outcome read is introduced.

Acceptance must cover two-process contention and same-ID replay, conflicting intents, budget exhaustion, crash at each durability boundary, changed/revoked installation, no loader call before durable reservation, no second loader call after pending/completed state, and no cached disclosure after revocation. Complete real E0 metadata/closure is necessary for activation but does not block implementation of these mechanisms.

Alternatives rejected: caller-provided authority flags/hash receipts (no trusted origin); reusing the tolerant display JSONL append as sole accounting (not transactional); a new service/database/scheduler (unnecessary parallel owner); waiting for enrollment when the mechanism is missing (does not implement the capability). Strongest counterargument is added filesystem protocol complexity. The falsifier is an adequate existing RF transaction owner with equivalent semantics; none exists in the inspected ledger/runner. Keep the extension narrow and reuse the existing validators and namespace.

The condition-order utility implements the frozen seed with per-task SHA-256 rejection sampling over six condition permutations, binding study, exact task-manifest digest and task ID. It rejects a substitute seed, malformed/duplicate identities and more than 10,000 tasks. This deterministic allocation mechanism does not select actual tasks, authenticate their provenance or establish reviewer blinding. The trusted study owner must resolve the exact task manifest and withhold this condition mapping from reviewers. Baseline k is constrained to the existing E0 domain maximum of eight.

Independent static review of the reservation implementation returned PASS with no blocking finding; its runtime and test bytes remain unchanged. All metadata and result digests still require current authorization because even a low-entropy label digest can disclose information. The deployed owner must qualify result provenance before completion, use a root-owned parent and a private study directory, and reconcile orphan publication without cleanup, replay or refunds. Local source tests do not establish Linux production or study admission.
