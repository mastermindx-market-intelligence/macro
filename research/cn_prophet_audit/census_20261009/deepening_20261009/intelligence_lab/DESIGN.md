# Intelligence contract laboratory — design frozen before results

This is an executable research prototype, not an installed ranking policy or new feature store. It settles four implementation choices using the accepted October 9 population and hostile synthetic records. No returns are used by this laboratory.

1. Compare coverage over all scored, raw-eligible, signal-buyable and already qualified pre-cap names. The first three are diagnostic scopes. The proposed featured ordering scope is the qualified pre-cap population, computed with the same existing admission rules **before** either cap. This is a new versioned policy, and is not authorized for production by these results.
2. Keep score and intelligence orders separate. Require complete finite, numeric, bounded intelligence evidence in the competing population; otherwise retain the entire incumbent score order. Measured zero remains valid. Reject duplicate/malformed candidate identities. Do not use a per-row V3 substitute as an intelligence value.
3. Freeze every feed's normalization reference population after its decision-time source qualification, before feature calculation. An unrelated candidate with missing intelligence must not change coverage of already qualified competitors. A new genuinely available observation in a feed's normalization population can legitimately change relative feature values and must create a distinct generation. These are different invariants.
4. Prototype **system-observed replay** of source revisions: UTC-aware decision cutoff; source publication and first-seen times no later than the cutoff; unique version identity; explicit observation session for fast data; slower facts remain usable until superseded or expired by their own contract. Later corrections must not rewrite earlier decisions. Date-only publication, missing first-seen and unversioned payloads cannot certify system-observed historical availability. Historical market reconstruction is a separate evidence mode, not implemented by trusting a Boolean provenance flag.

The input probe records actual source schemas/clocks and a minimal lossless projection of the current qualified rows. It does not invent publication timestamps for them. Behavior tests include valid zero, all-zero intelligence, missing qualified/unqualified rows, malformed types, duplicate identities, permutation invariance, post-cutoff additions, later corrections, equal values, source-day expiry, long-lived periodic facts and changed normalization universes.

Acceptance is correctness of those contracts and exact V3 positive-control reproduction. A changed shortlist proves only selection influence. Actual source-time-qualified production coverage and investment improvement remain separate unanswered questions. Findings can reject the prototype's design; any amendment is explicit.

## Explicit design amendments before the second challenge

The first 41 checks exposed a further design question, not an observed production incident: filtering invalid or expired revisions before choosing a version can silently resurrect an older value. The revised experiment first identifies the latest **known, provenance-qualified** revision of each upstream observation, then evaluates its payload/validity. A known retraction, invalid numeric correction, expired correction or unqualified cadence must suppress that observation; none may restore an older revision. A correction not yet known at the cutoff must leave the earlier decision intact. Retraction and payload status are proposed explicit source-contract fields, not invented history for current caches.

Expected observation sessions are source-specific. The current margin cache legitimately carries the prior session while its collection day is current; imposing one global observation session would wrongly reject it.

The analyst duplicate experiment found 475 exact duplicate ticker/payload groups and zero conflicting groups. Actual reader outputs and percentiles are invariant to full physical row reversal. This negative result does not justify changing current scores. At a future versioned-record boundary, exact canonical duplicates may be coalesced; conflicting records claiming the same known version must fail closed. Candidate identities and score ranks remain unique.

The temporal selector returns source observations, not already aggregated ticker features. An upstream source with multiple observation identities for a ticker must retain its existing qualified aggregation rule before cross-sectional normalization. A dictionary's last row is not such a rule. Numeric revision ordering is a fixture of this prototype: a production source must supply or preserve an authoritative revision order; arrival order and hash order cannot invent one for legacy data.

## Independent challenge and repair

The separate reviewer reproduced the 56-check version exactly and retained it with thirteen failing synthetic cases under `../reviews/intelligence_contract_review/`. The revised principal prototype now excludes provably future availability before validating unrelated identity fields; chooses known higher revisions even when their applicability is malformed, then suppresses them; validates source-session syntax and caller-owned cadence (`expected_sessions` plus explicit `periodic_families`); rejects noncanonical ticker syntax; and handles unrepresentable numbers within the contract exception model. Exact duplicate comparison uses canonical JSON after lossless normalization of equivalent scalar numeric representations. It does not equate `True` with `1`, or round distinct large integers into the same value.

Normalization now requires one source family, unit and feature-contract identity, as well as one aggregated feature per canonical issuer. The caller must derive the expected trading session from the existing source/calendar owner; date-format validation alone is not a trading-calendar proof. Numeric intelligence coverage still does not certify compatible generations or source-time coverage. The existing generation owner must bind the qualification population, incumbent score/rank, intelligence inputs, feature normalization population and calibration receipt before this ordering function is called. All-zero reproduction is established for the coherent current dataset, not for contradictory caller-supplied ranks.

This remains a fail-closed research contract, not a complete versioned source store. Records lacking availability cannot certify historical completeness. Exact current analyst duplicates remain harmless in the tested reader; synthetic failure fixes do not establish current-data corruption. The separate repaired-hash acceptance will retain the original failure record.
