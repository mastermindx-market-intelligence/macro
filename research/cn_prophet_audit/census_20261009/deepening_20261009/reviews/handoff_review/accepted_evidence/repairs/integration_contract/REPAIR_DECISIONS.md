# Integration contract: repaired executable research result

The seven reproduced integration failures are addressed in this new research package. The repair preserves the existing China event store, archived pack, scheduled reconciliation and daily ledger owners. It adds strict evidence validation around pinned native functions. It does not create a production ledger, call a vendor, change a production source/data file, or certify an economic fill.

The study remains frozen at Macro `3d90aad6d83152dfeeaf8345bc995826ac9d3139`. `DESIGN.md` records the seven preimplementation hypotheses and the later clock amendments. `baseline_identities.json` and `baseline_preservation.json` bind the unchanged original laboratory and sealed reviews. The original laboratory's successful prototype run is retained as historical evidence; its seven independently reproduced gaps are not erased by this repair.

## What the executable result establishes

The full runner reads the actual canonical artifact, exercises all 180 frozen score/rank projections through the native pack assembler, performs a genuine three-name gate probe, and invokes the actual evaluator driver six times with an isolated in-memory transport. It then rolls the current pack key to the synthetic next-session settlement generation, resolves the prior generation from its archive, consumes real native event shapes, and writes/replays a temporary ledger using the native Parquet writer. The new refusal and compatibility controls run against those same inputs. Exact counts, source hashes, runtime and code identities are in `integration_results.json`; the terminal process receipt is in `execution_receipt.json`.

The recorded path has three names, four distinct events and four daily ledger rows because the native key includes event kind. The membership receipt has two confirmed names and one dropped name. The ledger's technical confirmation is separately taken from the same-session settlement pack's `center_buyable`: that is not a fill or realized-return label. `close_same_day` and `next_close_fill` remain null.

The retained-fixture verifier replays the complete three-authority join and all saved object/prior-row counterexamples through nine exact native modules without importing a checkout or calling the network. It also checks the exact compressed canonical board, native parser bytes, source contract, executed code and retained Parquet identities. Local replay does not pretend to execute a missing local Parquet engine; the full host run and independent review provide actual file-backed evidence. `--parquet` is available to rerun the file refusals where an engine exists.

## Seven interface decisions

| Reproduced failure | Repaired contract | Discriminating evidence |
|---|---|---|
| A whole daily key could vanish from the spool while its old row survived | Every retained target-session row's consumed event IDs must be a subset of the complete resolved session spool, before iterating reconstructed rows | Removing one transition object or all transition objects refuses; a truly new zero-event session with a valid close snapshot remains valid |
| Readable duplicate or unrelated Parquet could be silently merged/rewritten | Validate native schema, row shape, session/key validity and key uniqueness before native merge; reject exact and conflicting duplicate daily keys uniformly | Both conflicting orders, exact duplicates, unrelated tables, unknown row schemas and empty unrelated tables refuse with zero writer calls and unchanged bytes |
| Equal-built-at conflicting closes could be selected by a content digest | Canonicalize membership/economic fields, group by exact observation time, refuse conflicting ties, and coalesce equivalent evidence while retaining all supporting object keys | Both nonce-order variants refuse; reversed row order and irrelevant metadata coalesce to the same membership receipt |
| A raw-basis label was stamped without source evidence | Natural inputs remain unavailable unless a supported source contract resolves exact retained bytes through an identified adapter; the positive fixture is explicitly synthetic | Missing basis, raw declarations and adjusted declarations cannot qualify natural inputs; altered bytes, adapter identity, record hash and copied price fail independently |
| Native FIRST_WINS could silently retain a tampered first price | Reconstruct the first observation from the authentic resolved first event and archived pack; compare its complete projection and hash before merge | Changed first price, first/quote clock, source identity, basis or frozen fields refuse even when the copied projection is rehashed; an authentic later repeat updates last/count fields and preserves first fields |
| Huge JSON integers could raise untyped numeric overflow | Numeric predicates reject values that cannot satisfy the finite floating-price contract without throwing | `10**400` is rejected per name while peer names continue; source-payload and ledger boundaries refuse it explicitly |
| Rehashed packs accepted scores outside the contract | Apply finite 0–100 validation at pack ingestion as well as canonical projection | Rehashed -1, 100.01 and huge scores refuse; zero and 100 are accepted |

All refusals occur before the native atomic writer. Null/list/scalar normalization addresses actual Arrow/pandas readback representations; it is not a provenance repair. A missing ledger means no prior rows. A corrupt or schema-invalid ledger does not mean an empty ledger.

## Event time and first-observation authority

An event must have an archived pack and a source receipt that were known by that event's own timestamp. Later envelope publication cannot make a backdated event valid. The independent reviewer supplied and executed both counterexamples: a receipt first available at 02:01 attached to a 02:00 event, and a pack built at 02:01 attached to a 02:00 event. Each now refuses while an actual native 02:01 event remains valid.

The pinned native serializers truncate their ISO timestamps to seconds. A real source receipt can have finer precision, so simply comparing it to a truncated event stamp would reject a legitimate observation from the same fractional second. The repair first verifies agreement with the native evaluation second, then preserves the supplied evaluation instant at full precision in the existing `ts` and `built_at` fields. A native evaluation and source receipt at 02:00:00.500000 pass without relaxing the source-before-event rule. This is a timestamp-precision change in existing ISO fields, not a new ordering service.

After exact event-ID deduplication, all events for one daily key must use one generation. Distinct identities at exactly the same retained event instant refuse as ambiguous. A digest establishes identity; it cannot decide which differing price or source observation was first. Strictly later events can update `last_ts`, `last_px`, `occurrences` and the consumed ID set. Their replay is idempotent. The complete first-observation projection stays unchanged.

## Source evidence: what is native and what is proposed

The immutable native adapter bytes in `pinned_quote_adapter.py` are an exact copy of `engine/live_quotes.py`, SHA-256 `bd8bfd85bf4ff1279d564220b7f3f8b8b4e5f7263323252ae6489ed5163d1074`, Git blob `f7ad6ebc550811708a20aaf259b30dd1df0a3699`. The resolver extracts and executes its pure Yahoo parser functions without importing its network client. The full runner also hashes the pinned Tencent path, local snapshot adapter and scheduled caller source as part of the original file, and the snapshot projection source separately.

| Surface | Native or research extension | Meaning |
|---|---|---|
| `price`, `prev_close`, `quote_ts`, `source`, `price_basis`, `quote_ts_synthetic` and the other quote fields | Native parser outputs | Yahoo `price_basis=regular` describes the quote rung; it does not establish adjustment basis. A supplied payload timestamp can make the native synthetic-clock flag false even in a synthetic research payload |
| Native Yahoo/Tencent parser implementation | Exact pinned code | Neither parser supplies the natural adjustment-basis receipt required here |
| Local snapshot normalization | Exact pinned code | Projects to price, previous close, change, time and generic `source=quotes`; it does not retain enough provider/basis custody to certify raw prices |
| `SYNTHETIC_QUOTE_CONTRACT` and `SyntheticQuoteResolver` | Explicit research additions | Define this synthetic scenario's CNY/unadjusted units, field mapping and exact parser identity; no natural provider is admitted |
| `source_evidence` | Proposed event extension | Retains contract ID, explicit synthetic origin, source receipt time, exact original UTF-8 payload text and SHA-256, and the native parsed-record SHA-256 |
| `price_adjustment=unadjusted_research_fixture` | Explicit research label | Separates scenario units from an actual vendor's unadjusted print |
| `pack_id`, source-board identity, event ID and first-observation metadata | Proposed additive evidence | Bind the existing event transport and existing ledger row to the correct archived source generation |

The resolver hashes the original payload bytes before parsing; different whitespace changes the source-byte identity while leaving native parsed economics equal. Caller-supplied provider/basis strings, a Boolean qualification flag, or numerical previous-close agreement cannot qualify the source. Altering an event's price and recalculating its digest still fails if the price does not equal the native replay of its retained source payload.

The pack's adjustment string and anchor are retained as producer declarations. The native probe metadata also records three unknown input-adjustment classifications. This package does not turn a declaration or historical price-file match into a publication receipt, fill receipt or corporate-action conversion. The vintage and tradability workstreams own those separate questions.

The required event inputs already have an incumbent owner and transport. The implementation should reuse the existing China event spool and archived pack store. It needs an additive evidence envelope/source receipt, not a second production event feed or ledger. Native event `price` remains the producer field; `px` is only the adapter for the existing reconciliation function.

The three joins remain distinct: archived N−1 pack for first-event identity and frozen score/rank; N settlement pack for the technical gate verdict; N canonical board for the membership receipt. A current key that has rolled to N cannot replace the archived N−1 authority. No ranking formula, promotion policy or array reordering is changed. Zero remains a valid score; published `board_rank` is not substituted with `score_rank`.

### Existing ledger compatibility

The native schema name and `(date, ticker, kind)` daily key remain. Older valid noncolliding native legacy rows retain their existing fields and acquire no new provenance; nullable columns introduced by a mixed Parquet table remain null. An unbound legacy row in the target session is refused for incumbent-owner adjudication. Duplicate daily keys are also refused uniformly. This package supplies no automatic migration, guessed provenance, original-latch rewrite or ledger replacement.

## What remains a natural-process proof gate

The research fixes establish the bounded interface behavior and reproducible refusals. Production readiness still requires the installed evaluator and scheduled consumer to produce a natural source-qualified event, retain its actual source/receipt identity and prior pack, persist a zero-transition close snapshot, list the complete actual store, and replay the existing durable ledger idempotently. Actual permissions, retention, object-read failures and scheduler failure reporting require natural receipts.

The natural quote source's adjustment basis remains unavailable under the pinned adapter evidence. Its owning contract must be resolved before qualifying natural prices. Source-board publication vintage, benchmark/fill economics and full-universe tradability remain separate gates, with their own owners. The laboratory's 60-second future-quote allowance is an explicit research parameter requiring owner ratification; it does not loosen the source-receipt-before-event or pack-before-event boundaries.

## Reproduce

For the complete frozen-source gate/driver/Parquet experiment:

```bash
python3 -B run_lab.py --repo /path/to/macro \
  --sha 3d90aad6d83152dfeeaf8345bc995826ac9d3139 \
  --out /tmp/cn-integration-repair-results
```

The runner creates its own immutable-source export and refuses production output paths. It requires Python, pandas, a Parquet engine and PyYAML. The recorded host used Python 3.14.7 and pandas 3.0.5. Measured pack build duration is part of the native pack contents, so a new run can have different content IDs while preserving the same source inputs, values and assertions.

For the exact retained run without a source checkout:

```bash
python -B verify_contract.py --out /tmp/cn-integration-retained-replay.json
```

Add `--parquet` where a Parquet engine is available to replay the six saved file refusals in a fresh temporary directory. Neither verifier requires a vendor or production service. `MANIFEST.json` binds this candidate's exact code, results, receipts, fixtures and memo; the independent acceptance is kept outside this package so the reviewed candidate remains unchanged.
