EVIDENCE:

**MAJOR — producer and consumer resolve `site` through two different roots; a non-default `storage.site_dir` makes the consumer withhold forever.**
- Producer: `engine/china_intel_hub.py:128-130` calls `narrative_crossmarket.compute_china_us_context(_root() / "site", observed_at=observed)`, where `_root()` is `config.ROOT` (`engine/china_intel_hub.py:85-86`). The path `site` is hard-coded.
- Consumer: `engine/china_intel_bus.py:586` calls `context_for_briefing(data.get("us_theme_context"), site=_site_dir())`, and `_site_dir()` is config-driven and may be absolute (`engine/china_intel_bus.py:57-59`: `Path(config.load()["storage"]["site_dir"])`, returned as-is when absolute).
- The consumer then re-reads the source tree through that `site` and requires byte equality with the producer's receipts: `engine/narrative_crossmarket.py:466` (`latest = compute_china_us_context(site, observed_at=now)`) and `:469` (`if any(latest["sources"][r]["sha256"] != sources[r]["sha256"] ...) return unavailable("SOURCE_CONTENT_CHANGED")`).
- Consequence: whenever `storage.site_dir` is not exactly the relative string `site`, producer and consumer read different trees. The outcomes are either permanent `SOURCE_CONTENT_CHANGED` / `SOURCE_CONTENT_UNAVAILABLE` (silent, indistinguishable from a real same-day correction — the very signal this check exists to raise), or, if the two trees happen to hold different-but-valid bytes, a mismatch that is reported as a source correction that did not occur. `config.yml:50` currently sets `site_dir: site`, so the default deployment coincides; the defect is latent, not currently firing, and `lib/config.py:39-40` already exposes the canonical `config.site_dir()` the producer does not use. Severity major rather than blocker because it fails closed (withholds context) rather than emitting context under a false receipt.

**MINOR — producer-side `sources` shape differs between the two `UNAVAILABLE` emitters, and only one is contract-checked.**
