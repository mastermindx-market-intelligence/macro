## 7. Identity and temporal correctness

Reuse #8637's `ReferenceSnapshot`/`ReferenceReadReceipt`. Pure validation is not proof of real original read custody. Capture and decode the exact complete artifacts, bind actual owner receipts and use the same eligible generation in both lookup directions. Later eligible refusal shadows earlier binding. Receipt-only changes must remain visible even if Parquet bytes did not move. Old views never borrow new issuer/master bytes.

Validity is half-open and namespace-specific. A stable house file key may differ from the current vendor symbol. Regenerate from the actual committed predecessor, not an empty scratch output that deletes absent records. Compare semantic rows as well as bytes. A double receipt read only proves what the existing protocol guarantees; it does not alone prove latest-state linearizability or prevent A→B→A ambiguity.

The [temporal primitives](https://github.com/mastermindx-market-intelligence/macro/blob/bb8da347eca15e480a1f423f4905e2a6f452bf62/lib/dataos/temporal.py), blob `094b149a8b9158f19cb99c4005568c12db96ed41`, filter a chosen clock. Distinguish event/effective time, publication, system observation, derivation and retained consumer/output recording. A source published before t but first acquired after t may support a qualified public-information reconstruction, not proof that Mastermind used it at t. A later correction carrying an old event date is not eligible in an earlier observed view. Current code over historic inputs is recomputation, not original system replay.

Choose the greatest eligible revision by stable record identity and declared mode. Source clocks cannot be guessed from filesystem time, query dates or build timestamps. All dependencies—raw price, actions, identity, membership, transform—must satisfy the guarantee. Hashes cannot recreate unretained material. ## 8. Corporate-action and price mathematics

Start from [the existing basis vocabulary](https://github.com/mastermindx-market-intelligence/macro/blob/bb8da347eca15e480a1f423f4905e2a6f452bf62/lib/dataos/price.py). Vendor methodology is endpoint-specific: [Massive aggregate adjustment](https://massive.com/knowledge-base/article/how-can-i-get-historical-stock-data-adjusted-for-splits-and-dividends) and [Tiingo EOD fields/corrections](https://www.tiingo.com/documentation/end-of-day) are not a universal `adjusted=true` contract. Use only qualified existing licensed source data; no purchase is commissioned.

For a simple split r=new shares/old shares and target share-reference v:

`S(t;v) = product(r_e for t < effective_e <= v)`

`P_sadj(t;v) = P_raw(t) / S(t;v)`

Apply the inverse quantity transform only to quantities known to be raw shares under the same convention. Do not adjust already adjusted inputs again. Keep exact ratios internally, coherent OHLC basis and declared rounding. Fractional adjusted volume is not automatically invalid; synthetic open remains synthetic.

Cash distributions additionally require currency, per-share basis, entitlement/ex/pay dates, same-boundary event order and reinvestment/withholding policy. Original declared cash, current-share restatement and backward price-normalization factor differ. A simple independent holding oracle uses `wealth = shares × raw_price + cash`. Vendor-adjusted closes cannot silently impersonate that ledger.

Qualify ordinary forward/reverse splits and cash dividends first. Special distributions, rights, mergers and spin-offs need explicit admitted economics or typed unsupported intervals; do not invent a generic conversion. A real no-action interval requires coverage evidence, not just an empty endpoint response.

**Do not overstate vintage effects.** Multiplying both return endpoints by the same nonzero scalar leaves their simple return unchanged. Vintage differences may matter for absolute levels, different endpoint factors, action boundaries and cross-leg comparisons. Tests must include both the invariant control and a false-return counterexample. Do not claim every earlier result is wrong or silently rewrite it.

Future-suffix changes across raw values, actions, references and membership must not change an earlier qualified observed result. A current view may update explicitly. An exact retained view needs actual bytes/output and current read rights; removal or revocation produces refusal, not substitution.

Synthetic correction proves machinery, not natural production acquisition.
