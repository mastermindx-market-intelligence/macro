## User and machine outcome

The user problem is that current Mastermind AI can answer from supplied/internal
context without actively closing material evidence gaps. R1's first machine
capability is deliberately narrower than customer wiring:

`minimal public research query -> external search -> selected source extraction ->
normalized evidence receipt that proves what was searched and what source content
was actually retrieved`.

The receipt must make these different states impossible to confuse:
search not configured, invalid public query, provider/search unavailable, no search
coverage, search snippet found but source not opened, source extraction failed,
source opened with bounded content, and partial source opening.

No model conclusion is generated by this slice. The later analyst must consume this
evidence; provenance does not substitute for synthesis.

## Why Tavily is the first qualification carrier, not a permanent routing decision

Official Tavily docs rechecked 2026-09-19 describe:
- POST `https://api.tavily.com/search`;
- search depths advanced/basic/fast/ultra-fast;
- a `finance` topic alongside general/news;
- date windows and provider-estimated published dates;
- advanced/basic/fast snippets, with provider answer/raw-content separately optional;
- POST `https://api.tavily.com/extract` for source content;
- extract basic/advanced modes, up to 20 URLs;
- query-aware extraction that reranks source chunks;
- per-URL `failed_results`, including partial/all failure under a successful HTTP response.

Those properties make search + actual source-content extraction testable with one
provider. Brave and other providers remain legitimate comparison candidates. This
source does not mint a provider winner or credential authority.

## Source architecture

New provider-neutral evidence boundary:
`engine/neuralweb/public_research.py`.

It is intentionally not registered in `brain_gateway.py` yet. That shared gateway
is owned by the separately held financial bridge (#7365), and R1 must prove retrieval
semantics before creating a customer-visible tool.

The module has three public stages:

1. `search_public`
   - requires a service key from the explicit argument or `TAVILY_API_KEY`;
   - validates a minimal public query (<=400 chars, no control characters);
   - bounds provider topic/depth/date/domain filters and results;
   - disables provider-generated answers and raw page content in search;
   - returns only normalized search snippets marked
     `source_open_state=not_opened`;
   - rejects unsafe/private-looking source URLs and duplicate canonical URLs;
   - records provider request ID and credits only when safely typed;
   - returns only a SHA-256 query fingerprint, not the raw query.

2. `open_public_sources`
   - accepts at most five safe public HTTP(S) domain URLs;
   - rejects credentials in URLs, localhost/private IP literals, private suffixes,
     unusual ports and malformed/control-character URLs before provider transport;
   - calls Tavily Extract only, never a local arbitrary-URL fetch;
   - distinguishes opened, failed, missing-result and transport-failed source states;
   - bounds extracted content;
   - marks all extracted text untrusted and explicitly non-authoritative;
   - labels query-reranked content `query_reranked_chunks`, and non-reranked
     extraction `bounded_page_extraction`;
   - always sets `full_document_reviewed=false`.

3. `investigate_public`
   - searches, selects only returned safe URLs, opens the top bounded candidates,
     then joins discovery metadata to extraction state;
   - no-search coverage, all-open-failed, partial-open and all-opened states remain
     different;
   - never calls a fallback provider/account.

The existing lifecycle, identity, model router, user memory, source stores, cache,
retry system, signal engines and trading authority are unchanged.

## Real machine consumer

`scripts/probe_public_research.py` is an operator qualification consumer. It
prints a machine-readable investigation receipt and exits fail-closed when no service
key is configured. It stores nothing and does no model synthesis.

## Security / failure semantics

- Tavily API requests disable HTTP redirects at the service transport.
- Provider error text, raw response bodies, service keys and raw public queries are
  never surfaced in normalized error receipts.
- Search results can discover a URL but cannot claim the source was opened.
- Extract HTTP success with per-URL failures remains partial/unavailable as appropriate.
- A provider-injected URL not requested by the caller is ignored.
- Retrieved content is always `untrusted_content=true` and
  `source_instructions_authoritative=false`.
- Empty search is explicitly a coverage gap, not proof of absence.
- Provider-estimated publication date is labeled as such and remains subject to
  source-level event/publication/correction checks.
- Search provider scores outside [0,1] are not promoted as evidence strength.
- Identical canonical URLs are deduplicated before evidence selection.

### Closed public request and explicit adapter

The core owns exactly these fields: issuer, ticker, listing, evidence_need,
start_date, end_date, information_cutoff and source_preference. Both a mapping and
a directly constructed frozen PublicEvidenceRequest are validated at every public
entry path. Raw strings, unknown/private/free-form fields, malformed types,
non-enumerated needs/preferences and windows outside start <= end <= cutoff fail
before adapter invocation. Identity lengths and the generated400-character query
bound refuse excess instead of truncating listing, cutoff or source preference.

The ten evidence needs implement the first-company slice from architecture blob
6ecc355d97b13dbf4f3a17251fc8d1eaf4cde120. Source preference is explicit:
primary_first, independent_first or balanced. Query construction retains issuer,
ticker, listing, need, dates, cutoff and the selected preference. It does not accept
caller query text. This validates structure only: identity truth, source-time
admissibility and semantic privacy/minimization remain unverified. The existing
public_minimal / caller_attested_unverified receipt and scope refusal remain.

public_research.py has no vendor credential, endpoint, vendor option enum or
default network client. The injected adapter has search and open_sources methods;
the core requires explicit completed/action/executed envelopes and constructs its
own receipts. A completed open/find action, truthy string or integer, snippet,
prose or URL cannot satisfy a new search. Core normalization independently caps
rows, snippets and content even for another backend. Requested-source membership,
canonical URL identity, missing/failed/partial states and conservative extraction
provenance remain enforced. full_document_reviewed always stays false. The schema
identifiers remain v1 because the existing receipts are preserved additively;
the public function input contract deliberately changes from raw query/vendor
options to a structured request plus an explicit adapter.

Only public_search_tavily.py owns TAVILY_API_KEY, the fixed Search/Extract endpoints,

fixed service POST or evidence URLs carrying ordinary public queries.

### Transport and URL repair

The default adapter requests stream=True with redirects disabled. It counts
decoded chunks before appending excess bytes or calling json.loads:1MiB for Search,
2MiB for Extract,16KiB requested chunks. Content-Length is not trusted; no whole-body
Response.content or Response.json path is used. A finally block attempts response
close on every returned-response path, with opaque cleanup failures. Invalid JSON,
non-object JSON, nonfinite JSON constants, HTTP errors, oversized responses and
read failures use typed opaque errors. Neither provider error body nor query/key/
exception text enters normalized errors. Existing30/35-second requests timeouts
remain; these are not advertised as a total wall-clock deadline.

Extract successes and failures each have an independent64-row scan. The core also
caps its own scans. Extra provider URLs cannot enter evidence; meaningful query
strings remain part of requested URL identity. Huge/nonfinite score or credit
metadata is unavailable rather than raising conversion errors.

Evidence URLs must be HTTPS, credential-free and lexically public with conventional
port443. Literal/obfuscated IP hosts, local/internal suffixes, malformed hostnames
and unsafe URLs are refused. A bounded query-name check decodes case/percent
variants and rejects high-confidence access/OAuth/token/signature/credential/
security-token names before discovery receipts or Extract payloads. Ordinary q=1
survives. A signed URL is refused as a whole; it is never silently stripped and
relayed as a supposedly equivalent source. These lexical checks do not prove DNS
destination safety. The selected remote extractor retains its network boundary;
the later governed direct opener is a separately unbuilt/unqualified capability.
