## 2. Concrete findings and minimal repair seams

### G1 — High: unreadable prior graph/PIT history can reach replacement writes

The graph store's non-strict `_read` converts an existing unreadable Parquet into an empty frame. `append_rows` calls that non-strict reader and then atomically replaces the destination using only the new rows. The graph orchestrator also reads stored edges without `strict=True`. Its strict THS-input guard does not protect every destination ledger. [Graph read fallback](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/theme_graph/store.py#L211-L230), [append and replace](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/theme_graph/store.py#L358-L379), [orchestrator entry](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/scripts/build_theme_graph.py#L104-L123).

The incumbent PIT writer has the same loss path: `_append_rows` calls forgiving `read_history`, then writes the resulting combined frame directly to the target. [PIT read](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/basket_membership_pit.py#L336-L356), [PIT append](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/basket_membership_pit.py#L465-L489).

**Reproduction:** with a pre-existing file and an injected decode failure, each writer invoked its replacement write with one new row and returned `rows_added=1`. The graph strict reader refused the same injected failure. This proves the control-flow hazard; no production corruption is alleged.

**Minimal repair:** within the existing store owners, distinguish first creation from unreadable existing state before any append. Strictly validate the old ledger and required schema when the file exists. Reuse owner atomic-write discipline for PIT, and ensure destination preflight happens before a multi-artifact graph publication starts. Do not create a replacement history service. Test that nodes/edges/evidence/lifecycle/capability/identity corruption refuses publication without overwriting any prior bytes or advancing `_meta`.

### G2 — High: complete-empty basket observations disappear before graph interval construction

The incumbent flattens only member rows. An observed empty basket has no row representation. Graph `ths_membership_intervals` builds each basket's collection dates only from dates containing at least one member of that basket. This correctly avoids treating a staggered collection gap as a deletion, but makes a fully emptied basket indistinguishable from an uncollected basket. [Owner flattening](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/basket_membership_pit.py#L302-L322), [graph date set](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/theme_graph/local_sources.py#L343-L402).

**Reproduction:** two complete owner-shaped documents: day 1 has A→A.SZ and B→B.SZ; day 2 retains basket A with `members=[]` and B→B.SZ. `members_asof(A, day2)` returns `members=[]`, `pit=True`; graph intervals retain A.SZ with `valid_to=null`. The disagreement is between existing owner and graph semantics on the same source data.

**Minimal repair:** extend the incumbent membership owner's collection receipt to identify scope, completeness, observed-empty state and collection/knowledge time. Graph must consume this receipt. A certified full snapshot/explicit empty collection closes the prior interval at the observation; a partial/uncollected basket remains a gap. Never change this to blanket global absence-closes-all, which would regress the existing staggered-collection protection. Require empty basket, deleted basket, missing source, partial collection, true reappearance and full-vendor shutdown cases.

### G3 — High: graph THS intervals ignore an explicit removal already effective at the snapshot

The owner preserves `added`/`removed` and `members_asof` uses them to filter active members. `ths_membership_intervals` uses row presence and never reads either field. A retained historical row whose removal predates the snapshot can therefore become a new active graph interval at that snapshot. [Owner source dates](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/basket_membership_pit.py#L616-L627), [graph construction](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/theme_graph/local_sources.py#L364-L402).

**Reproduction:** October 3 snapshot retains A.SZ with `removed=2026-10-02`, plus active B.SZ. The owner returns B.SZ only; graph emits open intervals for both A.SZ and B.SZ, opening A.SZ on October 3.

**Minimal repair:** reconcile active-at-observation semantics through the incumbent owner adapter. Do not backdate a graph interval to an unverified source `added` seed. At minimum, a source record already inactive at observation cannot be promoted to a fresh active interval. Source removal correction, future-added records, removal before first graph observation, and reappearance need separate cases with valid versus knowledge clocks preserved.

### G4 — Medium: current-rights claims exceed actual in-process refresh behavior; internal eligibility is still unbuilt

Rights are read from the incumbent registry, but `_load` is cached solely by path. Editing a reviewed family's rights in that same process does not invalidate the cached verdict. [Cache and lookup](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/theme_graph/rights.py#L90-L133).

**Reproduction:** `direct_display_ok` returns allowed; editing the same file to `internal_only` still returns allowed; clearing the cache makes it refuse. This concerns long-lived readers and explicit revocation tests, not an observed production rights event. A new one-shot process naturally reloads the registry.

Separately, `licensing_for_family` returns `(True, False, False)` for an unknown family and always makes internal computation true. The current registry does not implement separate internal computation entitlement. Do not describe the existing plane as fully separating source access, internal use, derived display and redistribution. Public unknown-family refusal is real; internal-use eligibility remains a D2E contract gap. [Licensing tuple](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/engine/theme_graph/rights.py#L168-L187). Current Finviz and THS classes are both unresolved; grandfathering names exact old owner surfaces and does not license new GMI surfaces. [Registry](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/config/theme_sources.yml#L1-L67).

**Minimal repair:** version/digest the incumbent registry in each build/read context and implement explicit revocation refresh for long-lived processes. Extend the same registry with separately reviewed capabilities and eligibility reasons; a reviewed rights state and measurement quality must remain different dimensions. Inheritance through derived/canonical projections must carry source-family provenance; do not infer permission merely from a canonical endpoint.

No basket has a `tickers` field. Current ThemeState has `narrative=null` for all 18 themes, and its data/site copies are byte-identical. [ThemeState artifact](https://github.com/mastermindx-market-intelligence/macro/blob/bebcb24db8707f93c3acca470590fead13e78dbd/data/neuralweb/theme_state.json#L1-L45).

No future source may become eligible because the build timestamp is fresh. Retain a stale-but-visible context only with explicit status and an authority cap, rather than requiring all display context to disappear.
