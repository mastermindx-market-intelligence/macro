**Blocking Finding 1 — Settled closing comparison is destroyed by the next successful settled build**
- Locus: `scripts/build_basket_pulse.py:1319` (settled lane), `scripts/build_basket_pulse.py:769` (equal-timestamp branch), `scripts/build_basket_pulse.py:860` (`_save_lastgood`).
- Mechanism: post-close tick 1 measures RTH baseline → official settle, emits `status="observed"`, and persists the *settled* points as the new `observation_baseline`. Tick 2 reloads that settled baseline; SPY's official settle stamp is unchanged and no member correction is detected, so `bench["ts"] == prior_bench["ts"]` returns `benchmark_nonadvancing` and overwrites the observed rows in both the returned payload and the sidecar. For the rest of the evening the closing read is undeliverable, although the measurement is unchanged, same-session, and still inside the consumer's 45-minute age gate.
- Internal inconsistency: if `_settled_build` returns `None` at tick 2, control falls to the sidecar-serve path (`scripts/build_basket_pulse.py:1336`), which pops only `observation_baseline` and re-emits tick 1's payload *with* the observed `intraday_comparison` rows. Identical market state therefore renders the closing interval or not, depending on an unrelated recompute flag.
- Minimal counterexample: US, regular 16:00 ET close. Last RTH build 15:59:30 stores SPY `ts=15:59:30`. Build A at 16:02:00 sees the official settle (`basis="regular"`, `ts=16:00:00`, never revised) → `observed`, 30 s interval, baseline := settled points. Build B at 16:04:00, same settle `ts` → `corrected` is `False` → every row is `benchmark_nonadvancing`; `_intraday_comparison_block` requires `status=="observed"` (`engine/neuralweb/market_packet.py:700`) → returns `None` → the LEADERS intraday half vanishes at 16:04 with age 4 min ≤ `QUOTES_STALE_MIN`.
- Minimal remedy: in the settled lane, when the benchmark stamp is unchanged and no correction is detected, re-attach the prior sidecar's already-observed comparison rows (still returning `prior` as baseline) and let the consumer's age/session gate remain the only expiry. Equivalent alternative: do not overwrite the RTH baseline with settled points on the tick that produced the closing interval, so each post tick re-measures the same explicitly windowed interval — corrections still reset via `baseline_corrected`, and `session_date` still resets the next day.

**Blocking Finding 2 — `observation_baseline=None` means "delete the retained baseline"**
- Locus: `scripts/build_basket_pulse.py:867` (`if observation_baseline is not None`) with callers at `scripts/build_basket_pulse.py:1528` and `scripts/build_basket_pulse.py:1331`; `None` is returned by the early exits at `scripts/build_basket_pulse.py:716`, `:718`, `:726`.
- Mechanism: any build in which `_intraday_comparisons` early-returns writes the payload with no baseline key, erasing the previously persisted reference that the settled lane needs. This is a defensive-path data loss, not a hypothetical malformed-input case: existing single-writer ownership already excludes untrusted mutation.
- Counterexample A (fully reachable from the shown code): `build(now=<naive datetime>)` at 15:59 ET hits `scripts/build_basket_pulse.py:717` → `("invalid_evaluation_clock", None)` → sidecar written without `observation_baseline` → the 16:02 settled build finds `prior` missing → `baseline_missing` → no closing comparison for that session, permanently.
- Counterexample B (conditional, see limitations): if a US build can be `live`/`delayed` while `session == "post"` (quotes still fresh just after the bell), `scripts/build_basket_pulse.py:715` returns `("unsupported_session", None)` and wipes the RTH baseline before the settled lane ever runs.
- Minimal remedy: preserve the stored baseline when the newly computed one is `None` (read-modify-write that single key, or pass an explicit "no change" sentinel distinct from "no baseline").

**Non-Blocking Observations**

- The consumer's `3e-6` relative-vs-absolute/benchmark tolerance (`engine/neuralweb/market_packet.py:758`) is adequate for every plausible regime (worst realistic drift ≈1.8e-6 given the ±40% band) and only rejects legitimate rows in the pathological `|absolute|≈|benchmark|≈40%` corner.
- `_intraday_comparison_block` drops a non-conforming comparison with no `gaps` entry, unlike the day-move sanity drop at `engine/neuralweb/market_packet.py:825`; a producer/consumer schema or tolerance drift would be invisible in diagnostics.

- A basket dropped from up/down for exceeding the ±40% day-move band can still appear in the intraday half. Different measurements with explicit windows, so not misleading, but asymmetric.
- `_signed` renders legs at 2 decimals while `relative` is geometric, so a near-zero relative prints `0%` beside non-zero legs. This is the documented honest-zero policy and never flips a sign; not blocking.
- `engine/sp500_heatmap.py:191` is clean: exact-timestamp endpoint matching, tz-aware/unique/`hasnans`/length guards, no ffill or nearest-row, and a bad latest close skips the ticker instead of rewinding — behavior matches its disclaimers, including the explicit refusal to treat a row as a duration.
