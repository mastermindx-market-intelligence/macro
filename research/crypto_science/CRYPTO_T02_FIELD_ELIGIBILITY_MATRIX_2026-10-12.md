Decision clock used by the injection tests: `AS_OF = 2026-10-11` (`tests/test_crypto_input_eligibility.py`). The projections have no as-of argument. This note reuses R3 (`research/CRYPTO_SCIENCE_R3_INPUT_COHORT_RESULTS_2026-09-28.md` at `fd8095012e91`) and R10 (`research/CRYPTO_SCIENCE_R10_SOURCE_QUALIFICATION_RESULTS_2026-09-29.md` at the same commit). Page trace, not a template census. Crypto calls `build_market_state` (`scripts/build_crypto.py:24`, `:469`) and puts that dict on the page (`:561-591`). It also calls `build_asset_states` (`:488`, ETH/SOL) and `build_btc_options` (`:489`). ## Clock law on the read path

Collectors store a provider bucket timestamp as the parquet index. Examples: CoinMetrics `time` normalized (`collectors/coinmetrics.py:61`); BGeometrics `d` sliced to 10 characters, `unixTs` dropped (`collectors/bgeo.py:119-123`); OKX funding `fundingTime` normalized to midnight (`collectors/okx.py:120-121`); Coinbase candle epoch (`collectors/coinbase.py:92-105`); Farside table date (`collectors/farside.py:56-58`); COT `report_date_as_yyyy_mm_dd` (`collectors/cot.py:88`). CoinGecko global and mempool fees use `datetime.now(timezone.utc).date()` as the index (`collectors/crypto_misc.py:59`, `:303`).

`btc_inputs._col` (`engine/btc_inputs.py:24-31`) and `crypto_market_state._series` (`engine/crypto_market_state.py:19-28`) keep that index, drop duplicate labels with `keep="last"`, and do not record an available time or a received time. `_series` also `dropna`s, so a trailing NaN disappears and the previous number becomes latest.

Receipts exist only for `okx_funding`, `okx_taker`, and `bgeo_funding`. `received_at`, `first_seen`, and `fetched_at` are the same local stamp. `provider_first_published_at`, `unit`, `timestamp_role`, and `finality` are forced null (`collectors/_crypto_observations.py:99-104`, `:121-122`). The page projections never read those captures. A `received_at` column on the frame is ignored (`test_col_delayed_receipt_is_not_available`, `test_market_state_delayed_receipt_is_not_available`).

Upsert default is `new.combine_first(old)` (`lib/store.py:115`): the new non-null wins, the prior value is not kept. The projections then keep the last duplicate index.

Weekend and holiday. Nothing in `engine/btc_inputs.py` or `engine/crypto_market_state.py` names a publication calendar (both files read in full). A Saturday/Sunday hole in `fred/DGS10` is unlabeled (`test_fred_weekend_gap_is_labeled_nonpublication`, row `DGS10`, `xfail(strict)`). The same unlabeled hole is what a holiday or a failed fetch looks like. Crypto spot and perp series are collected every day. FRED, TGA, Farside ETF flow, and COT are not. Downstream, `macro_overlay` reindexes macro series onto the BTC calendar and `ffill(limit=7)` (`engine/btc_signals.py:1655-1663`), so a Friday print is written onto the next BTC days. That ffill is outside the injection surface.

## Shared constraint S

Every parquet field below is **CONSTRAINED(S)** for observed display and for output publication when a page reader exists. Row id `S`. These pins are `xfail(strict)`: `test_col_future_row_is_not_available`, `test_funding_future_row_is_not_available`, `test_load_price_future_close_is_not_available`, `test_intraday_vol_future_bar_is_not_available`, `test_series_future_row_is_not_available`, `test_market_state_future_cap_is_not_available`, `test_col_revision_a_to_b_is_visible`, `test_funding_revision_a_to_b_is_visible`, `test_market_state_revision_a_to_b_is_visible`, `test_col_delayed_receipt_is_not_available`, `test_market_state_delayed_receipt_is_not_available`. Remove a marker only together with the engine fix and the matrix row update.

- a future index is returned as available (`test_col_future_row_is_not_available`, `test_funding_future_row_is_not_available`, `test_load_price_future_close_is_not_available`, `test_intraday_vol_future_bar_is_not_available`, `test_series_future_row_is_not_available`, `test_market_state_future_cap_is_not_available`) — `xfail(strict)`
- an A→B rewrite on one timestamp keeps only B (`test_col_revision_a_to_b_is_visible`, `test_funding_revision_a_to_b_is_visible`, `test_market_state_revision_a_to_b_is_visible`) — `xfail(strict)`
- a receipt after `AS_OF` is still available (`test_col_delayed_receipt_is_not_available`, `test_market_state_delayed_receipt_is_not_available`) — `xfail(strict)`

Historical reconstruction and prospective research are **UNAVAILABLE** for those rows: the projection has no vintage, and R3 §2 / R10 §4 already found that a parquet timestamp is not a publication time. This lane did not redo that census.

Absence is not zero on these readers. Missing or empty frames become `None` or an empty series (`test_col_absent_frame_is_none_not_zero`, `test_col_empty_frame_is_none_not_zero`, `test_series_absent_is_empty_not_zero`, `test_market_state_absent_inputs_are_none_not_zero`). A NaN cell stays NaN in `_col` (`test_col_nan_cell_is_not_replaced_with_zero`). An observed 0 stays 0 (`test_col_observed_zero_stays_zero`, `test_funding_observed_zero_stays_zero`, `test_heat_funding_observed_zero_stays_balanced`). Mark price is not a funding rate (`test_funding_missing_field_is_none_not_mark_price`). A missing close is dropped (`test_load_price_missing_close_is_dropped_not_zeroed`). No price frame raises (`test_load_price_absent_raises_instead_of_a_zero_frame`). A partial hourly bar stays NaN (`test_intraday_vol_partial_bar_is_not_zero`). `load_hourly` of a missing file is `None` (`test_hourly_absent_is_none`, `test_intraday_vol_absent_hourly_is_none`).

CONSTRAINED rows besides S. Each pin is `xfail(strict)`, including `test_market_state_stale_zero_is_not_a_current_zero`:

- stale 0 is published as a live 0 when another series is fresh (`test_market_state_stale_zero_is_not_a_current_zero` row `fear_greed`, `test_heat_funding_stale_zero_is_not_a_current_zero` row `funding_rate_fundingRate`) — `xfail(strict)`
- the latest NaN fear cell is replaced by the previous print (`test_market_state_partial_latest_cell_stays_unavailable` row `fear_greed`) — `xfail(strict)`
- absent BTC volume is worded `Normal` (`test_market_state_absent_volume_state_is_not_normal` row `volume`; `engine/crypto_market_state.py:203-207`) — `xfail(strict)`. The number stays `None`.
- SSR forward-fills a missing stablecoin day (`test_ssr_missing_stablecoin_day_stays_missing` row `ssr`; `engine/btc_inputs.py:165-167`) — `xfail(strict)`
- supply-in-profit fraction forward-fills a missing supply day (`test_supply_fraction_missing_supply_day_stays_missing` row `supply_in_profit_pct`; `engine/btc_inputs.py:168-172`) — `xfail(strict)`
- class cap carries dominance across a gap of up to 3 days (`test_total_cap_gap_is_not_filled` row `class total cap`; `engine/crypto_market_state.py:59-60`) — `xfail(strict)`
- ETF "5d" is the sum of the last 5 stored rows, here 50 instead of the one print inside the calendar window (`test_etf_partial_window_is_not_a_five_day_sum` row `total`; `engine/crypto_market_state.py:193-195`) — `xfail(strict)`

Run: `python -m pytest tests/test_crypto_input_eligibility.py -q -p no:cacheprovider -rxX` → `15 passed, 20 xfailed` (0 failed, 0 xpassed). The same command with `--runxfail` → `20 failed, 15 passed`. The 20 `xfail(strict)` tests are the contract above. Assertions were not weakened.

## Admitted path

The one measured path admitted for a narrow purpose today is OKX `BTC-USDT-SWAP` funding as returned by `funding_asof` on captures already stored for `okx_funding` (`collectors/_crypto_observations.py:162-213`).

Admitted use: observed display, and a replay of what this process had received by an explicit `as_of`, of `predicted_rate` and `settled_rate` when `status` is `observed`. `settled_rate` is cleared when the settlement timestamp is after the receipt (`:209`). A later capture with a null settled rate does not reuse the older settled rate (implementation `:203-212`; contract encoded in `tests/test_crypto_collectors.py:test_r11_later_missing_actual_is_not_repaired_with_an_old_value`, read this session, not re-run). `interval_hours` and `annualized_settled_pct` stay null (`:206-207`). A real zero settled rate is kept (`_rate`, `:174-178`). Conflicting payloads with the same receipt time become `conflicting_capture` with null rates (`:211-212`).
