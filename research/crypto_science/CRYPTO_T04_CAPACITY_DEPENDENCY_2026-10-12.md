## 3. Operational envelope (proposal only)

No numbers below are approved limits. They describe how a later owner-supplied bound has to behave. They are not an implementation.

Payload variety. Three `source_id`s are registered, with different allowlists (`FUNDING_FIELDS`, taker triplets, `BGEO_FIELDS`). A caught-up okx fetch records up to three receipts whose params differ (`instId`/`limit`/`after`, taker `period` `1D` vs `1H`). Bgeo funding is a separate provider file. The R12 sample repeated one 480-triplet body, which is why 20868848 logical bytes became a 100527-byte file. A page of 100 distinct funding rows is already 19121 payload bytes in the local construction, against 17301 for the repeated 480-triplet probe body. A ceiling copied from the compressed repeated file understates a store of distinct pages. Bounds are per provider file, and the decoded bound is on canonical bytes after `checked`, not on `st_size`.

Duplicate work. `already_present` still reads the parquet and runs `checked` on every stored row (`_crypto_observations.py:139-149`) before it returns. The duplicate timings in the baseline (0.572471s at 1000 rows) are that read, not a no-op. An envelope that budgets only the rewrite misses the steady path, which is mostly duplicates once each occurrence has been stored. The duplicate must not write and must not move `first_seen`.

Interruption. `LOCK_NB` returns `unavailable` with the file untouched and does not retry. `atomic_write` unlinks the tmp sibling on failure and `os.replace`s only after `to_parquet` returns. An unreadable store returns `None` and the append is aborted. A bound check belongs under that same lock, before the full decode, as `PLAN:25` requires. A killed writer leaves the previous parquet and every stored `first_seen` as they were.

Reached bound. Return the receipt `status` that the code already spells, `unavailable`, with a distinct `error_type`, and emit the existing log line `Crypto source evidence unavailable`. Do not delete rows, do not rotate the parquet, do not reset `first_seen`, and do not substitute an empty history. `load_asof` on a store past its read envelope raises; it does not return zero rows. `fetch_result_status` may keep returning `stale`, because `run_adapter` rejects any declared status outside `{ok, stale, blocked}` (`base.py:681-682`). Putting the words `capture unavailable` into the declared fetch status would raise. The explicit unavailable signal is the receipt dict plus that log line. Independent numeric frames stay publishable; the adapter test `test_r11_capture_failure_is_visible_without_hiding_independent_values` already requires the funding frame to remain while status is `stale`.

Until the owner writes the four bounds, the coded behavior stands: keep-first with no age, refuse only `MAX_ROWS` / `MAX_JSON_BYTES` / schema / lock / unreadable-store failures, and surface those as `unavailable` receipts. This note does not add a default cap.
