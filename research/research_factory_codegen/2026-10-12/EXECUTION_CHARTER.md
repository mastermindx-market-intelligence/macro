## A00 decision: prerequisite source is permitted; execution stays closed

The assigned engineering scope includes trusted source that validates inert JSON
and strengthens RF-16 refusal. It does not include running or generating research
candidate code before boundary acceptance. No passing shape check, configuration
boolean, digest, model title or caller-authored receipt constitutes admission.

The prerequisite wave plans closed manifest/input/output contracts and a
dormant completeness check. The first reviewed change is a shared metadata
refusal at Factory validation, canonical writes and routing. Its fixtures
contain synthetic metadata and numbers only. It does
not add `code_candidate` to the Factory enum, register a candidate, spend a trial,
read market data or labels, import source, execute a primitive, evaluate a result,
write a Vault record, enable a workflow or publish a product surface.

Reserved metadata is `code_candidate`, `research_codegen`, the prefixes
`research_codegen.` and `rf-codegen-`, and the keys `codegen_manifest`,
`codegen_manifest_ref`, `codegen_contract`, `codegen_protocol_ref`. The existing
router must refuse these before its broad source/domain/type matches. This is a
metadata fence, not a detector of all disguised code or an OS isolation boundary.

The contracts' successful structural validation is only source-level evidence.
Their admission result must retain `generation_enabled=false`,
`execution_enabled=false`, and `authority_granted=false`. Runtime activation
requires a separately reviewed integration with the existing trusted owners.

## Scientific freeze and honest unresolved fields

The intended objective is fixed-cohort drawdown/MAE entry ordering using existing
lawful price research inputs, never candidate-selected metrics. Initial search is
at most four explicit variants across two mechanisms, subject to the incumbent
budget and RF-15's two refinement cycles. This is a design ceiling, not a runtime
allowance or permission to reset trial history.

The first actual runtime proof must use one known-answer synthetic primitive and
one deliberately future-dependent control, count both, and traverse execution,
evaluation, challenge, adjudication and the existing operator view. No such run
has occurred in this source wave.

The assigned root has selected the bounded source-level design in
[PROTOCOL_DESIGN_V1.md](PROTOCOL_DESIGN_V1.md) and its
[machine-readable companion](PROTOCOL_DESIGN_V1.json): nine fixed sector ETF
exposures, the incumbent bare-washout cohort and numerical ruler, a fixed
26-session formation schedule, 25-session MAE and 21-session exit, matched unit
reference exposure, and at most four counted variants including the synthetic
pilot controls. These are predeclared research choices, not measured claims.
The design fixes a 50-basis-point minimum worthwhile effect, familywise testing
envelope, calendar blocks, sample-planning rule and one selection-feedback release.
Source exclusions are common and fixed before outputs; a candidate failure on
a qualified opportunity-bearing formation refuses the whole candidate result.

Actual lawful data/version/vintage receipts, the incumbent evaluator feature-input
seam, original trial-family history, required sample size and independent methods
acceptance remain unqualified. The generic promotion helper intentionally checks supplied inputs;
the new lane must establish its mandatory proof set before calling it. The
existing Oracle reversion adapter projects registry results and does not yet
accept an independently validated feature array. Those are remaining engineering
and methods obligations, not permission to invent an evaluator or declare A00,
T01, L01, C01 or E01 fully complete.

No historical batch may begin with an unresolved freeze field. Prospective
evidence requires actual later observations and matured labels; source tests,
backfilled timestamps and a configured schedule cannot satisfy it.

## Delivery and rollback

Each source wave receives relevant regression checks and independent review,
then follows the repository's CI/merge chain. Source merge, installed files,
selected configuration, accepted execution and product acceptance are separate.
The initial source wave requires no runtime installation or unrelated service
restart. A later release must prove the authenticated operator path and retain
failed/null/refused candidates as visibly as survivors.

Rollback must disable new admissions while preserving all existing attempts,
trials, Vault consumption and outstanding children on their original carriers.
This charter creates no background process and claims no prospective completion.
