# Host identity decoder: source contract and physical limit

The new `scripts/research_codegen_qualification/runtime/host_identity.py` is a pure decoder for a future bounded observer. It reads no files, runs no commands, follows no supplied path and grants no execution. It is excluded from the current fixed-canary capsule. Its two inputs are distinct JSON wire formats; caller identity, capture provenance and installed runtime version still need independent binding.

The contract was checked against immutable gVisor commit `97e8e896904cb364319cd9758241d3f0bd27a6f4`, resolving release-20261005.0. Five downloaded source files matched that commit byte for byte. Original source manifest and verification are in `containment-acceptance/workloads/host-source-primary-v1/` under the evidence root.

- OCI state returns the sandbox PID and ordinary OCI fields. Internal Container metadata separately holds `goferPid`, `sandbox.id`, `sandbox.pid` and `sandbox.cgroup`. It cannot be substituted for OCI state. The single-container decoder requires the same full container/sandbox identity, matching live declared statuses and matching typed positive sandbox PIDs. A zero gofer value is represented as absent declaration, never proof of cleanup. [Container source](https://github.com/google/gvisor/blob/97e8e896904cb364319cd9758241d3f0bd27a6f4/runsc/container/container.go#L685), [sandbox PID encoding](https://github.com/google/gvisor/blob/97e8e896904cb364319cd9758241d3f0bd27a6f4/runsc/sandbox/sandbox.go#L132).
- The implemented state filename is `<CID>_sandbox:<SandboxID>.state`. The older `meta.json` comment does not match `buildPath`. The decoder returns only the basename for the fixed single-container case, without choosing a runtime root, globbing or probing a partial ID. [StateFile implementation](https://github.com/google/gvisor/blob/97e8e896904cb364319cd9758241d3f0bd27a6f4/runsc/container/state_file.go#L415).
- `runsc state` has no command-specific `--format=json` option. It serializes OCI state, not internal metadata. Loading state also checks running state by default; this decoder does not call it or claim it is a side-effect-free privileged read. [State command](https://github.com/google/gvisor/blob/97e8e896904cb364319cd9758241d3f0bd27a6f4/runsc/cmd/state.go#L53), [default load checks](https://github.com/google/gvisor/blob/97e8e896904cb364319cd9758241d3f0bd27a6f4/runsc/container/state_file.go#L109).
- Cgroup JSON uses `cgroupv1`, `cgroupv2`, `cgroupsystemd` or `cgroupunknown`. The decoder retains only the kind and descriptor digest. It never resolves descriptor-selected paths or substitutes compatibility cgroup limits for sandbox enforcement. [Cgroup serialization](https://github.com/google/gvisor/blob/97e8e896904cb364319cd9758241d3f0bd27a6f4/runsc/cgroup/cgroup.go#L508), [compatibility limit](https://github.com/google/gvisor/blob/97e8e896904cb364319cd9758241d3f0bd27a6f4/runsc/container/container.go#L121).

The earlier Fabric source audit remains unaccepted because it conflated these records and proposed unsupported flags, filenames and cgroup shapes. Its valid narrow PID mapping is retained; the corrected source contract is a separate root finding. No complete helper census, Docker-to-OCI PID adapter proof, current kernel/PID-start identity, executable/cgroup enforcement or cleanup follows from two declared PIDs. All decoder outputs explicitly keep host observation, complete helper census and cleanup proof false. Actual runtime-root selection, concurrent state-file handling and bounded kernel observations require the later qualified caller and recovered canary evidence.
