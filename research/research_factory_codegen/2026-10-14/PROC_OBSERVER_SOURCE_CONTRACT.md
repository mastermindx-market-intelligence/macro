# One-process observation contract

`scripts/research_codegen_qualification/runtime/proc_observer.py` is dormant source preparation for the independent host observations needed by containment qualification. It has no import-time I/O or CLI. An explicit caller supplies one exact authorized PID; invalid values refuse before I/O. The current fixed-canary capsule remains unchanged and does not include this helper.

The helper opens a Linux pidfd and holds the exact `/proc/PID` directory while reading only `stat`, `cgroup`, then `stat` again. Child lookups use that held descriptor, fixed names, no-follow and nonblocking flags. Each read is limited to 4097 bytes plus a one-byte EOF check, with a 4096-byte accepted maximum. It polls the same pidfd without waiting before and after the reads. Any exit/error event, malformed record, changed start ticks or permission failure refuses. Every acquired descriptor receives one close attempt; a close error refuses after the other descriptors are closed, without retrying a possibly reused FD.

Linux documents that an open proc descriptor does not prevent PID reuse, but a descriptor referring to a dead process does not operate on its replacement. A pidfd can be polled for process termination. These are separate observations; equal PID/start ticks alone are not treated as unique identity. See the [kernel proc documentation](https://docs.kernel.org/filesystems/proc.html) and [pidfd_open manual](https://man7.org/linux/man-pages/man2/pidfd_open.2.html).

Field 22 of `stat` gives start ticks since boot. Field 2 is opaque and may contain parentheses, spaces or newlines, so splitting the whole record on whitespace would be incorrect. The bounded parser finds the final closing parenthesis and validates the numeric suffix. Raw process names never enter the result. See [proc_pid_stat](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html).

The narrow cgroup profile accepts one unified `0::/path` record and returns only the path digest and whether the path is root. It refuses legacy/hybrid records, deleted or parent-relative paths, controls and ambiguous components. It never resolves that path or reads cgroup files. Kernel cgroup paths depend on the observer's namespace, and root membership says nothing about exclusive custody or enforcement. See the [cgroup v2 documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html).

This observation does not prove that an earlier runsc-declared PID still denotes the same process before acquisition, that the proc mount/observer namespace is trustworthy, that all helpers have been found, or that resource limits and cleanup hold. It does not provide an atomic cgroup snapshot or guarantee future liveness. Fixed byte/syscall counts do not guarantee wall time if the kernel blocks; a qualified outer supervisor and deadline remain required. Container identity, helper census, resource enforcement and cleanup flags stay false.
