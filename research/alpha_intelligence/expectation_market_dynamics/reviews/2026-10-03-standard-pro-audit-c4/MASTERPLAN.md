## 1. Product promise and finish line

Build an institutional-quality, security-level expectations workspace that answers, in a few seconds: what explicitly observed forecasts changed; which operating assumptions are compatible with the selected price under a stated model; what price and options have actually done or priced; where comparable channels disagree; which interpretations are uncertain; and what next observation would distinguish the rival explanations.

The user and machine must consume the **same canonical, versioned derived outputs**. Human-readable explanations may summarize those outputs but may not create missing numbers, probabilities, identities, causal claims or authority. All evidence remains with its current owner. A K3E projection is not another analyst-history store, financial truth plane, event system, identity plane, residual engine, options store, evaluation framework, lifecycle or trading system.

### Required core completion

The core program is complete only when all of the following are evidenced on the accepted release:

1. Existing SRC-A1 acceptance is reconciled and published through its incumbent carrier, with qualified source versions and preserved historical defects.
2. A bounded, economically and rights-qualified cohort supports deterministic expectation surfaces and two-cutoff replay; failures, stale inputs and unsupported periods remain visible.
3. An owner-composed market-response surface and an options-context surface have real qualified positive cases and honest missing-leg behavior.
4. At least one owner-approved forward valuation family supports conditional inversion, a two-dimensional contour and an auditable feasible envelope without false identification or probabilities.
5. A descriptive coupling view compares like-for-like objects and refuses unsupported timing/causality; a calibrated phase classifier is not required to fake completeness.
6. An existing security-level product surface delivers the workflow through the actual authenticated Terminal/Macro transport, with evidence inspection, scenario controls, replay, responsive/accessibility proof and canonical save/context handoff.
7. The existing evaluator holds a prospectively frozen experiment set and a complete disposition for every attempted hypothesis. No predictive authority is granted by UI release. Optional scientific candidates may conclude FAIL or INSUFFICIENT_DATA without falsifying the delivered descriptive product.
8. Release, rollback, monitoring, owner assignment and successor recovery are proven; the next ordinary source cycle is observed without altering cadence.

A legitimate `UNESTIMABLE` on a difficult individual case is success. An entire advertised capability that always returns unknown because its dependencies never shipped is **not** completed. Regional expansion, contributor analytics and predictive promotions retain explicit residual scope; they cannot quietly disappear into a final “done.”

## 6. Product information hierarchy

The first screen contains a compact as-of header, evidence scope and four to six component cards: explicit expectations; price response; price-required assumptions when available; options-priced uncertainty; disagreement/rival explanation; next observable. There is no overall green/red or “K3E 82” investment score.

The advanced layer exposes fiscal horizons, coverage and contributor limitations, correction lineage, model assumptions, solver diagnostics, scenario locks, residual controls and evaluation maturity. A user can distinguish OBSERVED, DERIVED, CONDITIONAL MODEL, PRICED-Q and EXPERIMENTAL at a glance. Tooltips explain these in ordinary language without claiming model certainty.

The key interaction is not endless dashboard navigation: select security → understand changed state → inspect one claim → adjust a clearly conditional assumption → compare the prior capture → save a canonical research reference → return after the next qualified observation. References can be consumed by the existing Brain, watchlist, briefing and later Prophet context. Alert delivery and portfolio state stay with their existing owners.

Accessibility/translation do not invent semantics: source prose that lacks translation is labeled; units, dates and minus signs remain legible; keyboard focus survives receipt open/close and event switches; scientific null reasons become useful user messages rather than internal code dumps.
