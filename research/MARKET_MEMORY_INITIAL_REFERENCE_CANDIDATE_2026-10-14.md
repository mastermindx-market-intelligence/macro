# G1 initial native-reference candidate preparation

The actual legacy reference directory inspected for G1 has `prospective_reference` but no native `publication` or `identity_observations`. The DataOS reader correctly refuses that incomplete snapshot. Existing DataOS work and its live carriers #8637 / #9199 retain custody; this change does not publish, enroll a subject, or change those readers.

`build_initial_reference_candidate` is a pure preparation function over supplied receipt bytes, all five artifact bytes, alias records, master records and an explicit code identity. It preserves the original prospective reference and every legacy receipt field, derives only the original existing owner-read clock, builds the native initial anchor with no attempts, and validates the complete result using the real `lib.dataos.identity.validate_reference_snapshot` with identical before/after bytes. Existing publication/history, revisioned rows, inconsistent original probes, incomplete artifacts and malformed/resource-unbounded inputs refuse.

The result is a detached frozen candidate containing canonical bytes and digests. `published=False`, `identity_admitted=False` and `records_bound_to_artifacts=False` are explicit descriptions of what this function establishes, not authorization tokens. It is neither a ReferenceSnapshot nor a ReferenceReadReceipt. Matching bytes and semantic records establishes internal consistency only: the caller still must prove the supplied records were decoded from those exact Parquet artifacts, establish authentic source provenance, hold publication authority, and obtain the actual subsequent native read receipt. This function does not provide or infer those facts.

Validation: 37 new cases and 212 existing native-owner cases pass together (249). The 37 new cases also pass with CI's Python3.12. The suite uses synthetic fixtures only and covers complete native validation, all five missing/tampered artifacts, semantic-record tamper, no file I/O, input mutation, original-context mismatch, existing-history refusal, nullable revision columns and adversarial JSON/types/bounds. The existing Market Memory CI job now explicitly runs the new suite; the manifest validates315jobs without new jobs or removed coverage.

Fabric run `mm-g1-initial-reference-candidate-20261014-01a1333c-v1` was refused before launch because eligible hosts lacked admitted artifact capacity (telemetry/disk/thermal/lane constraints). No worker ran, no effect was retried, and no acceptance was recorded for that run. The assigning parent performed this bounded preparation directly. There is no production caller or real-data candidate in this change. G1/A42 and the full28-task49-case program remain open.

A new regression demonstrates that changing supplied serialized bytes while retaining the same semantic records changes the physical seal and generation while the unproven-binding marker remains false. The remaining proposed checks belong to the authentic publisher or identity-selection consumer. Repeated calls are detached candidate preparation, not competing admitted initial publications; mint-once enforcement requires the existing owner's state. The candidate preserves legacy fields and original supplied clock/probes but does not authenticate their provenance. An empty or unresolved master can be internally sealed without admitting an identity; the native selection path still owns identity uniqueness. Adding a vendor allowlist here would create a competing DataOS rule. The original receipt hash binds supplied raw bytes, while the candidate is separately canonicalized.

Resource limits are per input, not a measured peak-memory budget: five artifacts permit up to320MiB of bytes, and two canonical record sets permit128MiB in total; parsing and validation require additional working memory. There is no production caller or endpoint in this change. Any later caller must establish its own admitted workload bound and all publication/source/read obligations. Before/after candidate validation here is build-time conformance, not evidence of an actual filesystem read interval.


## R23: byte-bound, physically decoded preparation (October 17, 2026)

The original pure `build_initial_reference_candidate` contract above remains **unchanged**: caller-supplied semantic rows cannot be trusted merely because raw artifact hashes agree. The new opt-in `build_parquet_bound_initial_candidate` is a bounded **in-memory** physical-data check over the exact supplied receipt and five Parquet byte buffers. It lazily reuses the existing Entry Radar `identity_observation_snapshot._parquet_records` implementation rather than inventing a competing Parquet reader or identity selector. All five artifacts must decode as bounded supported Parquet, and the decoded **vendor-alias and security-master** records—not separate caller-provided arrays—are passed into the existing native `build_initial_reference_candidate` and `lib.dataos.identity.validate_reference_snapshot`.

The returned frozen `ParquetBoundInitialCandidate` separates its claims:

- `alias_master_semantics_bound=True` means the two **natively semantically sealed** record sets are derived from those exact Parquet bytes.
- `all_artifacts_parseable=True` means all five physical Parquet members were parsed under the existing bounded decoder. **It does not establish independent issuer/migration semantic attestation**, so the wrapper's overall `records_bound_to_artifacts=False` remains intentionally conservative.
- `source_authenticated=False`, `published=False`, `identity_admitted=False` and `current_read_admitted=False`: none may be upgraded by a caller or historical filename. This code supplies **no** actual clock, file writes, canonical writer lock, source-provider authentication, new publication, trial enrollment, signal or trade.

The new function has no path, clock, caller-semantic-record or authority override argument. It constructs detached copies of all inputs. The old detached helper, old tests and source publication machinery are unmodified.

**TDD evidence:** ten newly parameterized cases initially failed because the new function was absent, and passed after implementation. One additional native read-path test compares a legacy receipt refusal against a successfully reopened ephemeral candidate within the same synthetic five-file directory, with the reader's actual completion clock. The combined real identity, snapshot-adapter and initial-candidate suite passed **315 cases**, zero failures/errors/skips; two warnings involved cleanup of unrelated previously protected pytest temporary directories, which this operation did not change.

Candidate receipt SHA256 `b1a81e25eb80cc34a96738dedfa9208ff9ca0369995a1add84d58bb297e8cf1f`; candidate generation ID `813e2d397bdb7b2eb524e2e57f4ef425cd6378710ec3d6bcdc966f28ebd50f31`. This candidate **is not the canonical receipt** and its hash is not a published status.

An independent temporary-directory read test using those exact five committed Parquet bytes first reproduced the native refusal on the **original legacy receipt**, then reopened the same files with the temporary candidate receipt and constructed the existing native alias table. The native `ReferenceReadReceipt` completion timestamp was measured **during that actual temporary file-read call**, not taken from file mtime or the legacy historical event dates. The temporary directory was deleted; no canonical artifact, original Git object, source-response, production data or identity publication changed. The temp reader result demonstrates format interoperability, **not** historical as-issued identity or a live installed generation.
