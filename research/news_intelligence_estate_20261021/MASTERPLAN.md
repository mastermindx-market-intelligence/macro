## Executive decision

Run this as an **owner-preserving convergence programme** under the existing Market Intelligence Institutional Buildout, with explicit dependencies on Prophet News Impact, GMI/Company Theme Exposure, MarketOntology, Earnings/K3E, Data OS/Research Vault and the existing release and runtime owners.

The estate already has substantial capability: a shared ticker-news store and authenticated streaming API; source and revision provenance; editorial curation; deterministic event classification; event and outcome ledgers; a separate Macro Release Intelligence programme; policy and regional-news producers; MarketOntology transmission and exposure primitives; business-impact extraction/adapters; and several useful product surfaces.

The main remaining work is to make these capabilities operate as one trustworthy information path. Today, the named Mastermind news tool and portfolio lens still consume older headline-count/sentiment bundles; the richer news and business-impact paths are not proven through every downstream consumer. Several near-complete product candidates are held at review, integration, deployment or authenticated proof. Quantitative qualification is a separate unfinished obligation.

The programme should deliver three independently accepted outcomes:

1. **Reliable factual delivery:** a source release, later revision, denial or withdrawal reaches the appropriate users and machines with correct identity, clocks, attribution, rights and freshness.
2. **Useful contextual research:** the same evidence supports ticker, sector, theme, catalyst and portfolio research, with sourced economic mechanisms, competing explanations, explicit uncertainty and inspectable lineage.
3. **Qualified quantitative influence:** specific event features influence an existing engine only when the existing evaluation and decision owners accept the evidence and its scope. A rigorous negative result can complete a research question while leaving influence disabled.

These outcomes must not be tied to one global “all green” gate. A blocked Macro cockpit review does not block an independent event corpus; a null predictive result does not block factual news delivery; an unavailable licensed source does not justify hiding the coverage of working sources.

## 3. Material audit findings and proposed priority

The priorities below are implementation recommendations for Fable. They are not new global control-plane states.

### P0-A. Recover release and acceptance debt before rebuilding finished components

The strongest near-term product gains are closing actual release and proof gaps: the article-class follow-up #9963, original sidebar #1081, Macro News #9612, generated company-news panels, MarketOntology #9639 and F05 family consequences. Each has its own owner and dependencies.

The latest retrieved receipt now proves a successful canonical build at the standard 3,072 MB heap, deployed merge `d9ec4d2b86e9e9e0129d7fcd4c646f25f7670c49`, live BUILD_ID `build-TfctsWXpff2fKS`, exact runtime-source hashes and the subsequent authenticated sample. Reuse that proof. Finish #9963's backend-only quality repair without another Terminal build unless a material new invalidator requires one. Deployment and authentication are no longer the reported blocker. [S04, S33]

Macro #9612 has a specific reviewer packet-retention dependency. Mastermind #1661 is open and Ready at the observed head, but source qualification, protected merge, installed generation and reconciliation of the original failed reviewer are separate steps. This dependency must not become a gate for independent news work. [S03–S06]

### P0-B. Make the semantic joins explicit

Today there are legitimate complementary objects: source reports and revisions, story groups, qbus qualitative events, Chronicle lifecycle/consequences, News Impact issuer/thesis deltas, quantitative observations and downstream decision context.

Fable must freeze how those objects reference one another and who owns correction and identity. Do not require all objects to collapse into one table. Do not let each programme invent a competing event ID or replace original source revisions with a generated summary.

A single release can contain several claims; one economic event can have many reports and corrections; one issuer can have multiple securities; one event can affect several themes with different mechanisms. These relationships are not equivalent to string-matching tickers or counting articles. [S01, S07–S13]

### P0-C. Corrected evidence must propagate through every derivative

Source revisions are useful only if corrected details, briefs, theme hypotheses, cached AI context and machine assessments stop serving superseded claims. The shared ticker API addresses parts of this; the Brief design correctly identifies a remaining publication race.

Require generation/manifest-bound conditional publication through the existing owner. A separate “check current source, then write” sequence is insufficient when a correction arrives between those acts. Preserve the distinction between historical as-of replay and a current view. Rights withdrawal may suppress delivery while retaining only what the lawful retention contract permits.

Test semantic correction and access withdrawal separately. An equivalent administrative rights renewal should not trigger an unnecessary model call. [S01, S03, S06, S14]

### P0-D. Complete the quantitative programme without laundering incomplete samples

The current Prophet News Impact workstream records a frozen target of 600 cases across three 200-case families. Its gated-v2 census reports 99 drawn, 74 MATCH/scorable cases and a remaining target shortfall of 526 scorable cases. It also records source-body/identity gaps and unresolved third-family gold adjudication.

These are dataset and evidence gaps. Hundreds of code tests do not close them. Preserve all drawn-but-unscorable cases, explicit exclusions and original denominators. Do not relabel diagnostics as measured accepted packets, weaken the frozen registration, or allow the system under test to generate its own gold.

The leaf adapter is not a completed product integration. The exact native producer/consumer path, freshness, rights, correction handling and B4 acceptance are separate tasks. [S07–S09, S21–S23]

### P0-E. Connect richer news to Mastermind's real consumers

The actual `get_intelligence` tool reads `site/intelligence/by_ticker.json` or standalone legacy news and alt-data products. The portfolio lens similarly reads the older compact bundle. Macro's composer uses headline count, sentiment direction and side-by-side alt-data/radar reads.

Extend these owners to receive qualified event/thesis evidence, numeric deltas, expectation provenance, materiality explanations, competing interpretations and correction status. Use current authenticated owner interfaces and read models; do not make the Brain a second news database.

Audit language such as “divergence is the edge” against actual accepted validation. Context availability does not establish return predictiveness. [S15–S17]

### P1-A. Preserve and improve existing macro and sector news models

The older `macro_surprise.py` reads latest-revised series. That is suitable only for its labelled current context, not a historical first-print surprise backtest. Macro Release Intelligence already exists to address first prints, forecasts, benchmark sets and forward grading. Reuse it.

Likewise, theme news volume already feeds coarse narrative/attention calculations. The audit should not claim that all news is unused or that all source values are disconnected from model inputs. Trace the exact consumer and accepted authority before adding weights. Display-tier inputs can be used upstream where existing law permits; that does not automatically promote the output.

Replace article-count independence with event/source-family-aware features where validated, and preserve explicit missing coverage. Quiet can mean low attention or a broken feed; the system must distinguish them. [S18, S19, S24, S25]

### P1-B. Build Briefs as an admitted, reusable product workload

The approved direction is explicit demand and shared reuse among equivalently entitled readers. News arrival, page opening or ticker changes in Headlines mode should not create inference work by themselves.

The current design did not qualify a shared durable Brief artifact owner, cross-process request owner, conditional publication operation or enforceable pre-call spend reservation. Logging successful usage after a call is not admission. Resolve those bindings before enabling the endpoint or adding a Brief tab.

Use an extractive baseline and an injected adapter first, then compare admitted models on the same rights-eligible corpus. Preserve failures, timeouts and uncertain-cost attempts under their original identity. [S14]

### P1-C. Repair record drift where it changes execution

Examples found in this audit include older “not built” MarketOntology wording, an older Prophet continuation frontier, and an early all-four-legs integrated-answer gate followed by later accepted v0 source and I-R12 route activation with H05 honest-null.

The execution plan must point to the current clause and scope. It must not either reopen already decided questions or treat a later narrow release as universal acceptance of every upstream leg. [S07, S10–S13, S26]

### P1-D. Harden legacy default-off inference semantics

At the audited source, `config.yml` explicitly sets `news_llm.enabled: false`, matching the module-level default-off intent. However, `enabled()` and another path use `.get("enabled", True)`; the function's own docstring says on by default when a credential is present.

An isolated execution of the actual `enabled()` function returned false for explicit false and true for missing configuration with an inert provider-present stub. This is a **counterfactual configuration-omission risk**, not evidence of live inference or current unintended spending.

A bounded owner task should make absence fail closed, reconcile contradictory documentation and ensure any future activation uses current admitted model/budget routes. Do not switch on this legacy path to implement the new Brief service. [S27]

## 5. Target information contract

### 5.1 Six meanings, mapped to existing owners

| Meaning | Required information | Existing owner family |
|---|---|---|
| Source observation/version | Native source/item ID, immutable revision, original source, permitted evidence, published/received/available clocks, rights and correction lineage | Data OS/source owners, qbus news store, Research Vault where applicable |
| Story group | Navigation/deduplication members, exact revision refs, source/syndication family, grouping uncertainty | Existing qbus/news grouping |
| Economic event/claim | Event type, lifecycle, proposition, rumor/denial/confirmation, affected entity, evidence span, supersession | Existing qbus/Chronicle/domain event and News Impact owners |
| Quantitative observation | Value/range, unit, currency, period, accounting basis, actual/expected/prior/revised-prior roles, baseline origin and cutoff | Earnings/FIF/K3E/Macro Release Intelligence/source owners |
| Exposure/impact interpretation | Sourced relationship, valid interval, mechanism, assumptions, scenario, counter-evidence and falsifier | GMI/Company Theme Exposure/TXI/MarketOntology/News Impact |
| Consumer decision context | Exact accepted inputs, as-of envelope, provenance, uncertainty, allowed research actions and approved influence | Existing Macro, Terminal, Brain, Prophet, sector, catalyst and portfolio consumers |

These are conceptual distinctions, not instructions to create six databases.

### 5.2 Time and identity rules

Preserve publisher time, first local receipt, source availability, economic effective time, revision availability, materialisation time and consumer decision cutoff separately. A later materialised artifact may reconstruct an earlier cutoff only when its underlying evidence was actually available then. A historical news archive retrieved today is not proof that the system possessed it in the past.

Bind issuer, security/listing, geography and currency through existing identity owners. Ticker text is a display label, not a universal identity. A customer mention, competitor similarity or shared theme cannot manufacture a supplier relationship.

Use time-valid graph membership. Never apply today's taxonomy, company exposure, consensus or final legal state to a historical decision without an explicitly qualified as-of reconstruction.

### 5.3 Numerical rules

For earnings and guidance, compare like with like: quarterly versus annual, fiscal versus calendar period, reported versus adjusted, revenue versus bookings/backlog/GMV, authorised versus executed buybacks, and point estimate versus range. FX conversion and corporate-action adjustments require their own dated evidence.

Keep actual, expected, previous and revised previous values distinct. A prior print, statistical trend, model nowcast and vendor consensus are different baselines. If an expectation is unavailable, the system may explain a change versus the prior value; it must not label that a consensus surprise.

All arithmetic is deterministic over admitted values. LLMs may extract candidate facts or explain evidence; they do not originate an EPS forecast, causal coefficient or trading probability by assertion.

### 5.4 Correction and independence rules

A copied wire is one originating information family. Ten outlets do not create ten independent confirmations. Distinguish genuinely independent reporting, official confirmation and syndicated repetition.

A correction creates new history and invalidates affected current derivatives. It does not rewrite what a user could have known earlier. A denial does not silently delete the rumor; the lifecycle retains both, with source and timing.

Corrections invalidate or supersede generated current interpretations while preserving original as-known evidence and decision history. They may mark a saved result as superseded and propose an update through the existing authorised owner. They must not silently rewrite a user thesis or reverse an already executed action; rights withdrawal still controls which source material may be displayed.

The same evidence set and rights scope should produce consistent factual interpretation across Macro, Terminal and Mastermind. Language-specific phrasing may differ; numbers, source identity, correction state and coverage may not.

## 6. Fable and Opus operating model

### 6.1 Fable Meta-CEO mandate

**Preferred avenue: Fable.** This assignment warrants Fable because it requires sustained cross-repository integration, contested owner boundaries, scientific and product acceptance, and recovery of several partially delivered programmes. The Chairman explicitly requested this hierarchy.

Fable is accountable for:

- freezing the minimum cross-owner contracts and the definition of complete;
- resolving scope and priority conflicts;
- preserving original operations, accepted work and holds;
- deciding when a section is ready for integration or needs harder principal work;
- approving model/evaluation escalation and rejecting unsupported promotion;
- adjudicating end-to-end evidence and maintaining the final accepted coverage statement.

Fable should perform hard strategy, architecture, auditing and mission-critical implementation when that work genuinely needs principal judgment. It should not become the routine source collector, case labeler, test runner or UI implementer.

### 6.2 Six Opus sections

These are **logical responsibilities**, not a claim that six concurrent seats are available. Actual placement and concurrency come from existing Capacity/runtime admission. Start fewer sections if capacity is limited, preserve one independent review lane, and avoid shared-file writers.

### 6.3 Paid Fabric assignment contract

Every bounded child receives a frozen packet containing:

- existing parent/root and lawful operation identity;
- current assigned receiver and original carrier/custody where continuing work;
- exact base/head, owned files/interfaces and forbidden overlap;
- one question or implementable outcome;
- admitted source inputs and rights;
- expected artifact or code delta;
- deterministic acceptance cases, meaningful negative controls and failure conditions;
- allowed runtime/provider/budget route and bounded attempt cost;
- output limit, return carrier, unresolved-effect handling and reviewer;
- what the child must not infer or promote.

Use the current supported Fabric schema, not this prose as an invented API. Preserve ACK, admission, START, delivery, acceptance, CI, merge and production proof as distinct facts.

The parent reviews the actual returned artifact and original execution evidence. A summary that says “passed” is insufficient. Do not replay an ambiguous operation under another ID, provider or transport. A blocked child freezes its own effects; independent work continues.

### 6.4 When Opus or Fable executes directly

Direct principal execution is appropriate for cross-owner architecture, difficult causal/economic reasoning, consequential scientific judgment, difficult correction/publication races, or a narrowly scoped mission-critical repair that bounded workers cannot reliably perform.
