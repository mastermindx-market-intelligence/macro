### 4. Findings and their evidence

#### F-01 — Browser confluence can create a washout from proxies

**Confirmed at pinned source; priority: repair before an affected positive setup claim.** The Python engine leaves L1 unknown when its measured precursor inputs are absent. The browser additionally looks for washout/reclaim/bounce/buy substrings in entry status or accepts a coiled squeeze.

Our extracted-function synthetic witness returns L1=true/K=1 for status-only bounce_wait and for squeeze-only input; the Python function with absent washout inputs returns L1=null/K=0. The same witness finds a known failed-breakout trap is L7=false in Python but null in the browser. Main also maps several other absent legs to false in JavaScript while Python preserves unknown; that is a semantics reconciliation question, not a license to alter every existing consumer rule. [R25](06_EVIDENCE_REGISTER.md#r25) [R26](06_EVIDENCE_REGISTER.md#r26) [R69](06_EVIDENCE_REGISTER.md#r69)

The actual 6867 diff removes the proxy block, fixes known-trap false and introduces canonical snapshot timing. It is the existing repair route. Its weekend guard explicitly leaves exchange holidays/early closes to canonical calendar integration. Current checks include ci-gate/contract-delta failures. We did not reproduce its entire test suite, authorize deployment or prove a live market incident. [R28](06_EVIDENCE_REGISTER.md#r28)

#### F-02 — Freshness must be measured at the consumer, not inferred from a running service

**Accepted owner observation plus prepared diagnostic source.** A natural fetch/compute cycle took 1,261 seconds. #10201's actual diff measures list_expirations, combined lazy stream/parse/retry time and build_frame with monotonic clocks. It does not change request order, acquisition scope, caching or concurrency.

This is not proof the network alone is slow, and it is not a measured speedup. Next evidence is a naturally scheduled run of the qualified installed source under the incumbent release authority. Compare distribution, root/expiry effects, truncations and source/consumer age before selecting a remedy. [R12](06_EVIDENCE_REGISTER.md#r12) [R30](06_EVIDENCE_REGISTER.md#r30)

#### F-03 — Large event counts can hide weak prospective evidence

**Confirmed dated artifact; current runtime unknown.** The checked gate file is dated October 18, with last event October 16. It contains 103,893 ledger rows across 49 sessions,11,319 ordered source clocks,92,574 legacy_unknown clocks, zero non-null published_at, zero scored rows and scoring.enabled=false. The ordered share is approximately 10.90%; ordering alone does not establish full point-in-time eligibility.

There are zero graded_ok outcomes in that artifact,18,225 not_matured and 65 grader errors. Do not present 103,893 as independent training cases or current qualified evidence. Preserve legitimate retrospective/development uses, but require actual availability and population qualification for prospective claims. [R24](06_EVIDENCE_REGISTER.md#r24)

#### F-05 — A heuristic score can gain unsupported authority through presentation

**Source inspection plus product-risk inference.** flowScore uses fixed component weights and tier labels; its own comments describe a conviction score. This is not empirical calibration. A percent sign, green action treatment or adjacent probability panel could make the user read attention as likelihood even if the code never emits a probability field.

Review the complete composition: default ordering, badges, tooltips, rationale and Plan handoff. Keep the existing score owner; expose component reasoning and source eligibility. Any probability requires a qualified target, horizon, population and calibration version. This audit does not establish that every current screen makes the mistake.
