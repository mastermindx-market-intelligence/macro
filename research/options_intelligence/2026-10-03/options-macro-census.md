# Macro options source census — immutable code, distinct consumer contracts

**Research date:** 2026-10-03. **Repository:** mastermindx-market-intelligence/macro. **Primary source pin:** `6f5e78e94e8808582a650cdfa0fc3357040a179c`. **Candidate-only supplement:** PR #8310 head `a15ba9ae77826bf6a1d6fcb40022b6816b705e43`.

## 1. Decision summary and evidence limits

The source supports extending existing records with carefully labelled options context; it does not support replacing incumbent stores, assigning a new owner, or assuming the current runtime is healthy. The most consequential findings are:

1. **Trade/quote provenance is now retained by the real collector entry points.** A separate lossy normalizer still exists, but the inspected caller uses `bulk_trade_quote`, not that helper. EOD/OI/Greeks normalization still loses intraday source-clock detail and Greeks model provenance.
2. **The measured NBBO block and soft signing are separate algorithms.** The measurement block rejects future quotes and locked/crossed markets. Soft signing does not inspect quote timestamps, print conditions, or quote conditions. Neither establishes trader identity, opening intent, dealer inventory, or an executable fill.
3. **Chain heat's `ask_share` is generally a proxy reconstructed from categorical `side`.** It must not be equated with the separately measured `microstructure.at_ask_share`.
4. **The closed `stock_score` GEX gate is not a global GEX veto.** Prophet's US C1 fusion independently registers and conditionally admits the GEX verdict. AD1's daily options brief explicitly supplies no GEX verdict. Those consumer boundaries must remain separate.
5. **Canonical candidate and outcome schemas already exist.** The candidate carrier is inactive, strict, and has fifteen authority flags fixed false. The current outcome schemas keep option returns unavailable. An `options_context` addition needs an incumbent schema change, not an unregistered JSON key or second state machine.

All conclusions below are **source observations** or explicitly labelled inferences. No market data, entitlement, process, credentials, current artifact, deployment, worker, live provider, or runtime test was inspected. Comments describing past “measured live” incidents are historical source assertions, not fresh verification. The primary pin proves what the code says at that commit; candidate-head code is not represented as merged or activated. Existing C0 owners and the Terminal #599 lane remain unchanged.

## 3. Store resolver, reads and coverage do different jobs

The canonical resolver classifies a candidate as `has_root`, `drained`, `no_tiers` or `unknown`. It refuses provably empty stores. A timeout, denied listing or failed probe becomes `unknown`, which **still resolves**, with an explicit warning that readability is unverified. It checks only whether a tier contains a root directory; empty root directories, corrupt parquets, stale dates and thin coverage can all survive resolution. This is a deliberate availability policy, not a claim of data health. [resolver classifications](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/thetadata_store.py#L127-L205); [resolver scope](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/thetadata_store.py#L234-L247); [unknown resolution warning](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/thetadata_store.py#L312-L337)

General `_load_parquets` reads whole matching year files, drops full-row duplicates, caches by resolved path, and skips unreadable files at debug level. The cache key contains no content hash or modification time; a long-lived reader needs explicit cache clearing to see rewritten data. Returned empty or partial frames do not by themselves distinguish absent files from corrupt files. Full-row dedup also does not resolve conflicting rows sharing one contract/date identity. [general parquet read and cache](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/thetadata_store.py#L429-L482)

`oi_for_date` is a stronger narrow reader: one OI root/year, projected contract columns, exact timestamp/root predicates before normalization, a second exact-date/root check afterward, no broad cache and full-row dedup. Missing or malformed files still return a stable empty shape. “Point-in-time” here means exact requested normalized date; the normalized store has already lost intraday OI availability. [narrow OI read](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/thetadata_store.py#L517-L580)

The convenience `chain` joins same-date EOD, OI and selected Greeks. It expressly does not shift OI and delegates the positioning-date law to callers. Its Greek projection excludes gamma, vanna and charm even if stored upstream. `make_chain_provider` uses median underlying price where present, otherwise **the strike with maximum summed volume**; despite loose “volume-weighted” wording, it is an argmax strike, not an underlying-price observation. Its T is integer calendar days/365, clipped at zero: unsuitable as an exact seconds-to-expiry authority. These helpers are reusable research adapters, not lossless source contracts. [same-date chain joins](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/thetadata_store.py#L757-L817); [provider spot and T calculation](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/thetadata_store.py#L939-L990)

`iv_coverage` reports first/last date and number of dates with positive non-null IV. It neither proves continuous coverage nor reports contract-level completeness, quote quality, entitlement, unit consistency or freshness. Read errors are skipped. [IV coverage definition](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/thetadata_store.py#L876-L912)

AD1 intentionally bypasses `chain`/`make_chain_provider` and performs its own projected, receipt-bound assembly. Its role-split session selection has separate OI/EOD plausibility and latest-session balance checks, including a two-demotion cap so systemic thinness is reported as coverage loss. Its source denominator is the resolved current options universe, not whatever roots happen to exist in the historical store. The pure engine checks 90% source coverage separately from 60% eligible-name coverage and carries stale/degraded states. This is additional consumer protection, not evidence that any current source passes. [role-specific session membership](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/scripts/build_options_intel_brief.py#L422-L475); [universe receipt and missing anchor](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/scripts/build_options_intel_brief.py#L1070-L1085); [source coverage and staleness](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/options_intel_brief.py#L1229-L1258); [separate coverage and eligibility gates](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/contracts/options/OPTIONS_INTEL_BRIEF_V1.md#L54-L76)

## 4. Soft signing, measured microstructure and legacy arithmetic

### Current live flow: two adjacent algorithms

`process_batch` checks exact safe sequence, positive integer size, finite positive price/strike, canonical root/right/expiry, and valid regular-session source trade time before mutating state. It requires one root per call. Naive vendor timestamps are localized to America/New_York; ambiguous/nonexistent local times become missing. Session/contract/root-scoped state and event identity prevent cross-root collisions. Event IDs hash session, root, expiry, strike, right and the batch's maximum source sequence. [time and event identity](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L252-L276); [source-row admission](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L754-L856)

Sequence handling rejects rows at or below the previous per-contract maximum, then advances that watermark before quote filtering. This supports overlapping re-pulls under an assumed monotone sequence contract. It is **not a correction ledger**: same/lower-sequence corrections and late arrivals cannot be inferred safely from this mechanism. The inspected block has no explicit same-batch dedup by contract plus sequence; it should not be described as proof that repeated rows inside one response are harmless. Rejection diagnostics are counts/notes, not a retained amendment/quarantine record. [sequence watermark and processing order](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L858-L903)

Soft signing retains quotes with bid > 0 and ask >= bid, sorts by contract plus trade timestamp, and computes midpoint sign with a previous-print tick fallback. It does not use sequence as a timestamp-tie breaker, carry the previous print across batches, inspect quote age, reject future quotes, or evaluate conditions. A first midpoint trade can receive NaN from its missing prior price; an unchanged midpoint trade can remain zero. Neither receives an explicit abstention reason. All retained-print premium remains in gross denominators, while only positive/negative signs enter signed subtotals. These semantics should be exposed if promoted into any research feature. [soft signing filter and ordering](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L148-L187); [quote/tick fallback](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/flow_signing.py#L22-L32); [signed-share denominator](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L297-L330)

The separate `microstructure` computation deliberately runs **before** that filter. It measures source versus covered counts/premium, quote age, spread, quote sizes and four execution locations. Validity requires finite positive trade inputs, bid > 0, ask > bid and quote age >= 0. Locked/crossed/future/missing quotes are uncovered. There is **no maximum quote-age threshold**, no trade/quote-condition admissibility rule and no condition-based cancellation/reversal handling in this function. At-ask/at-bid/outside/inside shares are premium-weighted over covered premium, using a 1e-9 absolute price tolerance; the two edge shares determine aggression sum/difference. These are execution-location facts conditional on matching quality, not buyer/seller identity. [microstructure validity](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L379-L448); [measurement denominators and fields](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L474-L545)

One further boundary matters: a batch with no quotes surviving soft signing returns no events, even though a zero-coverage measurement was computed; notable events alone get the measured block attached. Therefore a feed's attached measurements are not a complete census of every fetched contract. Their contract-level denominator is more honest than post-filter counts, but event selection still matters to downstream sampling. [empty signing result](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L900-L925); [notability and measurement attachment](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L1019-L1050)

### Live flow and nightly options flow are not substitutes

Live heat computes per-print signed premium as positive-sign premium minus negative-sign premium. Legacy `options_flow` signs minute-close changes, aggregates signed contract volume, then multiplies **all contract premium by the sign of net contracts**. Those values can differ greatly for offsetting trades at different prices. Both hardcode a 100 multiplier; neither calculation establishes adjusted-contract economics or customer/dealer identity. [per-print live signed premium](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/live_flow.py#L930-L951); [legacy minute signing](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/options_flow.py#L79-L105); [legacy net-premium arithmetic](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/options_flow.py#L122-L151)

The legacy engine remains source-reachable: `scripts/build_options_flow.py` fetches Massive minute aggregates, calls `of.build_flow`, writes `site/flow/<symbol>.json`, and accrues `data/options_flow/summary_<symbol>.parquet`. Its exact target minute-session guard does not guarantee its Greek/OI snapshot is at that date: `_chain_pair` falls back to the latest snapshot if all available snapshots are newer than the target. This is a specific source-level future-vintage risk for replay, not an observation of a contaminated run. The pinned signing gate has both `scored=false` and `direction_reliable=false`; metadata does not remove the numeric fields from legacy payloads or summary stores. [legacy snapshot selection and target guard](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/scripts/build_options_flow.py#L89-L122); [legacy writes](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/scripts/build_options_flow.py#L132-L175); [pinned legacy signing gate](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/data/options_flow/signing_gate.json#L1-L10)

### Chain heat's similar names hide different quantities

Live coalescing's `ask_share` means premium with a positive **soft sign**, not literal at-ask execution. That fraction is not included in the emitted event shape; the event carries `side` plus the separate measured block. The chain-heat writer fills absent `ask_share` with 0.80 for `~buy`, 0.20 for `~sell`, 0.50 for `mixed`, and null otherwise. The aggregator premium-weights that proxy, then labels >=0.65 accumulation, <=0.35 distribution, else contested. The output stays `direction_reliability="soft"` and display authority; the envelope even substitutes 0.5 for missing aggregate share. Treating this numeric proxy as measured aggressor probability would silently manufacture evidence. [categorical ask-share reconstruction](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/scripts/build_chain_heat.py#L106-L133); [lean thresholds](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/options_structure.py#L191-L200); [proxy weighting](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/options_structure.py#L285-L291); [aggregate and authority labels](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/options_structure.py#L327-L368); [null substitution and source clock](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/scripts/build_chain_heat.py#L176-L193)

## 5. GEX in Prophet: code presence, gating and influence

| Consumer | Source wiring at the pin | What is and is not established |
|---|---|---|
| Per-stock `stock_score` | Reads `data/gex/gate.json`; missing/broken gate defaults false. A true gate allows +/-0.3 entry tilt and GEX-dependent idiosyncratic-risk inputs. | Pinned gate file says false. This proves the committed setting only. |
| US Prophet C1 fusion | Registers `gex_confirm_verdict` in F5_FLOW_POSITIONING, maps confirm/neutral/caution to +1/0/-1, reads the top-level board verdict. | Independent of the stock-score gate. A registered member may affect family and final scores if admitted. |
| Board evidence-stack chip | Confirm verdict contributes GEX-OPTIONS to the displayed evidence count. | A displayed vote is a separate use; do not count it as independent data from the same verdict. |
| Options entry state | Reads latest `data/polygon_gex/summary_*`, reconstructs confirmer input and emits verdict plus source dates. | Separate legacy-source display/context plane. It is not AD1's Theta assembly. |
| AD1 options intelligence brief | Producer always supplies `gex_verdict={}`. | GEX mechanics multiplier is 1 on this actual producer path; generic engine support does not activate it. |

The stock gate and its arithmetic are [gate reader](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/stock_score.py#L631-L644), [committed closed gate](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/data/gex/gate.json#L1-L5), [gated risk contribution](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/stock_score.py#L687-L709), and [gated entry tilt](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/stock_score.py#L838-L892).

The stock-library builder reads `site/gex/*.json` and falls back to its lighter GEX summary; it calls `gex_confirm.assess` and propagates the result to board rows. The inspected loader filters missing/no-options tier but has no source-age equality test. `assess` itself normalizes mechanics fields without preserving source timestamps. It grades short/long-gamma assumptions, wall proximity, vol-hole state and optional risk-reversal change; its long-direction default is used by these callers, and `rr_change` is not supplied. Its OPEX suppression is based on the supplied day count. These are heuristic calculations over an assumed dealer-sign model, not independent observations of dealer positioning. [GEX artifact loader](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/scripts/build_stock_library.py#L478-L498); [confirmer call sites](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/scripts/build_stock_library.py#L3894-L3908); [confirmer normalization and guards](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/gex_confirm.py#L69-L104); [confirmer mechanics and OPEX](https://github.com/mastermindx-market-intelligence/macro/blob/6f5e78e94e8808582a650cdfa0fc3357040a179c/engine/gex_confirm.py#L114-L190)

The key activation trace is concrete: builder propagation → `score_rows` → `_fusion_plane` → `fuse_board` → member admission → family aggregation. GEX needs 50% non-null pool coverage and, for an evaluable pool, within-night variation; identical oriented member vectors are collapsed within a family. Admitted member percentiles form family means, and present-family means form the fusion score. The US sort is stage then fusion score then ticker.
