## 1. Executive decision

Build the next Options experience around **one continuous investigation**:

**Discover something worth examining → understand the evidence → compare an exact expression → save the case → monitor an observable condition → review what happened.**

The existing estate already contains much of the difficult machinery: observed Flow and Statistics, Gamma/Delta exposure and strike-expiry views, volatility comparisons, research lenses, deterministic expiry payoff, candidate/campaign lineage, investigation persistence, and watch/review infrastructure. The main product weakness is the integration between those capabilities, followed by uneven source qualification, incomplete persistence paths, and insufficient end-to-end acceptance.

The upgrade should make a sophisticated product easier to understand without hiding its depth. A user should be able to read the current assessment quickly, inspect why it is supported, see contradictory or missing evidence, and move into a deeper investigation without losing the instrument, source vintage, selected contract, comparison basis, or original question.

“Production ready” has two independent meanings here:

1. **Engineering and product readiness:** supported workflows work on real admitted data, handle failure honestly, preserve identity and permissions, save and reopen correctly, perform well, and have authenticated deployed-consumer evidence.
2. **Scientific qualification:** each predictive claim has separately earned its causal data eligibility, frozen method, appropriate evaluation, uncertainty, cost treatment, and applicable promotion decision.

The product can deliver substantial descriptive and mechanical value while a forecast remains research-only or unavailable. A polished interface must not manufacture a probability, a trading signal, or a live sleeve.

### Decisions established by this round

- Preserve accepted work and integrate through existing owners.
- Keep the October 31 plan and acceptance namespaces authoritative; this document is their dated amendment.
- Use one coherent Options shell and context across the full workflow.
- Prefer a short assessment followed by inspectable evidence, rather than a dashboard that requires the user to synthesize every metric.
- Keep original evidence, latest evidence, and modeled assumptions distinct.
- Extend existing investigation, watch, source-receipt, and capability contracts; do not create a new Options database, collector, scheduler, retry queue, or authority registry.
- Expose research maturity separately from freshness, data quality, coverage, and account access.
- Preserve all current deep views and stable route aliases when simplifying navigation.
- Treat Paper as an editable specification with state and interaction coverage, not merely a gallery of attractive screens.
- Prepare the final Fable/T3 commission in turn 4; this turn performs no implementation dispatch, production deployment, model activation, or Paper mutation.

### 6.2 The shared workspace anatomy

**Header:** instrument/root, selected expiry or lens, market/session clock, current/history/scenario mode, and access/source state.

**Assessment:** one concise answer to the current question, an evidence-state label, the most material contradiction or limitation, and one useful next action.

**Main evidence:** the table, chart, matrix, term structure, payoff or comparison appropriate to the task. The chart must answer a question; no decorative analytic surface.

**Contextual pane:** one right-hand pane at ordinary desktop width, shared by the Inspector and Case context through clearly named tabs or deliberate drawer transitions. Inspector shows exact source, units, population, assumptions, clocks, corrections and related evidence. Case shows the current question, original evidence, expression, user assumptions, saved revision and watch status. Keep case context collapsed when no investigation is active. Technical IDs and method implementation details belong in Sources or build notes.

Do not implement global navigation + evidence + inspector + a second persistent case rail as four competing columns. At 1440px, an active case and selected node must leave the main matrix/table/payoff readable, with no critical numerical qualifier truncated. Small screens use a focused step or sheet and retain selection and return focus.

The anatomy is conditional on the view's job. It does not require every badge, contradiction, clock or pane to be simultaneously visible. Use progressive disclosure without concealing a limitation that changes interpretation or action. The first viewport should make the subject, result/state and useful next action clear; exact receipts remain reachable without losing context.

### 6.3 The principal journey

1. **Discover:** read a concise source-supported observation in Overview or Flow.
2. **Inspect:** select the exact row and see side uncertainty, corrections, population, and source age.
3. **Contextualize:** open Exposure with the root or exact qualified selection; retain the original row and return state.
4. **Compare:** examine a matched historical book, expiry or volatility context; show the comparison basis.
5. **Plan:** carry a qualified contract selection into the existing Plan editor; leave unprovided premium/quantity/side assumptions blank.
6. **Save:** create a revision through the incumbent Investigation owner and verify the exact readback. Reconcile an uncertain response before retry.
7. **Watch:** preview and arm an actually supported observable condition; show what will be evaluated.
8. **Review:** reopen the original case, exact firing receipt and later evidence; keep the draft assessment separate until a successful revision write.

The first Paper path should use one coherent, clearly marked illustrative case through these steps. It must not splice three unrelated SPY prices, expiries and dates into a purported continuous journey.

## 7. Surface-by-surface upgrade specification

### Overview

Lead with the user’s investigation priorities: a small number of material changes, open cases needing attention, and coverage/freshness context. Replace an undifferentiated metric wall with a readable hierarchy. Each item needs a specific reason for appearing, a timestamp and population basis, a limitation, and a direct investigation action.

“Nothing met the filter,” “source not published,” “refresh failed,” and “no qualified candidate” are different states. A quiet market is not a failed pipeline, and a failed pipeline is not proof of no activity.

### Flow

Retain fast dense scanning and exact inspection. Separate selecting a print from filtering the root. Preserve the user’s row, sort, filters, scroll and focus on return.

Show print grain, contract identity, premium basis, measured/proxy signing, uncertain side, corrections and possible package relationships. Possible legs remain possible until a qualified package source establishes membership. Related context below a filter does not silently enter filtered totals.

Source-specific Greek availability remains source-specific. Vanna/Charm computed elsewhere cannot enable uncomputed cells in the current matrix. A scenario must state whether it uses local-linear sensitivity or full repricing.

### Volatility

Make exact expiry, constant-tenor comparison, selected smile and expected-move method easy to distinguish. Show the relevant spot and IV clocks separately. Do not draw a line across unavailable wings or manufacture a fitted terrain from raw observations.

Event context should help explain a term difference, without claiming a causal effect unsupported by the data. Historical rank must carry its eligible history definition; an unavailable history rank stays unavailable.

Preserve the original calculation owner. A published band with an unstated method and an IV-times-square-root-time estimate must retain different labels.

### Research Lab and sleeves

Offer an approachable entry with a clear question and default lens, then expose detailed selection and comparison. Keep the exact table usable independently of 3D. Preserve pinned selections and supported comparisons on view changes, and withdraw wrong-root, wrong-account or unqualified source results.

Show research family, candidate formation, sample support, outcome maturity and permitted claim as separate concepts. “Accruing,” “research-only,” “unavailable,” and “qualified for this claim” need understandable copy and methods detail.

Complete the original source/retention/admission contracts rather than replacing them with a generic JSON cache. The current Matrix integration frontier includes a Matrix-specific server binding and genuine dependencies/source-use decision; absent binding must continue to refuse before I/O. [S07][S15]

### Plan and Compare

Give the user one clear primary action for the state: complete assumptions, calculate, compare, or save a qualified revision. Avoid duplicate Compare controls and repeated generic “saving unavailable” banners.

Keep authored side, whole quantity and premium distinct from dated reference marks. Changes to assumptions invalidate the previous result visibly. The current endpoint supports deterministic hold-to-expiry intrinsic payoff in its admitted ordinary SPY/QQQ domain; show that meaning explicitly.

Advanced pre-expiry valuation, IV/time/rate scenarios, exercise/assignment, adjusted deliverables, multi-expiry structures and realistic costs require their own versioned admission and numerical evidence. Existing engines should be reused, but backend existence does not mean the current Plan API supports them.

Comparisons must align currency, quantity basis, valuation horizon, payoff/model type and cost assumptions. Never present a modeled payoff as a forecast probability or as realized P&L.

### Saved research, Watch and Review

Use the existing versioned investigation as the continuity object. Reopen the exact requested revision; a newer revision cannot silently replace it.

Watch controls expose supported conditions and real evaluation semantics. An unsupported exposure-change evaluator remains unavailable. A source disappearance is evidence unavailable, not a bearish event. An observed price-watch firing does not settle a separate rotation hypothesis.

Review joins original evidence, the correct per-firing value/source clock, correction relation, delivery state and the user’s assessment. “Queued,” “delivered,” “opened,” and “assessed” remain different. The latest trigger stamp must not be applied to older receipts.
