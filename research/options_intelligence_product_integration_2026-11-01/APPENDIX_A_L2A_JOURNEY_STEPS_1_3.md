**Q4 traced answer — can a failed `/api/flow` read render the "no flows / empty" copy?** **No, on both surfaces.** Trace: fetch failure → `flowClientCache.readOutcome` classifies (network/`server`/`malformed` → `unavailable`; 404/410 → `absent`) and `doFetch` **deletes** the cache key on any non-data outcome (B`terminal/lib/flowClientCache.ts#L93-L103`) — a failed read never leaves an empty-array payload behind. `useFlowStream.readOnce` publishes `{status}` only and never clears `data` (B`terminal/lib/flowStream.ts#L98-L120`); `stale` is `data != null && failed` (B…#L261). Tape: empty copy renders only under `feed &&` … `events.length === 0` (B`terminal/components/OptionsHubView.tsx#L2740-L2744`); a first-read failure renders skeleton (or failure copy if the SSE transport itself errored). Desk: EmptyState requires `feed !== null` (B`terminal/components/flowdesk/FeedPane.tsx#L745`); a failure keeps `feed === null` → LoadingState. The one dishonest-ish rendering is failure-as-*loading* (rows 2.4/3.4), not failure-as-empty. Server-side confirmation: during an outage with a warm cache the route answers `stale:true` (B`terminal/app/api/flow/route.ts#L194`) or 503 `{"error":"feed unavailable"}` (B…#L169-L174) — never an empty events array.
