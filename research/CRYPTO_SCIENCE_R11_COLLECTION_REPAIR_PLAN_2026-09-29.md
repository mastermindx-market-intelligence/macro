## Design

Reuse collectors/_first_seen_store.py, the house keep-first/atomic/abort-unreadable evidence owner; do NOT extend lib/store.upsert into a second vintage authority, build another database, create a collector scheduler or activate a provider. Add a narrow collectors/_crypto_observations.py adapter for the existing OKX and BGeometrics collectors. It persists one evidence row per RECEIVED public response under the existing provider data directory and owner. Request parameters are strictly allowlisted; credentials, URL queries/userinfo and request headers are not persisted. Known public response fields are retained as canonical JSON with type/lexeme fidelity, plus logical-payload and exact-body hashes where body bytes exist, endpoint/scope and UTC received time. Unknown semantics stay unknown.

A response-capture identity includes scope, payload and received timestamp. Identical repeat of the SAME capture is idempotent; a later response, revision, or reversion creates a separate observation. This preserves A→B→A instead of silently assuming every content revision appears only once. first_seen means first received by THIS system, not provider first-ever publication. No existing stored history is backdated or imported as if it had contemporaneous receipts.

The new adapter uses the existing first-seen owner with one per-file nonblocking advisory critical section and verifies the persisted capture row. Concurrent capture contention, corrupt store or failed persistence reports evidence unavailable; existing numerical outputs remain available with explicit degraded capture status. This is local file-write exclusion, not a new lease/runtime/retry service. No blind retries. Current adapter HTTP methods make EXACTLY the same requests; hooks record already-received responses. No live adapter is invoked during development, only fake HTTP and temporary stores.

Funding evidence keeps predicted fundingRate, actual realizedRate, fundingTime, exact instrument, method/formula and any supplied interval fields separately. No default eight-hour interval, no realized→predicted fallback, no change to the incumbent daily funding_rate_okx or canonical Bgeo field. A pure as-of view reconstructs known captured revisions using receipt time, rejects conflicting ties and impossible actual settlement timing, and exposes unknown interval/publication/finality. It is not wired into risk allocation.

Flow evidence preserves BTC/CONTRACTS and the reported sell-then-buy order without inventing USD units or spot scope. The current display-only CVD consumer will use exact elapsed hourly membership, break cumulative history at ANY observed missing/invalid hour, withhold incomplete24/72hour outputs, avoid forward-filling price across missing hours, and remove unsupported absolute-dollar/proven-leading assertions. Retain compatible output keys but use None for unavailable unit-scaled fields, adding explicit native units/coverage. Warm-up/accrual, source qualification and wall-clock freshness remain distinct. No new scoring leg, warning threshold, allocation rule or provider qualification flag is enabled.
