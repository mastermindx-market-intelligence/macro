### 3.2 Formula and causal semantics that materially change the recovery plan

1. **Missing benchmark becomes zero on the current Technical Lab path.** The four relative-strength functions return a zero-valued series when `bench_close` is absent. `build_tech_lab_data.py` calls `tc.compute(sid, df)` without a benchmark argument; the technical score dispatcher does the same. Consequently that route can report no RS event where the input was never available. W1 needs an explicit unavailable/not-computable state; W2 needs a canonical benchmark input, as-of alignment and stale/missing policy. A neutral zero must not silently represent missing evidence. [C07][P02][C10]

2. **Fractal lag is already embodied in the output timestamp.** `_confirmed_fractals` evaluates the pivot at `t-2` only when bar `t` completes, using all five bars. The descriptor's `actionable_lag: 2` describes pivot-to-confirmation delay; shifting the returned event again would add a second delay. Passports need both anchor time and first-known time, plus explicit information on whether the emitted index is already confirmation time. [C08]

3. **“Earnings AVWAP” is a rolling max-volume proxy.** The actual anchor is the maximum-volume bar in the trailing 63 bars, with the latest tie winning; the implementation requires anchor age and unchanged-anchor run of at least five bars. It does not consume an earnings release timestamp. Daily typical-price VWAP is also not transaction-level VWAP, and the daily profile is not a tick-derived volume-at-price distribution. The existing guard against anchor jumps is useful; W1 must label the semantic approximation, and a true earnings anchor would be a distinct version with a data/clock contract. [C09]

4. **The OBV “slope” is an n-bar endpoint change.** The function returns `obv - obv.shift(n)`. Its docstring claims this has the sign of an OLS slope, which is not generally true: the simple sequence `[0,100,0,1]` has positive endpoint change and negative OLS slope. The passport should record the implemented change formula; correcting it to OLS would change event identity and require a version, not an editorial relabel. [C05]

5. **RVOL is daily contemporaneous volume relative to a rolling mean including the current bar.** Missing volume is filled to zero before division. This is neither time-of-day matched intraday relative volume nor proof of institutional participation. The denominator inclusion, warm-up and missing-volume treatment belong in the formula passport. [C05]

6. **Compression and breakout predicates are specific implementations.** Squeeze release requires the prior bar to be squeezed and the current bar not squeezed; direction is current close relative to a trailing Donchian midpoint. Donchian bands used for breakouts are shifted by one bar. A failed breakout tracks the most recent break's band within five bars and consumes the failure once; repeated break bars can refresh the reference. This is useful causal machinery, but it is not a universal “first breakout” definition. [C04]

7. **Bar patterns use exact high/low predicates, not marketing aliases.** Inside and outside are strict comparisons; `strat_212_bull` needs a prior up-type bar, an inside bar and a current high above that inside bar's high. It does not require the current close above the level or a separately classified current `2_up` bar. CRSI is similarly an explicit combination of close RSI, streak RSI and percentile rank, with its entry-stack restriction already registered. These mechanisms must survive alias normalization. [C06][C08]

8. **Declared parameters are not necessarily effective parameters.** MA factories and star wrappers capture their own periods and accept unused keyword parameters. The canonical dispatcher merging an override does not prove the function uses it. Formula parity work should exercise a small, synthetic parameter-sensitivity fixture where variation is claimed. This is a bounded contract test, not an outcome audition. [C01][C11]

9. **The display technical score is not actually equal-family aggregation as described.** The implementation assigns a family weight to each evaluated signal, sums those contributions, then divides by the accumulated per-signal weights. A family with more evaluated signals can therefore contribute more total weight; there is no preliminary mean within each family. Its “Strong Buy” style display bands cannot become TOI confidence or a Prophet input. [C10]

## 4. What Combo-v1 can and cannot be reused for

`build_leg_defs` selects nonchallenger, directional members of `LEGACY_COMBO_FAMILIES`; the explicit family list includes legacy groups plus `vwap_events` and `volume_profile_events`. It carries signal, timeframe, kind, family, direction and display names. It **does not carry or enforce** role, dependency family, entry-stack restriction or actionable-lag semantics. Merely lifting that whitelist would permit grammatically invalid or dependent combinations and lose source restrictions. [C02]

The current miner offers real reusable scaffolding: daily and Friday-labelled weekly bars, bounded recent-event activation (five daily bars or four weeks), state activation, AND rising-edge events, next-close forward-return rulers, support filters, redundancy screening and bounded beam search. It also reveals concrete limits:

- Weekly resampling is `W-FRI`; weekly values are forward-filled to the daily grid. A Friday holiday can make the completed week's label late/conservative. The route still depends on the input bars being completed and does not by itself prove the W0 close/known/decision/executable timestamp contract across all calendars and 4H sessions.
- The split is fixed at 1 January 2018. The miner's ranking score uses the **test-half** month-collapsed win rate and test baseline. The same test half is therefore part of candidate selection; it is not an untouched final holdout.
- The Wilson helper explicitly calls its application to average monthly proportions a heuristic, because those months are not Bernoulli draws. Do not advertise the result as a certified confidence bound for clustered signal trials.
- Jaccard redundancy is measured over the pooled activity panel. A preregistered fold-specific selection protocol needs to isolate this preprocessing as well as the final ranker.
- Centered `near_low` and `td_to_trough` grading uses closes from `t-31` through `t+31`. These are retrospective labels. They cannot enter a contemporaneous opportunity vector or tell a current user what fraction of a future move has already occurred.
- Builder exceptions can produce missing outputs or all-false legs rather than a typed refusal. Coverage and computation failure must be visible at the occurrence and evaluation boundary. [C02][C03]

Reuse the deterministic calculations and supporting research utilities where their contracts fit. Add the species-bound role grammar, missingness, fold isolation, trial accounting and current occurrence law through their canonical owners. No new universal score, research ledger or evidence clock is justified by the gaps in this miner.

## 6. Prophet: reuse selection and timing owners without implying adoption

### Current US ranker

`us_board_rank.py` identifies the live construction as `us_prophet_v3`, with an explicitly stamped v2 fallback. Fusion orients each allowed primitive by its registered sign, forms within-night cross-sectional percentiles, averages available members within each evidence family, then averages available families. Presence and variance checks operate on the live cross-section; absent families abstain, and no eligible family causes refusal. This is an unfitted aggregation, not a calibrated return forecast. `F3_THEME_STRUCTURE` is absent from the supplied frame and `F6_MACRO_REGIME` is structurally constant across rows and excluded from the global vote; regime belongs in a router/interaction context. Nominal archetype membership also does not become a signed continuous vote. [R01][R02]

`load_theme_context` reads existing basket artifacts and current membership, selects leading accumulate/enter baskets excluding US-sector IDs, and picks the highest ranked eligible theme for each ticker. This is a useful display/context join; it is not a historical point-in-time membership panel. The older `prophet_bridge.py` consumes board-published rows, owner entry status and conviction, with existing geometry and explicit dates. Its default 45-day horizon is a legacy consumer convention, not the admitted horizon of every future TOI species. [R02][R08]

### New B3/B4 contracts

B3 CandidateState is a read model over canonical upstream candidate state. It has explicit emergence/maturity states and all-false consumer authority; it does not own rank or lifecycle. B4 EntryAvailability is a deterministic, strategy- and horizon-specific evaluation (`HORIZON = "2_15_SESSIONS"`) that binds candidate generation, decision time, bound market date, quote as-of and geometry receipts. Missing required inputs produce `UNAVAILABLE_DATA`. Invalidation/retraction has precedence; a price beyond the chase boundary produces `RAN_DONT_CHASE`; explicit pullback requirements can produce `WAIT_PULLBACK`; only satisfied geometry and risk inputs produce `ENTRY_OPEN`. The existing entry policy owns its RTH calendar and quote/risk rules. [R03][R04][R05]

These are substantial coded contracts, but this census found only intra-adapter B3/B4 references and no external production caller in the inspected engine/scripts/app scope. They should remain **built, adoption not established**, rather than being used to claim an already served combined TOI–Prophet experience.

One integration hazard is already explicit: the B3 source adapter treats certain Radar episode rows as an **unversioned forward projection**, sets `canonical_event_id` to `None`, and records provisional context. TOI must not upgrade that episode address into an immutable entry-event identity. Consume the actual Radar event owner where immutable event evidence is required. [R05]

## 8. Exact identity and existing context contracts

### Identity

The exact identity owner is **Data OS**, particularly `lib/dataos/identity.py`, not a product whose name includes “Stock Identity”. Its listing, security and issuer IDs are stored master identities. Listing IDs are not recalculated from a current ticker after rename; ticker reuse and continuation require the existing curated alias and identity-break law. Alias rows have inclusive `valid_from` and exclusive `valid_to` dates and can be resolved/reverse-checked as of a date. The issuer master explicitly describes current issuer identity; a dated ticker alias alone does not prove a historical issuer relationship. [I01]

`theme_graph/identity_resolution.py` delegates exact identity to Data OS and retains the graph's `co:<market>:symbol#epoch` key for graph topology. It disallows bare-ticker equality as an exact identity fallback and can retain resolved listing/security IDs while the issuer remains unresolved. The behavioral `stock_identity` Atlas has explicit display-only, all-false authority; it neither allocates exact identities nor selects a per-name “best technical tool”. `ledger_identity.py` separately preserves historical continuation/break semantics. TOI must bind these axes, preserve partial resolution and missingness, and never mint its own symbol-based identity plane. [I02][I03]

### Theme, subtheme, sector and industry leadership

Existing company-theme exposure objects are context-only projections with upstream generation/hash references, event pins, theme/basket qualifiers, theme-state as-of/hash and coverage. Existing Neuralweb thematic state aggregates existing foresight/basket/radar/narrative/subsector/divergence sources. Its current artifact explicitly forbids ranking, sizing, alert escalation, board ordering, Mastermind arming and scored-path use. Phase history is hash chained and append-only, with transition/heartbeat records, not necessarily a dense daily panel of every historical input. Its live stale check uses current time, which needs deliberate treatment in replay. [X01][X02]

The theme-health module adds deterministic context above allocation rank. Some entirely missing inputs fall back to “mixed”; that label must not be interpreted as measured neutrality. Subsector confluence reuses existing basket and gate/sector signals and explicitly builds historical summaries with **current membership (`pit=False`)**. That implementation is useful current context and a declared descriptive approximation; it cannot supply unbiased historical dynamic-universe membership. Sector Central consumes existing cycle, trend/risk, regime and heat/crowding inputs. Its limited owner claims cannot be transferred to a new TOI species or become a revived rotation-cycle confluence. [X03][X04]

### Regime

The regime vector already has a builder and persistence owner, consumes existing state inputs, and exposes an exact-date/prior-date lookup with staleness. Date-level prior-only lookup is necessary but insufficient for an intraday decision-time guarantee; TOI still needs generation/known time and the exact state available at its decision. Use the existing regime owner and condition or stratify preregistered research. Do not introduce another macro classifier or a row-constant global ranking vote. [X05][R01]
