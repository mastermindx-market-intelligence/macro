## Findings

### 1. Exact incumbent D1 does not freeze its box at first ARMED

**Sections:** G2/G3 versus K2. **Severity:** high scientific identity conflict.

G2/G3 says geometry is fixed at ARMED. K2 proposes the exact incumbent `vol_squeeze.assess_series` range construction. The inspected `engine/vol_squeeze.py` computes the box over the compression run through the most recent compressed bar. After the fifth compressed bar makes it COILED/armed, further compressed bars can change the box. The final release then uses that run's boundary. These are different constructions.

**Correction:** preserve the incumbent as D1 by distinguishing versioned, provisional geometry while armed from the boundary frozen for a trigger. Preserve every known-at version and define first-trigger/reset behavior. If the intended TOI research instead freezes at first ARMED, name that as a new construction with distinct lineage and trial accounting; do not silently substitute it for the exact incumbent or inherit S16 evidence.

### 2. Five-bar activation deadline conflicts with D1's minimum duration

**Sections:** J1/J2 and K5. **Severity:** high experimental-definition conflict.

K5 places the activation deadline five completed bars from first FORMING onset. D1 requires five consecutive compressed bars, then a later noncompressed release before it can fire. With inclusive onset counting, activation cannot occur within that window; with five subsequent bars, only the earliest sixth-bar release can qualify. Most genuinely armed monitoring would fall outside the endpoint.

**Correction:** define endpoints explicitly. Prefer a fixed five-future-bar horizon from each predeclared current landmark, with minimum-duration eligibility represented as a structural zero/delayed-entry constraint where necessary. Keep original FORMING occurrences and never-armed cases in the cohort. A separate first-ARMED analysis is legitimate but has a narrower denominator. Alternatively choose one blind longer onset horizon tied to actual duration/release semantics before registration. This is design coherence, not outcome-based tuning.

### 3. Episode-average landmark loss can change the probability estimand

**Section:** K7. **Severity:** medium/high conditional on the proposed risk-set truncation.

If a risk-set episode ends when an event occurs, the number of forecast landmarks depends on that future event. Weighting each row by inverse eventual episode length is therefore outcome-dependent. Calling the resulting average simply a proper probability score can misstate its target. For example, equal numbers of one-step event episodes and two-step surviving episodes give first-landmark event rows weight 1 and non-event rows weight 1/2; the weighted Brier optimum is 2/3 instead of the actual first-landmark probability 1/2.

**Correction:** use fixed predeclared landmarks or primary score weights determined from information available at the landmark. Retain proper risk-set exposure for model fitting. Equal-episode summaries can remain a separate descriptive/utility estimand with explicit meaning, rather than being presented as unchanged at-risk probability scoring. Dependence-aware uncertainty still addresses correlated observations.

### 4. W3 outcomes are ordered before their required research adapters

**Sections:** N roadmap and P1 orders 6–7. **Severity:** medium execution dependency defect.

The W3 row/order 6 allows an outcome run after W1/W2/preregistration acceptance, while the thin occurrence/Eval adapters and deterministic prefix/label validation appear afterward. Yet D2, new occurrence identity, event labels, hazards and quantiles need those adapters to run W3 faithfully.

**Correction:** split adapters into (a) bounded research detector/label/estimator implementations and pre-outcome deterministic acceptance within W3 closure, and (b) forward/live production adapters in W4 after the scientific disposition. The outcome gate must explicitly require the former. Source-independent fixtures may be prepared while data is held.

### 5. Capability classification and scientific gates need separate columns

**Sections:** A4 and D1. **Severity:** medium explicit requirement omission.

The attachment requires the canonical capability vocabulary for each relevant capability and a separate W3 ADMIT/HOLD/REJECT gate for stores. A4 currently uses prose, HOLD, null and research-complete labels; D1 lists only gate dispositions. Those describe useful facts but do not supply the requested classification.

**Correction:** add a canonical capability-state column using PROVEN_LIVE, BUILT_NOT_PROVEN, PARTIAL, DARK_OR_DISCONNECTED, BROKEN, SPEC_ONLY, NOT_BUILT or REJECTED_BY_DESIGN, as supported by the evidence. Keep source acceptance, scientific admission and consumer authority in separate fields. Avoid making a broad PROVEN_LIVE claim from one sampled component.
