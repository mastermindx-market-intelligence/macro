## SEAT RULINGS R5.1–R5.7 (binding)

### R5.1 (B1, B2) — one parsing boundary; every renderer takes typed values only
The parse functions are private and are the only code that inspects a raw scalar. Each one:
- tests the type by identity first (`type(value) is str`, never `isinstance`, never set membership on an unchecked value);
- then checks range and form;
- raises `EconomicInterpretationError` and nothing else.

1. **Instants.** `_parse_instant(value, name) -> datetime` accepts exactly the canonical UTC form `YYYY-MM-DDTHH:MM:SSZ`. This is the form `_iso` in `engine/company_intelligence/events.py` writes, and the fixture lifecycle carries it. Recommended shape:
   - `type(value) is str`;
   - `re.fullmatch(r"[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z", value)`, ASCII digits only;
   - `datetime.strptime(value, "%Y-%m-%dT%H:%M:%SZ")` inside `try`, converting `ValueError` to the typed error;
   - round-trip equality `parsed.strftime(fmt) == value`.

   The seat verified that `strptime` refuses month 13, month 00, `02-31`, second 60, second 99, hour 24 and year 0000, and that only the round trip refuses the non-canonical `2026-7-29T17:00:00Z`.
2. **Dates.** `_parse_date(value, name) -> date`: the same rule for `YYYY-MM-DD`.
3. **Tokens.** `_parse_token(value, allowed, name) -> str`: `type(value) is str`, then membership in a closed `frozenset` of `str`.
4. **Numbers.** `_parse_decimal(value, name) -> Decimal` replaces `_decimal`:
   - `type(value)` is `str`, `int`, `float` or `Decimal`, compared by identity, so `bool` and every subclass are refused;
   - then a finite `Decimal`.

   `_parse_precision(value) -> int | None`: `None`, or `type(value) is int` and `value >= 0`.
5. **Where the boundary applies.** Each value below passes through its parser before it is used for anything:
   - `selection.currentness.state` (token) and `.source_clock`. `None` is allowed only with `currentness_unverified`; otherwise the value is an instant.
   - The validator's stored `selection.currentness` and `selection.currentness_observed_at`, through the same rebuild path. `_validate_payload_shape` uses `type(x) is str`, not `isinstance`.
   - `lifecycle.source_available_at` and `lifecycle.observed_at`. Each is `None` or an instant. `None` stays `None` in `clocks` and renders `None`; anything else that fails to parse raises.
   - Each of the four `fiscal_scope` entries (date), parsed in both build and validate before Task 1 is called. `fiscal_scope` itself must be a `tuple` or `list` of exactly four.
   - `semantic_revision` and `code_revision`: `type(x) is str` before comparison with the constants. A non-`str` build argument returns the unavailable payload, exactly as an unsupported string does. A non-`str` stored revision raises `EconomicInterpretationError` as today.
   - Every `compare_eps` argument (R5.2).
6. **Renderers take typed values only.**
   - `_clock_text(value: datetime)` and `_fiscal_clock(value: date)` receive parsed values and never a string.
   - `_valid_timestamp` and `_TIMESTAMP_PATTERN` are deleted.
   - The payload carries each clock's canonical string, which by the round trip equals the input.
