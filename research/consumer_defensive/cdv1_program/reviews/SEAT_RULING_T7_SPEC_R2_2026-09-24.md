## Majors

- **R11 (major 1 — collapsed row vs lazy load).** The collapsed row shows the section title, the issuer display name and the expand toggle ONLY. No status chip, no stance line and no other data-derived text may appear until the user first expands the section. There is NO prefetch for a collapsed section: private data is fetched only on user intent. After the first expansion the adapter keeps its DOM and merely hides it on collapse (no teardown, no refetch on re-expand within the same signed-in session); the chip and stance live inside the expanded body and never migrate into the collapsed row. Rewrite spec:24, :38 and :52 to say exactly this and delete any sentence that contradicts it.
- **R12 (major 2 — one ticker source).** The host's adapter call argument `issuer.ticker` is the ONLY input. The adapter WRITES `data-economic-issuer` onto the mount root as a receipt of what it mounted; it never reads that attribute. Delete every reading of `data-economic-issuer` and state the write-only rule in §3 and §6.
- **R13 (major 3 — the field map is a contract, not a description).** Retitle §6's field map "Binding contract on Tasks 3, 4 and 6 (contract-first)". State: Task 3's interpretation output, Task 4's v2 private publication and Task 6's API responses MUST expose these exact paths, or the task that cannot must amend this spec in its own PR before it merges; until Task 6 merges the map is `PROPOSED`, and the spec's STATUS line says so. Fix `source_text`: it is the ORIGINAL-language text only, shaped `source_text: {text, lang}` with `lang` an ISO 639-1 code (P&G filings are `en`); no ZH translation of private SEC text is ever produced or displayed. ZH applies only to copy the spec's own copy table owns (labels, chips, stance rows, definitions). `header`, `period`, `precision_note` keep EN/ZH pairs because they are spec-owned copy composed from typed fields, never quoted source text.
- **R14 (major 4 — auth transitions).** On an `mdx-auth` transition to signed-in while the adapter sits in the `sign_in` state, the adapter re-runs its load in place: no page reload, no re-mount, `data-economic-mounted` untouched. On a transition to signed-out, the adapter clears the expanded body to the `sign_in` state and keeps `data-economic-mounted`. The attribute is never removed while the adapter is alive; the mount guard at spec:33 therefore always holds. Rewrite spec:378 accordingly.
- **R15 (major 5 — every stance says what to do).** Every row of the pinned rule-ID stance table ends with one action clause drawn from this closed set, verbatim: "watch — don't chase" / "check the source before acting" / "nothing to act on yet" / "read the receipt first". Each row stays within the glance-tier word budget in both languages. No row may advise buying, selling, sizing or timing. Add the ZH form of each clause once in the copy table and reuse it.
- **R16 (major 6 — enumerate states).** `data-economic-state` takes exactly: `idle`, `loading`, `ready`, `sign_in`, `no_access`, `not_found`, `unavailable`, `unsupported`, `error`. Map: 401 → `sign_in`; 403 → `no_access`; 404 → `not_found`; 5xx, timeout and network failure → `unavailable`; a response whose schema version the adapter does not know → `unsupported`; any other failure → `error`. Each non-`ready` state has one plain-word EN/ZH line in the copy table and none of them names an HTTP code, a study or an internal state to the user. List the enum in §3 and repeat the mapping in §6.
