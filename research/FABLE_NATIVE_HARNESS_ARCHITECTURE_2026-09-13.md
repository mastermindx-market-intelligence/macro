## 1. Outcome and the architecture decision

Chris's job is to give a large program to a capable principal, then receive integrated,
useful work without managing accounts or discovering a ten-Fable census after the fact.
The machine job is to preserve a capable native coding environment while enforcing
suitability, delegated authority, real shared capacity and correction-safe execution.
The moat is reusable company context plus reliable orchestration and accepted outcomes,
not a growing collection of wrappers or an impressive number of simultaneous sessions.

The 10/10 end state is one coherent native cockpit: Fable plans and integrates; the
existing router places bounded work; qualified project leaders can manage subtrees;
cheap capable workers do routine execution; parent context stays useful; spend and
capacity remain visible; an interrupted tree resumes without duplicate work or grants.
One accepted user-visible capability, not ten summaries, is the unit of success.

**Decision for this slice: intelligent decomposition, deterministic admission.** Fable
may decide what work to ask for and why it is independent. It may not mint model spend,
choose an account to evade a limit, or turn an explanation into permission. The default
native profile is `router_only`. A separate `native_leaf` profile is a deliberately
restricted canary candidate, not the general cross-provider worker interface.

Do not make the principal either helpless or omnipotent. Its planning and judgment stay
rich. Its authority to start additional computation stays bounded outside its prose.
Role and model are separate: a project coordinator need not be a Fable model invocation,
and a model capable of coordination does not thereby become a company executive.
Chris remains Chairman; Sol retains thesis, architecture and final acceptance.

## 3. What Anthropic actually supplies

The current native subagent system supports nesting, with three layers below main by
default on v2.1.219+. Depth and concurrency are separate controls. The documented
concurrency limit is explicitly not enforced under ultracode and is not a lifetime
spawn budget. Explore can inherit the parent model. Environment overrides and model
allowlist substitution can also change the model actually served. Requested model is
therefore not sufficient spend evidence. [A1]

Agent teams are a different abstraction: their current limitations include no nested
teams and a fixed lead. They are not a ready-made four-level heterogeneous company
control plane. [A2] Anthropic's research-system report supports an orchestrator/worker
pattern and reports substantial token amplification for its multi-agent workload;
it does not establish that more agents always improve a coding task. [A3]

PreToolUse can deny an operation; SubagentStart is not a pre-spawn veto. Hook timeouts
and asynchronous hooks are not a substitute for reliable enforcement. [A4] Skills can
start isolated subagents through `context: fork` and can carry model/tool behavior.
A skill name is not proof that it is passive instructions. [A5] Native SendMessage can
resume a completed subagent without a new Agent invocation. [A1]

Adopt native context isolation, specialized tool scopes, compact evidence returns and
real native CLI behavior. Do not adopt unconstrained recursive delegation, model
inheritance as a cost policy, or native messaging as Executive admission.

## 4. Implemented source slice: a profile compiler and the existing guard

`python3 scripts/fable_harness_profile.py` compiles candidate JSON and native CLI argument
data from the installed source. It does not invoke a provider or execute hook source.
It verifies the existing registry, guard contract, hook wiring and source hashes. It
requires an exact declared supported CLI version, but explicitly reports the observed
version as null and `launch_authorized: false`. A declaration is not host attestation.

The emitted `--settings` now includes the existing routing PreToolUse hook and context
SessionStart hook. The guard command maps an interpreter/command failure to blocking
exit 2. It does not import the unrelated ship-loop or worktree hooks. The compiler emits
`required_workspace_sources` with exact input hashes for the existing workspace owner
to stage and attest under `CLAUDE_PROJECT_DIR`. It creates no source installer or grant.
This matters when the harness intentionally disables ambient setting sources: env and
agent definitions alone did not deliver the routing hook. Existing managed settings can
still constrain or disable customizations; the native receipt qualifies only its exact
isolated configuration, not arbitrary combined home/project/managed settings.

The default compiled profile, `router_only`, denies native Agent/Task, Workflow,
TeamCreate, SendMessage and model-invoked Skill. The existing guard independently
refuses these known launch/resume paths. Native main-loop reading, editing and shell
work retain their existing permissions; no broader permission is granted. Delegation
must use the existing Executive child path. An unavailable router means BLOCKED, not
permission to run a different CLI directly.

`native_leaf` admits only one invocation shape: root-level ROUTE census, named scout,
explicit Sonnet, and the existing complete commission contract. The generated `--agents`
override retains the existing scout instructions but exposes only Read/Grep/Glob,
medium effort and fourteen turns. There is no Bash, Write, MCP, Skill, Agent or messaging
in that leaf definition. Both `--settings` and `--agents` must be applied. The guard
rejects descendant launches, resumes, fork/leader types, ambiguous identity fields,
unknown launch fields, duplicate routes, malformed JSON and ambient model overrides.

The source profile explicitly sets the leaf default model to Sonnet and disables forced
subagent-model override. This is not a recommendation to spend the fleet's routine work
on Sonnet: it preserves the one existing native route for qualification only. General
execution belongs to the provider-neutral router and its already-qualified capacity.
Model allowlist fallback still requires observed requested/served equivalence before
this candidate is released.

Neither profile alters unprofiled session routing. No environment variable is installed
globally. Old sessions therefore are NOT protected by merely merging this source. A
profiled unexpected policy error fails closed; legacy behavior is intentionally not
silently rewritten in another worker's active environment.

### Deliberately incomplete fidelity, not a hidden compromise

Model-invoked Skill and native SendMessage are disabled in these strict candidates.
Otherwise a forked skill or resume can escape an Agent-only gate. Approved procedure
files can still be read as reference context; embedded commands do not gain authority
from being read. Full native skill use must return through qualification of the actual
resolved skill definitions, their model/fork behavior and their tool grants. This is a
required product gate, not a permanent decision to remove skills from Fable.

The environment concurrency value 4 is only a vendor hint. It does not establish a
four-worker budget under ultracode, and fourteen turns is a per-invocation limit, not a
session or account quota. No local JSON/SQLite counter is added to pretend otherwise.
The profile also is not an OS sandbox: native Bash, external MCP execution, manual user
commands, credentials and settings mutation require the existing managed host boundary.
Source hashes record inputs; they neither sign a grant nor prove effective runtime use.

## 5. Controlled pyramids, not exponential sessions

Target logical topology, proposed for later reviewed admission:

```text
L0  One principal/root responsibility, normally the already-running Fable
 L1  Bounded project leaders where coordination is independently useful
  L2  Optional subproject coordinators for genuinely separate deliverables
   L3  Leaf workers with no delegation authority
```

Depth counts delegation edges; it does not imply that every layer is populated. Most
work should be root -> worker. A coordinator is justified only when its decomposition,
local integration and independent return save more principal work than it creates.
A single census, file search, translation, test run or small patch is not such a case.
Do the deterministic operation directly when a new context would add no value.

Default additional Fable allowance is zero. A rare extra Fable principal is an explicit
Executive child admission within an existing root envelope, with evidence for why the
available cheaper class cannot meet the mission. It is not a native `FABLE-WHY` exception.
Use qualified economical leaders for scoped projects; use Fable for ambiguity and
integration that really need it. Avoid a compulsory reviewer or summarizer at every
layer: independent review is required where the acceptance policy demands it, not as
an automatic token multiplier.

An illustrative admitted tree could contain one root, two economical project leaders
and four leaf workers. The global envelope governs the whole tree. It is not two leaders
each receiving four new unrestricted slots. Provider concurrency is read from actual
capacity observations; no advertised plan limit is hard-coded from chat recollection.

## 6. Shared-budget and authority invariants

Implement these in the existing Executive admission/claim transaction and Capacity
owner, not in the CLI profile or Agent OS. The following are proposed requirements,
not claims about fields already present in production:

1. Every independently effectful child retains its canonical root, parent, attempt,
   policy revision, runtime binding and approved scope. A new provider session does not
   create a new organization identity or erase its ancestry.
2. For each comparable budget dimension, root spent plus outstanding reservations
   cannot exceed the admitted root ceiling. Child allocations partition the root's
   available allowance; allocations and reservations are not double-counted.
3. Reserve before starting. Concurrent siblings must atomically contend for the same
   remaining allowance. Reviews, repairs, continuation overhead and uncertainty margins
   consume reservations too. Preserve the existing COO reservation semantics.
4. Enforce both active concurrency and cumulative starts/attempts, plus depth and bounded
   execution time. A concurrency limit alone permits unlimited sequential spending.
5. Scope and capabilities can only narrow down the tree. Repository write paths,
   publication authority, network access, tools and further-delegation rights cannot be
   widened by a child prompt or by swapping providers.
6. Resume, repair and retry keep lineage and charges. They do not reset the grant. Release
   a reservation only from canonical terminal/no-effect reconciliation, never because
   a UI tab disappeared or a timeout was returned.
7. Different provider units remain different. Tokens, currency, rolling-hour requests,
   weekly allowances and concurrency slots must not be summed as interchangeable units.
   Missing, stale or unsupported quota is UNKNOWN, never zero usage or unlimited supply.
8. Cancellation propagates to the exact admitted descendants. A cancelled root does not
   leave orphaned spend; uncertain remote effects keep their reservations and carrier
   until the existing reconciliation path settles them.

The existing COO depth-one policy is closed. Do not weaken that policy in this source
PR. A later change must jointly review admission, reservation arithmetic, repair/review
capacity, restart recovery and all consumers before allowing deeper trees. Bumping
`max_depth` alone would be a false implementation.

## 7. Native environment and context delivery

Use the provider's supported native CLI behind the existing adapter; do not replace a
native coding session with a bare completion call and call it equivalent. Keep provider
configuration, auth realm and supported session mechanics adapter-private. Native app
windows are cockpits, not a new unattended execution authority. Preserve the selected
foreground sealed-CLI first vertical and its existing gates. [M3]

A launch consumes a bounded, source-pinned context package from the existing context
compiler and declared repository sources. It identifies the mission, parent/root,
acceptance, frozen interfaces, allowed paths, available tools/skills and budget view.
It is input to the existing attempt, not a new durable memory or session registry.

A worker receives only the relevant intent and evidence, not the whole principal
conversation. A subproject leader additionally receives the interfaces it owns, allowed
child classes and its slice of the root envelope. Cross-provider adapters materialize
only the skill formats and tools they can actually consume; unsupported capabilities
are reported as gaps before placement, not invented as model aliases.

Qualify native skills by resolved source and hash, not display name. Account, project,
managed and plugin sources can resolve differently. Check fork behavior, model changes,
injected shell commands, tool grants and load cost. Reuse the repository's existing
skill/agent material; do not create another skill catalog or blindly mount every MCP
server into every cheap worker. Keep credentials out of context and return packets.

Model selection uses the existing suitability classes first and current eligible
capacity second. A model cannot self-promote its task's difficulty label into an
unbounded premium route. Escalation returns concrete failed evidence or ambiguity to
the parent, whose bounded request is evaluated under the same policy. Root acceptance
stays separate from a worker's confidence or a green test.

## 8. Parent waiting and result consumption

The intended journey is: principal forms a small work package -> existing admission
reserves capacity -> existing broker launches the qualified adapter -> child returns
bounded evidence -> exact parent consumes the material event -> principal integrates
and proves the user capability. Do not add a second queue, inbox, retry daemon or
periodic Fable status prompt to connect those steps.

Return packets retain STATUS / RESULT / EVIDENCE / GAPS / DEVIATIONS and add existing
identity/usage metadata through canonical receipts, not hand-written status claims.
Large artifacts stay in their owner with immutable locators. A coordinator compresses
intermediate work but preserves contradictions and links; it cannot turn missing proof
into PASS. The principal wakes for a decision, blocker or meaningful result, not every
heartbeat. Idle orchestration should consume no new model turns.

A native transcript may resume only on the exact qualified binding under current law.
Compact/clear/resume must retain the profile, lineage and budget. New account sessions
must not reconstruct them from untrusted prose. EFFECT_UNKNOWN stays on the same carrier;
capacity availability is not permission to duplicate possibly-running work elsewhere.

## 9. Implementation order and acceptance

**Wave N0, this source candidate:** strict opt-in profiles, existing guard/context
extension, known-launch-surface coverage, before/after reproduction and source tests.
No activation is implied. The independently useful capability is compiling an auditable
native delegation restriction and enforcing it at the existing hook entrypoint.

**Wave N1, next critical vertical:** compose the principal profile through the existing
rich OperatorHarnessAdapter, capability and workspace owners, after reconciling their
current source contract and writer. Restore Executive read/admission/binding/capacity
before a real launch. The native configuration consumer is now fixture-qualified; a
registered rich Claude capability and real routed result are not. Observe effective
permissions and actual served model on the intended admitted realm. Prove one principal
-> existing router -> qualified economical child -> exact parent result, with real input
and a useful artifact. Do not call a loopback oracle the router or a native parent result
an Executive Job result. No new launcher service or quota database.

Mastermind #581's `ClaudeSubscriptionWorkerAdapter` is the sealed leaf floor: its
`_closed_settings` sets `disableAllHooks=true`, denies Agent/Skill/Bash, and its invocation
uses safe mode. Removing those restrictions to accept this principal profile would
change that owner's security contract. Preserve the leaf and rich-principal distinction.
Its interactive-only subscription profiles also cannot be promoted to unattended work
by this profile, a purchased plan or a successful local fixture. The protected capability
registry currently names Codex execution surfaces; this source compiler adds no registered
Claude surface. A healthy Executive connection alone does not close these source gaps.

**Wave N2:** re-enable qualified native skills and expose bounded child requests through
the existing CLI/tool facade. Prove a familiar native coding journey, including context,
file operations, scoped skills, interruption and return. Preserve the strict gate for
unqualified forked skills, workflow, teams and resume. A tool listed is not a tool proven.

**Wave N3:** extend existing COO admission/reservations for one bounded child leader and
its worker. Test competing sibling claims, cumulative starts, depth refusal, exhausted
reserves, failed review, restart and cancellation. Prove the three-node path before
permitting a four-layer topology; then prove one bounded four-layer case without lifting
all root ceilings. No recursive native Fable fan-out as an interim shortcut.

**Wave N4:** fleet pacing and observability through existing Provider Control/Capacity and
read-only projections. Show observed usage quality, remaining reservations, refusal
reasons and accepted outputs per spend unit. Demonstrate no materially worse output
quality than a native baseline while reducing avoidable principal overhead. Numbers
must come from observed comparable runs, not a claimed universal savings percentage.
