## 4. D2 — Content generation and permission version answer different questions

An immutable evidence generation identifies the content being explained. Current source/representation permission determines whether that content may be used or displayed now. They are not interchangeable versions.

Pin content once for a response. Obtain current permissions through the existing rights owner. Preserve the exact identity of the policy bytes and the parsed decision actually used. A repair that hashes newly read bytes but authorizes with an old cached mapping is still wrong: a fresh digest cannot certify a stale decision.

Before returning the private response, perform the owner's final entitlement/rights check. That check is the response-authorization boundary. A relevant policy change detected between loading and that boundary refuses the affected response; no old permitted payload or public copy substitutes for it. A change after that boundary applies to subsequent reads. Do not promise retroactive recall of bytes that were already lawfully delivered.

Historical evidence also uses current access permission. A request for an old observation date is not a request to restore an old license. If current permission forbids the requested representation, historical replay does not bypass that refusal. Existing entitled browser views clear their memory on logout or known entitlement loss and ignore obsolete in-flight responses, but cannot revoke a user's already-authorized screenshot or copy.

This clarifies R9's revocation requirement rather than weakening it. Tests should explicitly control the ordering of policy read, object load, final authorization and response release, so they do not accidentally pass by using a new process or clearing a cache.

**What closes D2:** same-process revocation, same-byte decision/digest consistency, mid-load restriction, historical-access restriction, and obsolete-response tests against the implemented existing owner. A fake test-only policy callback does not prove production policy freshness.

## 5. D3 — Corrections, permission withdrawal and ordinary source failure remain different

A correction changes what the source or house assertion says. It appends a new native revision with its predecessor, invalidating only dependent comparisons and explanations. A newer unrelated proposition does not supersede the old proposition. The NOVONIX pair remains the selected real case for that distinction.

A rights withdrawal changes what may be shown. It does not rewrite the historical fact into zero or claim that the underlying event never happened. A withdrawn or rejected assertion retains the history its owner lawfully permits retaining; the current view reports its appropriate unavailable or superseded state.

A transport/storage error establishes neither an empty dataset nor an economic absence. Strict not-found, failed read, invalid byte length, wrong content digest and unsupported object class stay distinct under the existing native error contract. Missing protected evidence never falls back to a public seed or stale cached body.

If one optional independent explanatory block is unavailable, the existing dossier can still render its unaffected legacy panels. But an incomplete selected positive case remains incomplete for V0 acceptance. A graceful degraded screen is a capability, not a waiver of the positive acceptance contract.

**What closes D3:** exact predecessor/descendant cases, independent-proposition survival, an authoritative empty result, explicit storage failure, and no-fallback proof. Source and response generations must be inspectable without exposing protected raw content through error details.
