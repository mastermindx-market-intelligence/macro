## 4. Alternatives resolved

**Wait for every shared dependency before any economic-core implementation.** This preserves integration safety but unnecessarily couples pure calculation work to storage, entitlement and page delivery. Retain the live dependencies at the adapter/release boundary, not as a prohibition on all deterministic implementation preparation.

**Reuse the entire Consumer Cyclical or Finance record.** Rejected. The numeric convention is useful, but the surrounding contract describes another bounded domain. Relabeling Materials is not reuse. No sibling engine is imported simply to obtain a minus sign or Decimal arithmetic.

**Move Materials claims to generic sector evidence records instead of GMI.** Not selected. Another registered schema's existence does not authorize a parallel source/review store or defeat the shared curation assignment. Any future explicit cross-owner bridge needs its own accepted semantics and real references; this document does not create one.

**Build the Materials-specific pure core, then connect accepted owner adapters.** Selected as the planning sequence. Existing F04 consumer paths remain the intended implementation location. Scalar conventions can be mirrored in that consumer's already-planned output contract, subject to review; no new shared scalar module or runtime schema registry is needed. The upstream exact-measure proposal AM1 remains necessary for the chosen GMI source path unless its owner accepts an equivalent representation.

The strongest objection is that a core written against provisional inputs can create rework or become a shadow data system. Bound that risk: limit it to immutable function arguments and returned explanations; no storage, source loading, fixture permission grants, identifier minting, API calls, background jobs or persisted current state. Separate conversion of admitted native records into those arguments. Do not freeze an upstream wire shape merely to save adapter work later.
