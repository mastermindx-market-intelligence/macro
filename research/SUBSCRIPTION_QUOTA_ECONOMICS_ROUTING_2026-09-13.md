## 0. Outcome and acceptance

The Chairman assigns an outcome, not a provider/account. An orchestrator requests a
semantic task class and receives a lawful route with the reason, relevant balances,
reset horizon, reserved headroom, and safe parallelism. Equivalent useful work uses
otherwise-expiring prepaid capacity before paid overage. Scarce models retain capacity
for genuinely difficult work. No extra reviews, repeated censuses, longer contexts or
invented jobs are created just to consume tokens.

Completion means fresh real account observations through the existing Provider Control
owner, an existing Executive claim and worker, a real accepted result, an explainable
Control Room/machine receipt, and measured reduction in manual quota instructions.
An offline forecast, green tests, an adapter, a draft PR or a merge alone is not that result.

This carrier supplies one independently usable capability: a deterministic one-shot
quota economics preview for source authors, with a CLI and executable scenarios. It
does not select or launch a Worker and cannot be consumed as live admission evidence.

## 3. Resource graph, not one percentage per provider

A route consumes a vector of provider-native resources: account-wide allowance,
model/subset allowance, short window, weekly window, billing-cycle pool, local/provider
concurrency and any authorized cash budget. Every applicable resource must fit.
A model alias can have several parents; the same subscription on two sessions or hosts
must still reference ONE shared pool. Account labels, process IDs and ordinal native
homes cannot establish shared-entitlement identity.

Bind observations to a reviewed opaque enrollment identity and generation. A plan,
key, membership or reset-generation change invalidates old joins and cost calibration.
Provider-reported values outrank estimates; late corrections update the existing owner
with source time and observation identity. Historical claim receipts are immutable.

Use native units. Requests, prompts, credits, tokens, percentage points and currency are
not interchangeable. A percentage-only observation may be modeled in percentage points
using separately calibrated costs; it never creates an absolute token allocation.
An advertised token estimate is not the live enforced limit. Unknown is not unlimited.

Keep true rolling release schedules distinct from first-use-anchored windows, fixed
calendar windows, billing cycles and nonexpiring credits. Passing a reset timestamp
invalidates the old balance until reobserved; a planning refill is not an observed refill.
A future shared-pool contract must be explicitly reviewed/versioned through the existing
capacity owner. Do not append fields to strict v1 or use this preview to bypass that work.

## 4. Allocation policy and intelligence

The target objective is accepted useful work subject to quality, authority, deadlines,
privacy, provider rules and budgets, with penalties for avoidable stranded capacity,
paid overage and rework. Raw token consumption is never a reward.

Hard gates are deterministic: approved model tier, review-family independence,
credential/enrollment validity, correct permitted harness mode, privacy policy, fresh
quota, all shared parents, concurrency, committed reserves, and no unknown Attempt effect.
An LLM can propose a decomposition or explain an outcome; it cannot waive these gates.

Cost estimates should use the existing Outcome Learning path: task class, model,
reasoning setting, context band, cache treatment, tools, duration and native quota delta.
Record uncertainty and sample count. Production reservations should use a conservative
upper estimate; unknown or weakly calibrated costs do not justify an aggressive burst.
Shared provider observations cannot attribute all concurrent consumption to one task.
Use completed-attempt usage where supported and interval reconciliation otherwise.
Never let an agent grant itself a stronger quality tier based on its own evaluation.

For a representative task, current startable work is the minimum native headroom/cost
across all resources, ready authorized jobs, and observed concurrency. Forecast useful
completions before each expiry with short-window releases, task duration and host limits.
The first source heuristic compares the achievable useful-work rate with a supplied
baseline rate. It is explainable, not a globally optimal stochastic scheduler. Missing
baseline means no claimed urgency inference. Forecasts for alternative models/accounts
are alternatives and MUST NOT be added when they share pools.

Future production demand forecasts must consider the existing ready queue, dependency
critical paths and already-admitted demand, not synthesize a second queue. Recompute on
meaningful events: task arrival/completion, new quota observation, cooling, policy/plan
change, reset or deadline. Use the existing supervisory cadence; no per-orchestrator
quota polling storm. Hysteresis and a minimum meaningful opportunity difference prevent
selection churn. Active Attempts remain bound to their carrier.

### Grok and Cursor

For approved equivalent build choices, Grok is preferred while it can perform the task
without breaking reserves, deadlines, independence or provider rules. Cursor becomes
the fallback for an eligible new task when Grok is unavailable for that task. A task
larger than remaining Grok headroom need not deliberately exhaust Grok to zero first.
No post-start automatic migration follows from a timeout or 429.

This is a strict Chairman preference, not an assertion that weekly always beats monthly.
If Cursor's cycle ends first, the system must surface the resulting stranded-capacity
risk rather than silently reverse the preference. Correct Cursor model/pool binding is
required; selecting a third-party model is not the same allowance as a Cursor model.

### Claude Fable and Opus

The Fable subset is a ceiling within the shared parent, not extra capacity. Protect
shared allowance for forecast high-ambiguity/Fable work before other models consume it.
For example, from a synthetic 100-unit parent with a 50-unit Fable ceiling, 30 units of
expected remaining Fable demand needs protection in the parent. Opus cannot consume that
protected amount. Both still stop if the shared parent is exhausted.

A 50:50 preference is a resource policy target, not a promise of equal token counts or
equal session counts. Use native cost weights and observed demand. Release a reserve only
under explicit reviewed policy when that class cannot use it before expiry; do not burn
Fable on trivial work or violate the role gate merely to reach a target percentage.
The preview accepts explicit reserves but does NOT yet learn or automatically release them.

### MiniMax, Alibaba, GLM and Codex

Use each actual product generation's short/long windows, credit multipliers and reported
reset anchors. Their plans are not one common '5h tokens' product. Adaptive parallelism
must respect observed slots and dynamic throttling, not the maximum of an approximate
marketing range. A weekly balance can be too large to consume through its remaining
short windows; show that honestly instead of promising full depletion.

Versioned time-of-use discounts can reduce native cost for flexible work. They must name
provider timezone, eligible model/tool, effective dates and verified plan generation;
do not apply a generic night discount. Do not delay deadline-critical work solely for a
discount, buy add-ons, redeem resets, or enable overage without the corresponding authority.
