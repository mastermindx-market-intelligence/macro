## G3. Multi-category membership

- **Ticker → multiple baskets is already legitimate and pervasive.** The US membership file has **264 of 708 all-history distinct members in more than one basket** and **1,038 all-history ticker→basket paths**; the active snapshot has **1,020 paths across 702 members**. The file is `data/baskets/membership.json:baskets`; computation: `len(paths)=sum(len(members))`, `tickers=len(set(members))`, `multi=sum(1 for t if occurrences > 1)`.
- **The house’s current multi-parent handling differs by surface.** The graph keeps multiple `MEMBER_OF` rows and lets consumers compose paths; F04 follows each basket path and returns typed abstentions rather than merging ownership (engine/market_ontology/exposure_map.py:575 and engine/market_ontology/exposure_map.py:880). Neural Web’s context vector stores the full basket-id list at engine/us_context_vector.py:948, then reduces the display pulse to the best-ranked basket at engine/us_context_vector.py:435. Sector Map uses “first basket wins” for its display subsector arm at engine/neuralweb/sector_map.py:146. Theme pathways use multiple `basket_refs` where a node has multiple group anchors.
- **Basket/theme multi-category:** a basket has one legacy `category` and one legacy `parent` display label in the membership file, while the theme crosswalk can express one theme from many baskets. Hierarchy V1 permits a child to have at most three parents, so a micro can legitimately belong to several categories or themes; the graph does not require a single-parent tree.
- **What is missing inside the law:** V1.1 can represent up to three micro parents, but there is not yet (a) a frozen category vocabulary that resolves the overlapping legacy labels, (b) declared basket→micro or evidence-source→micro wiring, or (c) tier-aware consumers. Those are required before multi-category research roll-ups can use micros. Per DEC:GMI-THEME-HIERARCHY-ON-CROSSWALK, ticker classification remains read-time composition, never a stored company→category or company→theme edge.
- **No vendor laundering:** finviz_themes and ths_concepts may be compared only under their internal-only families. They cannot supply names, membership or parents for a house category/micro. Binding language is quoted in G5.

## G3. Multi-category membership

- **Ticker → multiple baskets is already legitimate and pervasive.** The US membership file has **264 of 708 all-history distinct members in more than one basket** and **1,038 all-history ticker→basket paths**; the active snapshot has **1,020 paths across 702 members**. The file is `data/baskets/membership.json:baskets`; computation: `len(paths)=sum(len(members))`, `tickers=len(set(members))`, `multi=sum(1 for t if occurrences > 1)`.
- **The house’s current multi-parent handling differs by surface.** The graph keeps multiple `MEMBER_OF` rows and lets consumers compose paths; F04 follows each basket path and returns typed abstentions rather than merging ownership (engine/market_ontology/exposure_map.py:575 and engine/market_ontology/exposure_map.py:880). Neural Web’s context vector stores the full basket-id list at engine/us_context_vector.py:948, then reduces the display pulse to the best-ranked basket at engine/us_context_vector.py:435. Sector Map uses “first basket wins” for its display subsector arm at engine/neuralweb/sector_map.py:146. Theme pathways use multiple `basket_refs` where a node has multiple group anchors.
- **Basket/theme multi-category:** a basket has one legacy `category` and one legacy `parent` display label in the membership file, while the theme crosswalk can express one theme from many baskets. Hierarchy V1 permits a child to have at most three parents, so a micro can legitimately belong to several categories or themes; the graph does not require a single-parent tree.
- **What is missing inside the law:** V1.1 can represent up to three micro parents, but there is not yet (a) a frozen category vocabulary that resolves the overlapping legacy labels, (b) declared basket→micro or evidence-source→micro wiring, or (c) tier-aware consumers. Those are required before multi-category research roll-ups can use micros. Per DEC:GMI-THEME-HIERARCHY-ON-CROSSWALK, ticker classification remains read-time composition, never a stored company→category or company→theme edge.
- **No vendor laundering:** finviz_themes and ths_concepts may be compared only under their internal-only families. They cannot supply names, membership or parents for a house category/micro. Binding language is quoted in G5.
