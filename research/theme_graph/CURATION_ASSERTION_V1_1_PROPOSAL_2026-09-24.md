## 3. `observation` — discriminated two-branch union

```json
"observation": {
  "type":"object", "required":["kind"],
  "allOf":[
    {"if":{"properties":{"kind":{"const":"numeric"}}},     "then":{"$ref":"#/$defs/observation_numeric"}},
    {"if":{"properties":{"kind":{"const":"non_numeric"}}}, "then":{"$ref":"#/$defs/observation_non_numeric"}}
  ],
  "properties":{"kind":{"enum":["numeric","non_numeric"]}}
}
```
(Each `$defs` branch carries `required:["kind"]`, `kind` as `const`, and `additionalProperties:false`; each `if` also carries `required:["kind"]` so an empty object fails ONLY on the wrapper's `required` (no vacuous branch errors); the wrapper itself closes with `unevaluatedProperties:false`. The validator therefore reports the real cause — `required`, `enum`, `additionalProperties`, `type`, `pattern` — never "not valid under any of the given schemas". The code layer selects the same branch on `kind` before its own rules. **`value` uses the same construction one level down:** `{"shape":"point","point":"<decimal>"}` or `{"shape":"interval","interval":{…}}` — `required:["shape"]`, `const` branches, `unevaluatedProperties:false` on the wrapper; a body carrying both `point` and `interval`, or neither, is refused by the code layer as `value_shape_invalid` first (R12 §4.3 "conflicting scalar/range values"); the schema's second fence is the selected branch's `additionalProperties` at `value` (verified).)

### 3.1 `observation_numeric`
```json
{ "kind":"numeric",
  "measure_class":"physical_count|physical_quantity|physical_change|financial_amount|financial_change|ratio_level|ratio_change|unit_price|royalty_rate",
  "value": {"shape":"point","point":"<decimal>"} | {"shape":"interval","interval":{"lower":"<decimal>"|null,"upper":"<decimal>"|null,"lower_inclusive":bool|null,"upper_inclusive":bool|null}},
  "unit_label":"<minLength 1>", "currency":"^[A-Z]{3}$"|null, "currency_scale":0|3|6|9|null,
  "quantity_basis": <v1 enum>|null, "gross_net_basis":"gross|net"|null, "stock_flow":"stock|flow"|null,
  "denominator":"<text>"|null, "provenance":"reported|derived|target", "approximate":bool }
```
- `<decimal>`: string `^-?(0|[1-9][0-9]{0,29})(\.[0-9]{1,12})?$`; JSON numbers refused (code `decimal_string_required`, then schema `type:string` — a float is not the source's decimal); format failures → code `decimal_format_invalid`, then schema `pattern`; `-0`, `-0.0…` refused (code `negative_zero_invalid`); lexical precision kept.
- Interval: at least one of `lower`/`upper` non-null (code `interval_unbounded_both`); a null bound is a TYPED, explicit "the source states no bound on this side" ("at least 1,000", "up to $50m") — this is the only admitted unbounded endpoint, argued here against R12 §4.2's ban on smuggled infinities (NaN/exponent) precisely because it is declared, not numeric; the matching `*_inclusive` flag MUST be null when its bound is null and boolean otherwise (code `interval_inclusivity_invalid`); when both bounds present `lower ≤ upper` (code `interval_disordered`); an interval is never collapsed to a midpoint; **no same-sign restriction** (a source-stated "-2% to +3%" is valid).
- Sign law (code `sign_not_allowed`): `physical_count` → integer string, no `-`; a non-percentage or above-base royalty mechanism (fee exceeding the base, clawback, tiered-by-formula) is NOT forced into `royalty_rate`: the component's `rate` becomes `non_numeric/qualitative` with the source wording and `mechanism_text` carries the mechanism (R12 §4.2); `physical_quantity`, `unit_price` → no `-`; `physical_change`, `financial_amount`, `financial_change`, `ratio_level`, `ratio_change` → signed; `royalty_rate` → `unit_label == "percent"` and `0 ≤ value ≤ 100` (code `royalty_rate_out_of_range`; `unit_label: "percentage_point"` on a `royalty_rate` → `unit_class_mismatch`).
- Denominator law (code `denominator_required`): `ratio_level|ratio_change|unit_price|royalty_rate|physical_change` require `denominator` (for `physical_change`: the base population/period the change is measured against).
- Currency law (codes `currency_required` / `currency_forbidden`): `financial_amount|financial_change|unit_price` require `currency` and `currency_scale`; all other classes require both null. `currency_scale` = decimal exponent applied to `value` (`3` = thousands, `6` = millions, `9` = billions; `0` = units) — pinned in the schema description.
- Basis law (replaces v1's `quantity_basis_required` per class; TOTAL over the nine classes; codes `quantity_basis_required` / `quantity_basis_forbidden`): `physical_count|physical_quantity|physical_change|unit_price` require non-null `quantity_basis`; `financial_amount|financial_change|ratio_level|ratio_change|royalty_rate` require `quantity_basis` null and carry their scope in `denominator`/`industrial_context.measure_scope`. (`unit_price` requiring both a basis and a denominator is deliberate: the basis says what one unit is, the denominator says per what the price is quoted.)
- Unit/class coherence (code `unit_class_mismatch`): `financial_amount|financial_change` require `unit_label == currency`; `unit_price` is exempt from that rule (its `unit_label` names the priced unit, its `currency` the money); `ratio_*` require `unit_label ∈ {percent, percentage_point, ratio}`; `royalty_rate` requires `percent`; `percent` vs `percentage_point` never interconverted.
- Denominator law is TOTAL: `ratio_level|ratio_change|unit_price|royalty_rate|physical_change` require `denominator`; `physical_count|physical_quantity|financial_amount|financial_change` may carry `denominator` or null (a stated base is kept, never required).
- `provenance`: `reported` (stated outcome) | `derived` (source's own computation) | `target` (source-stated aim; never promoted by time — pinned by P8).
- Documentation-only mapping from v1's flat shape (no migration code): `value/value_high` → `point`/inclusive `interval`; `unit` → `unit_label`; `estimate_status: estimated` → `provenance: derived`; `precision: approximate` → `approximate: true`; `precision: range` → interval; `integer|decimal` → the decimal string itself.

## 4. `economic_right` (required iff `REPORTED_ECONOMIC_RIGHT`)

```json
{ "parties":{"payer":<label|null>,"recipient":<label|null>,"grantor":<label|null>,"grantee":<label|null>},
  "asset_scope":{"asset_label":<text>,"indication":<text|null>,"territory":<text|null>,"activities":["develop","manufacture","commercialize","sublicense","other_stated"]},
  "arrangement_state":"announced|operative|contingent|amended|terminated|unknown",
  "components":[<component>,…],            // minItems 1; component_selector unique (existing code family duplicate_local_selector)
  "missing_material_terms":["rate","amount","denominator","tier_method","loss_participation","cost_bearing","territory","term","thresholds","component_dependency"] }
```
`<component>`:
```json
{ "component_selector":<source-local id>, "component_kind":"royalty|profit_share|upfront|milestone|service_fee|cost_share|other_disclosed",
  "denominator_kind":"net_sales|gross_sales|profit|units|fixed|other_stated|unknown", "denominator_text":<text|null>,
  "net_of_selectors":[<component_selector>…],          // which earlier components/deductions the base is net of (R12 waterfall); [] when none or unknown
  "tier_method":"flat|marginal|whole_base|unknown|not_applicable",
  "tier_steps":[{"threshold":"<decimal>","threshold_unit":<text>,"rate":<observation union>}] | null,   // structural tiers when disclosed
  "rate":<observation union>,                            // numeric royalty_rate|ratio_level OR non_numeric (not_disclosed / qualitative / not_applicable)
  "amount":<observation union>|null,                     // numeric financial_amount OR non_numeric
  "loss_participation":"included|excluded|unknown|not_applicable",
  "cost_bearing":<text|null>,
  "triggers":[{"kind":"threshold|milestone|date|approval|expiry|other_stated","description":<text>,"business_effective":<date|null>}],
  "mechanism_text":<text|null> }
```
Laws: parties are source-scoped labels (`subject.company_node_id` stays the only canonical identity); a `royalty` or `profit_share` with `rate.kind == non_numeric` and `state == not_disclosed` is **valid** and is exactly what `missing_material_terms:["rate"]` records (no rule forces `mechanism_text`); `profit_share` requires `loss_participation ≠ not_applicable` (code `loss_participation_not_applicable_on_profit_share`); `tier_method ∈ {marginal, whole_base, unknown}` with `tier_steps: null` → `missing_material_terms` must contain `thresholds` (code `tier_thresholds_unrecorded`); observation-level `denominator` inside `rate`/`amount` must equal `denominator_text` when both present (code `denominator_inconsistent`); `net_of_selectors` must reference existing selectors (code `unknown_component_reference`); `amount: non_numeric/not_disclosed` on a component requires `amount` in `missing_material_terms` (code `missing_term_unrecorded`) — this is where the R12 waterfall dependency lives structurally, and the double-count hazard is named by `component_dependency` in `missing_material_terms` when the source does not say. No payout, effective rate, look-through or consolidated field exists.
