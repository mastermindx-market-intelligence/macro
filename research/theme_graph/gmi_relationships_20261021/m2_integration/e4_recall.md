## Regeneration command

```sh
RC=research/theme_graph/gmi_relationships_20261021/m2_recall
W=<scratch outside data/ and site/>
rm -rf $W/recall; mkdir -p $W/recall/wd/D1 $W/recall/wd/D2 $W/recall/ann
for d in D1 D2; do cp $RC/$d/sentences.jsonl $W/recall/wd/$d/; \
  for f in $RC/$d/annotations/*.jsonl; do cp "$f" "$W/recall/ann/${d}_$(basename $f)"; done; done
TZ=UTC python3 scripts/relationship_m2_recall.py compare \
  --workdir $W/recall/wd --annotations $W/recall/ann --report $RC/recall_report_v1.json
```

## Known limits, in plain words

- The reference key is the triple (subject issuer, species, counterparty
  issuer-or-name key). It does **not** compare direction or period: a pipeline
  row that states the same pair in the opposite direction, or in a different
  fiscal period, still counts as a hit.
- The reference set only contains relationships an independent reader found
  with the recall lexicon inside the fetched documents. A relationship whose
  wording matches neither the harvester cue patterns nor the recall lexicon is
  invisible to both sides and its miss is **not measured**.
- Counterparties that resolve to no US issuer enter the key as
  `name:<normalized text>`, so a spelling variant can turn one true
  counterparty into a miss and an unrelated mention into a hit.
- Precision is never used as a recall proxy, and recall is never used as a
  precision proxy; the two are separate measures.

## Fail-closed rule

E4 prints MEASURED only when the report exists, parses as the pinned schema,
carries every required field, and its `corpus_sha256` / `lexicon_sha256` /
per-file `extraction_sha256` pins still match the committed corpus, lexicon
and extraction bytes. Any other case — report absent, malformed, wrong schema,
corpus drift, lexicon drift, extraction files changed/missing/added — prints
`state=OWED` with the reason and `value=None`. A stale number is never
printed; nulls are printed, not papered over. E2's caveat now points at E4
instead of claiming recall is OWED.
