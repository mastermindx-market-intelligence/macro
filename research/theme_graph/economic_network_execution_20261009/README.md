# Economic relationship execution: first native inspection increment

This increment turns the completed economic-network research into an executable
Company Intelligence analyst capability. It inspects a manually asserted
relationship against held source bytes and returns a structured review result.
It does not produce admitted relationship truth or a served Graph1 hypothesis.

Research source: [PR #8661](https://github.com/mastermindx-market-intelligence/macro/pull/8661),
immutable head `2015e427ed4690f5a2778f63a825c2cdec4d8ac0`. The complete architecture,
casebook, sourcing strategy, evaluation design and WP00–WP10 masterplan remain
there. This implementation does not duplicate them.

## What can be done now

Run a real file-input inspection:

```bash
python3 -m engine.company_intelligence.relationship_candidates \
  --candidate /path/to/manual-candidate.json \
  --source /path/to/original-disclosure.html
```

The consumer checks the closed input shape and native flat span receipt, replays
the complete supplied UTF-8 source and exact cited range, and returns an
`INSPECTABLE` candidate when the input is structurally usable. Source-local names
and product scope must occur in the replayed text. This is a mechanical anchor
check, not independent semantic entailment or legal-party resolution.

The review result separates the manual assertion, source-byte consistency,
document metadata authenticity, native adoption, identity, timing and rights.
Missing production eligibility does not erase a useful current candidate.
Malformed evidence produces a bounded refusal rather than a substituted relation.

The initial taxonomy distinguishes product integration, supplier roster,
framework agreement, administrative party, anonymous counterparty, thematic
similarity and market correlation. It preserves their different meanings:

| Input | Review consequence |
|---|---|
| Planned product integration | Product-scoped manual candidate; no shipment or revenue claim. |
| Framework agreement | Framework candidate; executed deliveries and amounts remain unknown. |
| Supplier roster | List observation; no allocation across listed suppliers or all products. |
| Administrative party | Administrative role; no operating supplier relation. |
| Anonymous counterparty | Counterparty remains null and unresolved. |
| Similarity or correlation | Non-relationship observation; no economic edge. |

These are local candidate-review categories, not a replacement economic ontology.
Unsupported kinds must be handled by a later owned adapter, not forced into the
closest category. All canonical identity, shipment, revenue, economic weight and
theme-membership fields remain null. Every authority axis remains false and
`admission` remains `NOT_ADMITTED`.

## Input and trust contract

The top-level schema is `company_intelligence.relationship_candidate/v1` with
exact keys:

| Field | Meaning |
|---|---|
| `candidate_id` | Caller-assigned candidate reference, not an admitted fact ID. |
| `document` | `document_id`, string `version`, `source_ref`, nullable ISO `published_date`. |
| `dataset_id` | Nullable native dataset reference. A supplied name is not adoption. |
| `temporal_row` | Nullable source-bound native row for the optional cutoff probe. |
| `receipt` | Existing `earnings_release.span_receipt/v1`, generated by its native owner. |
| `assertion` | `kind`, `subject_label`, nullable `object_label`, `product_scope`, `lifecycle`, null `magnitude`. |
| `revision` | Original/corrects/contradicts plus the prior candidate reference where applicable. |
| `identity_annotations` | Null or supplied subject/object IDs; always untrusted annotations. |

Document URL, date, version and labels are caller annotations. The inspector does
not fetch or authenticate them. A matched body hash proves consistency with the
supplied body, not that the URL served that body or that the issuer authored it.
The real-source witness separately records the original retrieval and its limits.

Use a string source-version handle such as `sha256:<original-body-digest>`.
Do not invent an earnings event to satisfy a standalone issuer announcement.
Construct a flat receipt with the existing owner:

```python
from engine.earnings_release.receipts import receipt_for_char_span, sha256_text

receipt = receipt_for_char_span(
    source=original_utf8_text,
    source_sha256=sha256_text(original_utf8_text),
    char_start=selected_start,
    char_end=selected_end,
).to_dict()
```

The original bytes must strictly decode and round-trip as UTF-8. No HTML cleanup,
PDF extraction, whitespace rewrite, or encoding replacement may be presented as
the original source. A transformed document needs its actual native transform and
source lineage; this increment does not provide that adapter. The CLI bounds the
source at 4 MiB and the candidate file at 256 KiB.

### Text and rights

By default the API and CLI omit the dedicated machine-replayed support text.
They still return caller-provided annotations, which may themselves contain
source text. **This is not a quote-free or public-safe export guarantee.**

`--include-support-text` requests local analyst replay of already supplied text.
It does not grant display, redistribution, retention, embedding, training or
evaluation rights. Production consumers must use the existing source-policy and
entitlement owners; they cannot infer permission from successful replay or from
the absence of the dedicated support field. Original third-party bodies are not
part of this Git deliverable.

### Time

An optional `--as-of` requires a timezone-aware instant and an explicitly supplied
native registry. The profile must be produced, unambiguous, and declare the
candidate/document/version grain and source-hash binding used by this bounded
probe. An unrelated identity, price, or PG profile cannot be borrowed.

The wrapper validates the supported row shapes and delegates clock interpretation,
knowability and cutoff filtering to `lib.dataos.temporal`. DATE period labels stay
DATE labels; they are never promoted to midnight instants. Missing/naive clocks,
malformed required fields and DERIVED-only historical requests refuse. Filtering
or refusal occurs before constructing a semantic relationship view.

For this probe, `revision_seq` is a nonnegative integer, `code_version` is a
nonempty string, `input_cutoffs` is a nonempty mapping of named inputs to native
aware instants, and cutoff/expiry instants use native UTC validation. These are
explicitly bounded input requirements, not a universal replacement native schema.

Even a successfully filtered row is **supplied-row inspection**, not authenticated
historical source state or a replay of what the system served. The current native
catalog has no issuer-disclosure relationship dataset. The real Micron witness
therefore produces useful current inspection and refuses a historical request.

### Corrections

Correction and contradiction references remain in the candidate view. This pure
function never erases an original, chooses a latest revision, treats feed omission
as termination, or averages conflicting assertions into a confidence score.

## Real-source witness

The demonstration uses the original Micron announcement dated 26 February 2024.
Its selected clause concerns planned use of a particular HBM3E configuration in
NVIDIA H200. It does not establish completed purchases, exclusivity, a supplier
revenue share, or the present status of every product relationship.

The source body was retrieved on 9 October 2026. That retrieval is not evidence
that this system held these exact bytes in 2024. `MICRON_SOURCE_CASE.json` records
the source URL, exact retrieved-body digest and exact native span address without
redistributing the original body. `replay_micron_witness.py` reconstructs the
native receipt only when the supplied original source matches that digest and
then runs the actual file-input CLI in current and historical modes.

```bash
python3 research/theme_graph/economic_network_execution_20261009/replay_micron_witness.py \
  --source /path/to/the-held-original-micron-html
```

The expected current result is `INSPECTABLE / NOT_ADMITTED`, product-only and
planned, with null quantities and no Graph1 projection. The historical request
must return `AS_OF_REGISTRY_REQUIRED` with no candidate view, source provenance
or support. A changed source body must refuse before a new receipt is minted.

The public URL can later change its body, page scripts or wrapper. A mismatch
does not authorize refreshing the expected hash or silently accepting a different
revision. Obtain the retained source from its lawful holder or record a separate
new capture and review. Independent replay depends on access to those exact bytes;
the published digest alone does not recreate them.
