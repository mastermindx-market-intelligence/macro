## 3. Mechanisms actually implemented

### Historical set reconciliation

The synthetic model supports a D snapshot or an earlier/later anchor with complete reversible before/after events. It verifies the supplied seven-jurisdiction partition inventory, source-array bindings, exact member-ID inventories, coverage endpoints, all six event-kind declarations, unique event IDs and effective order. Forward application checks each before state; reverse application checks each after state. It then compares full reconstructed and target states, including missing IDs, extra IDs and same-ID differing states.

The test with one missing and one extra member has unchanged counts and still fails. A post-D removal is reversed to restore the omitted D member and reproduces the original modeled selection. A reversed transfer with the wrong current after-state fails before it can manufacture a plausible historical set. A current-only survivor directory remains held even with consistent rows and all approval-looking flags true.

One-to-one events have explicit changed-field limits. Transfer cannot secretly change issuer identity or primary status; conversion cannot secretly move partitions. Compound changes require separately ordered events. This is a deliberately narrower artificial state machine, not a generic parser of every exchange's event semantics. The model has explicit artificial date boundaries; real venue timezone, close-of-business semantics and historical perimeter authority remain unverified.

### Assertion resolution, measurement ordering and revision consistency

Shares, raw prices and FX use point bundles. The enclosing issuer/class/component determines the comparison scope, so publisher names and publication recency cannot split same-fact disagreements into separate facts. Assertion IDs cannot be reused across components. Post-K assertions and estimates are retained as exclusions. The greatest eligible measurement date is selected before any correction decision. A conflict at that latest date cannot fall back to an older clean date. An old conflict outside a self-contained newer measurement remains visible.

The model supports same-publisher, same-scope supersession and retraction with exact supplied relation-token bindings. All referenced assertions must exist, publication ordering must be coherent and applicable supersession edges must be acyclic. A correction does not silently remove a separate publisher's competing assertion. Aliases retain their provenance and do not count as independent agreement. A retraction with no remaining value produces unavailable. Relation labels, owner strings and matching tokens remain unauthenticated model claims.

The lower-level assertion helper also tests overlapping persistent numeric states: different starts do not erase an incompatible state applicable at D. Cross-interval persistent transitions and cross-publisher reconciliation remain typed unsupported holds. The actual public capitalization contract requires POINT bundles for shares, prices and FX.

Every successful or conflicting resolution receipt retains all supplied assertions, their publication and valid/measurement coordinates, original value token, publisher, unit basis and source span. It binds the complete supplied bundle's canonical content and retains active/excluded assertion IDs and the relation graph. This is auditability of the supplied bundle, not a claim that the bundle exhausts all public evidence.

### Exact capitalization and unit controls

The implemented class is an ordinary positive-valued economic class. Multiple declared classes are summed only when every class resolves; missing, duplicated, unsupported or unpriced class semantics hold the whole issuer. The kernel recognizes ADR, unlisted-proxy and zero/ceased-class requests and returns a specific richer-contract hold instead of omitting them.

Positive-role parsing applies to actual share measurements, raw price, scale, FX and split factors. Additive deltas preserve their sign. Zero delta additionally needs an explicit supplied no-change token; a generic true flag cannot substitute. Booleans, nonfinite inputs, binary floating point, exponent strings, rational-fraction strings, whitespace coercion and unsupported decimal syntax refuse. Resulting positive-class shares and final cap must remain positive.

The signed-retirement control gives `(100m−10m)×20=1.8b` and the unchanged absolute S tag. It does not produce the incorrect 2.2b result obtained by applying an absolute value to the retirement. The split test uses a post-split share count and a stale pre-split raw price; the price is explicitly divided by two. Missing bridge IDs, wrong basis, unknown quantities, duplicate action IDs/order, nonpositive factors and unresolved same-day action timing all hold the full cap.

Share measurement age is capped at 183 days. Raw price requires both the ten-calendar-day and five-supplied-scheduled-session limits. FX uses a single supplied common ECB reference date within five days, verifies the prescribed currency-per-EUR direction, and converts by USD-per-EUR divided by X-per-EUR. It does not insert a peg, use a different currency/provider/date or fall back to a convenient old clean quote. Actual calendar, counter-choice, source semantics, publication provenance and undisclosed-event completeness remain unverified.

## 4. Resource and refusal behavior

The JSON envelope is limited to 2 MiB, output to 8 MiB, records to 512, supplied sources to 1,024 and each source to 256 KiB. Other explicit limits include eight classes per record, 16 assertions and 32 relations per bundle, 32 actions per class, 1,024 membership events, 128 partitions/cases, depth 24 and 160,000 pre-parse structural tokens. Decimal text allows at most 48 integer digits and 24 fractional digits; integer JSON literals allow 12 digits.

Derived rational numerator/denominator bit lengths are bounded to 8,192. The cap bridge, price transformation, FX division and class sums are checked against that limit. This avoids accidental dependence on an interpreter's integer-to-string conversion ceiling. Exceeding the bound holds the full result; it is not a valuation eligibility rule or a reason to omit a class.

Unknown/missing/invalid cardinality values retain separate states. Only an actual nonnegative integer excluding booleans can be a supplied count. `NOT_PUBLISHED` is distinct from zero and allowed only for the source-declared total, with the supplied exhaustive-total reconciliation still required. Even a matching count remains a supplied-data statistic, not authenticated population truth.

The output encoder accounts for UTF-8 bytes and explicitly refuses an oversized result. It returns a small null-synthetic refusal instead of truncating records or certificates. The CLI reads bounded regular files with no final-component symlink following, emits JSON and deliberately exits 2 for every NOT_READY result. That exit is expected for a successful artificial calculation and is not represented as real readiness.
