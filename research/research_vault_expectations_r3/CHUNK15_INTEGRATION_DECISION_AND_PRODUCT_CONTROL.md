## 1. Selected design — stop leaving the gateway shape open-ended

The following is Sol's design selection for the research/adoption packet. It is **not** source-use permission, a release decision, an accepted worker assignment, or evidence that the runtime implements the contract.

### A. Reuse the existing tool; default behavior stays compatible

Retain `search_research`. The proposed optional request field is `evidence_scope`, a closed choice of `catalog` (default) or `source_text`. Existing calls that omit it retain their metadata behavior. The field expresses requested depth, never authorization. Final schema placement must be reviewed against complete current gateway/Brain files; no runtime schema was changed here.

Source-text discovery is an explicit request; no-match in metadata must not silently escalate privileges or cost. It requires the current report-level product gate AND the existing source owner's positive use decision before any body-conditioned identifiers or snippets are produced. An Essential metadata user is neither silently upgraded to body access nor forced into the webpage's unrelated preview policy.

### B. The gateway constructs a fresh private source check for every read

The R14 `make_guard` closes over `verified_source=False` and can cache original-byte verification for the life of that closure. Therefore adoption must construct it **inside each admitted tool invocation**, from server-derived principal/context and the current source owner. It must not reside in a singleton, module cache, conversation object or model-supplied argument.

The selection is untrusted reference data: report, query and expected versions. It is not a bearer grant. The source owner's current eligibility and versions must agree at read time. Private functions/callables do not become JSON tool fields.

This is a source-derived lifecycle constraint, not a passing cross-request or concurrent-revocation test. The eight R14 cases are still NOT_RUN. No alternate host, actor or sandbox was used to rerun them. Completion of that hold needs its original lawful resolution path.

### C. Source and allowance responsibilities remain distinct

Use existing strict bounded object reads before unbounded buffering, and keep selected PDF/body/catalog coherence. On change, require explicit rediscovery rather than silently opening another version. Keep the current reader's one final response-budget/debit path; do not retain a second bridge debit.

Preserve the allowed final slot, subsequent exhaustion, existing fail-open meaning and uncertain-effect handling. An allow result is not a persisted-debit certificate. Do not manufacture refunds or repeat an uncertain debit. This phase does not reexecute those previously tested cases or claim new assurance.

### D. Integrate the real consumer, not another callback framework

One implementation outcome: a permitted body-only company question finds its report through the existing Brain, opens literal support and produces a useful answer. An internal selection or populated company field is insufficient. Current issuer/security identity, metadata users, canonical source/storage and view accounting remain authoritative.

No new corpus, entitlement ledger, publication authority, cache service, replay plane, queue or general-purpose graph is commissioned. No model/provider call is authorized by this design packet. No R14 guard should be deployed as a standalone permission service.

## 2. Why the real-source control changes the intelligence contract

The new control uses five current-accessed official issuer pages across Microsoft, Meta and Amazon. It has 26 manually entered numerical facts and 12 draft answer tasks. It is assistant-authored research over public pages, not acquired MarketDesk material or an automated model benchmark.

The complete analysis lives in `CAPEX_RESEARCH_BRIEF_R15.md`. Its three interpretation traps are:

- a reported measurement-basis change must not become a claimed fall in underlying investment;
- raising only a range's lower endpoint must not become a uniform or probabilistic forecast change;
- cash-flow definitions, time windows, lease flows and pre-/post-tax profit measures must not be silently mixed.

The important contract addition is **reported-number change versus economic-thesis change**. Same entity/currency/target is necessary but not sufficient. A measurement change is useful intelligence and should produce an explanatory card, not vanish merely because the numerical series is noncomparable. Preserve the issuer's explanation as attributed, not independently validated physical-demand truth.

A material capex revision can reflect scope, classification, component prices, delivery timing, capacity quantity or a combination. Where the source does not quantify the decomposition, leave components unknown. Do not guess that the residual is volume, or convert the headline into a supplier trade call.
