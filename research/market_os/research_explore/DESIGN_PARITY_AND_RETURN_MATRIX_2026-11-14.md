## 5. Shared interaction contract

| Interaction | Required retained state | Design evidence | Later implementation proof |
|---|---|---|---|
| Open evidence/detail | Domain entity/case, source cut/version, applied filters and selected measure | Selected inspector and its originating view | Authorized exact source response; no stale cross-entity content |
| Close/Escape/Back | Invoking control, selected row, scroll and chart cursor/window | Readable close/return affordance | Real keyboard focus and browser traversal |
| Switch universe/mode/basis | New compatible identity plus recoverable prior selection | Control, selected state and meaningful loading/refusal | Correct request keys; old responses cannot render under new labels |
| Change locale/theme | Semantic value, units, identity and active state | Representative difficult labels/charts in both treatments | No truncation, contrast failure, focus loss or unit/date corruption |
| Refresh/correction | Original viewed snapshot remains distinguishable from newer evidence | Version comparison/notice and choice | Retained source bytes, dependency identity and explicit adoption |
| Partial resource failure | All independently valid sibling content | Scoped recovery view | Retry only the failed resource, bounded and cancellable |
| Save/restore | Original target and known effect state | Confirmed, unconfirmed, unavailable and conflict distinctions | Same-owner account effect, reconciliation and privacy |
| Permission changes | Safe return context without private data leakage | Scoped unavailable/re-auth state | Server enforcement; neutral foreign/absent behavior where required |

The detailed family contracts override generic behavior where their existing owner law is stricter. In particular, Capital focus-only changes use replaceState without changing its calculation tuple; China family/entity must restore together, including basket → sector traversal. No second router, local persistence authority, job queue or account owner is introduced.

## 6. Design-phase closure gate

Before frontend/engine implementation begins, reconcile the full existing-feature disposition across all twelve destinations. Every retained capability needs a named product home or an explicit progressive disclosure; every missing producer contract needs a typed unavailable state and an implementation owner. Do not quietly remove a difficult feature because the main view is cleaner.

Review meaningful workflows, required responsive/theme/locale specimens, source/basis and date precision, disabled/loading/empty/partial/error/access states, selection/focus/history return and saved-effect semantics. Confirm the frozen Capital acceptance matrix and any current release holds. Preserve all foreign/held Paper carriers.

Complete design-phase acceptance is distinct from working interactions. The later Terminal build must prove real producer → authenticated consumer → exact evidence → persistence/return journeys, deployed revisions and actual browser behavior. Static fixtures, CI or a draft PR do not establish production readiness.
