## 1. Diagnosis and specific supersession

The preceding local design solved visual noise but overcorrected toward an equal-weight chronological log. Important differences, decisive evidence qualifications and concrete next steps were not exposed sufficiently. Generic headlines and repeated investigation actions made the user do the analyst's job. Geometry checks and many mockup states did not establish useful comprehension.

**Compress the mechanics, not the decision-useful content.**

The following presentation choices in `MACRO_ALERTS_MARKET_CHANGES_DESK_EXPERIENCE_FREEZE_20260914.md` and its Figma brief are revised for this candidate: day-first uniform rows as the default, overly neutral urgency treatment, and implied completion through density/fold metrics alone. Now groups attention first; explicit chronological sorting remains in Explore, with actual firings in History. Strong priority cards, clear named attention groups and retained limiting evidence are justified when they help a user decide where to look and what to do. The existing Monitor archetype is not an excuse for a neutral activity log.

Unchanged: shared Macro `alerts.html` target; Terminal files preserved; native alert IDs, source clocks, tiers/severity, canonical score and push authority; no new market-event store, ranker, private inbox, portfolio system, queue or sender. Actual signal/return authority does not increase because a card looks stronger. This is not a broad repeal of the design system or other page architecture.

## 2. Implemented local design changes

- **Review first / Watch next / For awareness**: labels, ordinal marks, placement, scale and restrained semantic colors distinguish attention. Ordinal bars are not confidence, accuracy, expected return or independent source counts.
- **Specific briefs:** important cards show the change, implication, source-shaped before/after or actual separate occurrence dates, decisive limitation and a named next action.
- **Different actions for different information:** sample Macro risk implications, credit conditions, commodity confirmation, theme-rating comparison and underlying alternative-data records have distinct destinations and explanations.
- **Evidence separate from importance:** an important credit warning with mixed cross-asset support remains important to inspect but changes its next step to Compare the conflicting signals / Confirm before changing risk. No certainty score is invented.
- **Takeaway / Evidence / History**: the detail starts with what to do next, supporting and limiting evidence, and what would change the read. Technical receipts are available without displacing the initial answer.
- **Guided review:** Review in order traverses priority alerts. It is navigation only, not a fabricated read/unread or private notification update.
- **Retained power-user behavior:** AND search/source/topic filters, selection and focus return, latest-first exploration, original versus current semantics, missing historical original, source failure, quiet/empty/stale and unknown event date.
- **Responsive/native interaction:** dark/light and EN/ZH; full-screen mobile detail; nested source handoff, explicit modal edge focus, Escape and reduced motion.

All market data is explicitly fictional. Examples preserve the prior prototype's sample event facts and raw priorities and add authored interpretation. The contrasting mixed-evidence control does not mutate the original fixture. No real current market event, user holding, live price, plan execution or notification is demonstrated.

## 4. Source-content contract: the real next dependency

This correction is not finished by CSS. A usable priority alert needs a source-bound brief through the existing assembler and publication plane:

| Customer question | Required content | Boundary |
|---|---|---|
| What happened? | Specific subject/change, native ID and actual event time | Preserve unknown precision, corrections and source identity. |
| How much changed? | Compatible old/new values, state change or observed occurrences | No invented values, incomparable vintages or continuity from repeats. |
| Why care? | Concise event-family implication | Source-owned or reviewed interpretation, not fabricated causality/personal holdings. |
| How much attention? | Existing tier, post-governance severity, priority and relevant freshness | Clear presentation, not a new stock ranking or trade-sizing authority. |
| How much weight? | Confirmation, disagreement, data limitations and family-specific validation | Occurrence confidence, corroboration and forward edge are different. |
| What next? | Specific source-appropriate action and evidence destination | Preserve valid owner actions; do not invent Buy/Sell/Size to make a card actionable. |
| What changes the read? | Supported reassessment condition or stated missing check | No falsely activated semantic monitor. |
| Where is the evidence? | Original source reference, entitled exact link and optional independent current read | No current-data substitution or private data in shared HTML. |

The current source already defines cross-asset tiers, transparent priority and measured family validation. Use that information rather than hiding it or creating another global strength score. The current Design Doctrine requires signal, meaning and next step at a glance, with decisive nulls plain at Tier 1; the rejected design did not satisfy that job merely by looking clean.

The intended explanation path is source-authored content → reviewed family-specific presentation → later citation-bound model assistance. Models can help explain/compare once evidence permits; they cannot silently select/promote events, mint identity, re-rank stocks, size trades or trigger alerts from prose/sentiment. Model outage must not remove source-only usefulness; generic 'inspect evidence' alone is not a complete high-value brief.

First substantive production vertical: one real macro transition or accepted credit event through the existing assembler/renderer into a complete change/implication/action card and actual evidence-return path. Then prove the unconfirmed commodity and theme-rating cases. Preserve source law rather than narrowing the whole program to UI decoration.
