Scope: production-inert extension of the existing research reference, on the same PR/branch. No blocked source reads, benchmark edits, fresh-main comparison, source activation or market outcomes. Direct execution rationale: LOWER_TOTAL_OVERHEAD for a bounded continuation of the owned reference; no worker is displaced.

`window_pressure.measure_windows(bars, memberships, segments, *, start_utc_s, end_utc_s, cutoff_utc_s, config, mode="as_observed")` consumes the existing Bar/Membership/Segment types. The caller still owns identity, calendar, rights, basis and revision qualification. The reducer computes BVC once at the explicit cutoff, then joins security-minute observations to many factors. It never signs precomputed later-cutoff values as earlier knowledge.

The supplied contiguous same-session calendar segments must cover the exact half-open window. Expected cells are members times scheduled minute slots; absent rows are missing, never inferred zero. Explicit zero-volume rows remain zero. All known gross survives even when direction is unavailable. Full-window estimated net requires all expected rows and a numeric estimate in each; policy-neutral gross stays separate from directionally usable gross. Numeric completeness is not accuracy.

Baseline references use the existing MatchKey/Reference, with an identity binding actual sorted membership, mode, estimator, monetary basis, calendar reference and ET anchor/phase shape. Absolute session date does not enter the matching identity. References are absent for incomplete windows or corrected-history mode. All contributing history availability is carried conservatively; it is not independently authenticated by this reducer. No benchmark/market data is invented.

Test-first steps: establish missing-function failures; implement reducer; prove complete/missing/neutral/window/basis/cutoff boundaries; prove split sessions, overlapping union and deterministic replay; then exercise native BVC -> window -> baseline on explicit fabricated prior-session fixtures. Preserve prior source and tests unchanged. Evidence is scoped fixture proof, not market admission or whole-repository CI.


## R2 native deterministic-history serialization reuse — research scalability gate

The pure cumulative `window_pressure.measure_windows` has a local serialization optimization for the legitimate *same-cutoff, overlapping factor* situation. Previously it deep-converted each constituent `PressurePoint` using `dataclasses.asdict` for the union window digest **and again** for every factor that contains the constituent. Those conversions do not estimate any additional return or pressure; they only regenerate identical immutable dictionaries. A synthetic 100-security × 60-minute × 6-factor cProfile sample recorded **37,988 `asdict` calls consuming 1.339 seconds cumulative**, against 2.326 seconds for the whole measured reducer call under profiling.

The accepted reducer now constructs **one canonical `asdict(PressurePoint)` document per admitted constituent minute** after the original single-cutoff BVC pass, then reuses those read-only documents when computing both the entire window's input digest and each factor's membership-specific source digest. The exact original **security-sorted, chronological order** is preserved. The estimator, reference keys, matched-clock sampling, rights/basis/clock behavior, missing vs explicit zero handling, group overlap, point values, and every source/publication/trading authority flag remain unchanged. Caching the materialized objects for the duration of one invocation does not create a cross-cutoff cache, new live ingestion mechanism or independent data/membership owner; the documents cannot outlive a changed source or research information vintage.

Before modifying the source, five synthetic **canonical full-output golden SHA-256 digests** were frozen at the preceding accepted source head (complete, corrected-history, one missing minute, explicit zero volume and multi-phase sessions). All five output digests are **byte-identical after** the optimization. The dedicated golden tests were added to the existing `test_window_pressure.py` suite rather than creating a competing validation workflow. **413/413 complete 13-suite native tests passed locally** on M2 Python 3.12, with the prior structural, quote, data-admission, day-coverage and OOS controls unchanged.

A bounded single-run synthetic observation, **not a production SLO or statistically replicated benchmark**, found 24,000 constituent-minutes across 200 securities, 120 minutes and eight factors reduced from approximately **4.719s to 3.649s** (22.7% observed time reduction). The same process-maximum resident set rose from ~242 MB to ~260 MB; the materialized-doc reuse trades memory for fewer repeated recursive conversions. Smaller scenarios and the five frozen golden hashes are recorded in `evidence/window_history_cache_performance.json`. This does **not** prove the real data/source, latency SLO, customer publish readiness, historical profitability or institutional buying; the pilot still requires original source rights, action-adjusted monetary basis, valid source/reader receipts, PIT membership and release acceptance.
