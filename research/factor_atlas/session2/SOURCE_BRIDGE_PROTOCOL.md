# Factor Atlas Session 2 — owner-shaped minute intake to pure BVC/window preview

**Research implementation only.** The native code is `prototype/intake_bridge.py`; the source material remains under incumbent Terminal/Macro reader, revision-selector, listing, corporate-action, calendar and dataset-licensing ownership. This bridge contains no network, database, options/quote collector, source selector, entitlement service, publish job, auth plane, registry, scheduler or customer interface.

## What the adapter now makes executable

`preview_intake(IntakeScope, MinuteEnvelope*, Membership*, BVCConfig, start/end, cutoff_ns, input_class)` composes the already-accepted **S2-P1 metadata preflight**, original `pressure.Bar` validation and **native cumulative `window_pressure.measure_windows`** without reimplementing any of those owners. The proposed explicit four-name input scope is AAPL/MSFT/NVDA and SPY, with a **source-owner-supplied** calendar. The adapter checks actual one-minute grid, original source and reader receipts, selected revision evidence, unit/basis and action-vintage reference, dataset-use claim, roster subset and a single point-in-time membership mode. No fake source calendar, split adjustment, backdated availability clock or five-minute interpolation is introduced.

Each source-shaped `MinuteEnvelope` carries exactly one `source_preflight.MinuteClaim` plus finite positive closing price, nonnegative volume and optional positive VWAP. An explicit zero-volume owner state is distinguishable from a missing source minute and from a present-positive-volume row. Source/reader availability is conservatively ceiled **up from nanoseconds to a full UTC second** before constructing a `pressure.Bar`—because the native BVC/window core consumes integer seconds. If preflight metadata is complete at a subsecond cutoff but the converted integer-second availability has not occurred yet, the stage is `CUTOFF_PRECISION_WITHHELD`, **never** backdated to an earlier bar-close or reader time. The existing revision selector owns collisions: two selected versions for the same symbol-minute are rejected by the preflight, not independently chosen by Factor Atlas.

Any missing minute, missing/stale receipt, conflicting security listing/basis, unproven price-volume basis, unknown volume, invalid data claim or inconsistent owner role returns no BVC projection. It retains the incumbent preflight reasons and expected/represented/missing denominators. A future out-of-scope appended source row cannot rewrite the previous window's valid prefix or digest. Independently fabricated factor memberships are *test geometry*, not a production point-in-time roster registry.

## The non-negotiable authority distinction

There are exactly two input classes:
- `SYNTHETIC_FIXTURE` — the **only** class permitted to enter mathematical preview. It produces a `WindowPressure` with research authority FALSE, independent gross overlap accounting and in-session BVC estimates. This output has **no market measurement meaning**.
- `OWNER_UNVERIFIED` — even 100%-complete self-asserted metadata, strings that look like rights receipts and SHA-256 hashes, and perfectly plausible market prices return `OWNER_ADMISSION_REQUIRED` with **window=NULL**. It cannot be used to run a real-market pilot or infer source truth.

All outputs permanently retain `status=NOT_ADMITTED`, `source_quality=NOT_ADMITTED`, `source_authenticated=false`, `source_rights_verified=false`, `market_pilot_admitted=false`, `may_execute_market_pilot=false`, `customer_publishable=false` and all five rank/alert/size/trade/publish flags false. The simple type and hash-shape checks **do not authenticate** immutable origin, source rights, reader custody, volume treatment, actual corporate-action vintage, license permissions or real point-in-time membership. This module has no argument for positive admission. It is intentionally a **research preview bridge**, not a competing source-admission or production-authorization system.

The first *real* pilot can be executed only by the current incumbent source/reader owner after a genuinely approved input bundle exists: true one-minute traded price/volume and source response (including actual source-known), Macro reader-completion clock, matched selected revision receipts, action/volume basis, PIT listing/calendar and specific entitlement dataset-use proof. The owner must then integrate the established reader/selector into a separately accepted consumer path; it must not try to make this bridge “live” merely by re-labeling `input_class`. The required Terminal #844 and Macro #8623 source-owner deliveries remain separately Draft/unmerged. The proposed live AAPL/MSFT/NVDA/SPY one-minute and synchronized quote/print cohort is still **NOT_ADMITTED**.
