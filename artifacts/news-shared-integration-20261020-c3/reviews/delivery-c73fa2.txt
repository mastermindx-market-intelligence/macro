**Residuals (non-blocking)**
- Shared default executor: both pools submit via `asyncio.to_thread` → the loop's default executor (`min(32, cpu+4)`). The 8-slot bound limits concurrency but reserves no threads, so a pool task can hold a slot while queued behind unrelated `to_thread` traffic (head-of-line blocking on SSE admission) and conversely delay it. No deadlock — no nested acquisition. The artifact shows this coupling (commit p95 16.56 → 61.34 ms at 32 subscribers). A dedicated executor would decouple it.
- No admission fairness: waiters race on `FIRST_COMPLETED` with no FIFO, so a waiter can be starved under sustained saturation. Not observed in my probes.
- Inherited per-cycle `Path.resolve()` on the event loop at `app/ticker_news.py:919` — present unchanged at `b644688c:925`, so not a regression, but it is the last blocking filesystem call inside the async generator.
- `evidence_for_security`'s `break` leans on the single-writer / status-column invariant; `continue` plus an explicit truncation flag would be sturdier defense-in-depth.
- Per-row thread offload makes stream throughput scale as rows × subscribers against a fixed 8-slot cap — deliberate, but worth a production-sizing note.
