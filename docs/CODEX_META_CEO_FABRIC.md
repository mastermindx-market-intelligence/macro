# Meta-CEO Fabric delegation: attended Codex and Claude sessions

**Scope:** An explicitly Chairman-assigned Mastermind Meta-CEO / principal using a
Codex or Claude harness. This is an operating procedure for an existing session,
not a role grant, a new scheduler, or permission to start an independent project.
An ordinary worker remains a bounded worker.

## First decision: principal judgment versus delegable execution

After recovering the assigned mission, accepted architecture, exact current
source/writer, and live effects, divide the *authorized* next work into:

- **Principal retains:** direction, unresolved C3 architecture, authority/risk
  rulings, tradeoffs, task boundaries, worker-return review, integration and
  acceptance, and meaningful conversations with the Chairman.
- **Fabric leaf:** independently scoped research/census, mechanical transforms,
  implementation under frozen architecture, tests, regression repair, and
  bounded reviewer work. Classify each leaf on *its own* C0/C1/C2 complexity.
- **Occasional coordinator:** a real multi-child domain_orchestration mission,
  only with the existing root grant, operator authorization and meaningful review
  responsibilities. Merely being a Codex subagent is not evidence a frontier
  coordinator is required.

**Delegate before substantial routine execution** when expected worker
framing + execution + verification + repair costs less scarce principal work.
Don't start a child just to reach a concurrency count. Direct principal work is
appropriate for a short critical-path decision or when actual worker admission
cannot lawfully start, with a concrete reason:
`LOWER_TOTAL_OVERHEAD`, `PRINCIPAL_JUDGMENT`,
`UNIQUE_APPROVED_ACCESS`, `CRITICAL_PATH_SHORTCUT` or
`NO_ELIGIBLE_PRE_EFFECT_WORKER`. Do not turn an explicit tool/permission
refusal into a fallback using another carrier/account.

## Codex: the *installed* existing Fabric path

In an eligible attended M2 Codex shell, consult the installed
`mastermind-fabric-delegate` skill and use the incumbent
`fabric_task.py` adapter documented there; **do not** reimplement
SSH, capacity, lease, credential handling, queuing or result retrieval.
The installed adapter's source is in the existing
`.../handoff_kits/meta-ceo-b-2026-09-08/ext/fabric_task.py` tree
and its absolute home path is host-specific. A repository document does not
install or grant this adapter on another device.

1. Verify the actual current Codex native thread identity. Use the real
   `CODEX_THREAD_ID` after confirming it belongs to this session, or an
   already verified original-root binding. Never guess a root, substitute an
   unrelated `CODEX_SESSION_ID`, or treat an environment variable as custody
   authority.
2. Identify *independent* input/artifact scopes and the exact original
   operation. Check whether an Executive/other-carrier submission already
   exists: `QUEUED` is not started, but it must not be duplicated.
3. If the adapter and current shell/permission gate are available, submit
   each new bounded leaf **once** with one stable ID, appropriate
   `--class` / `--task-complexity`, `--root` and `--parent`,
   sending its packet through stdin (not command-line credentials):
   ```sh
   python3 "$FABRIC_ADAPTER" request \
     --id "$CHILD_RUN_ID" --class mechanical \
     --task-complexity C0_MECHANICAL \
     --cwd '~' --root "$VERIFIED_ROOT_ID" --parent "$VERIFIED_ROOT_ID" \
     --stdin <<'WORK_PACKET'
   OBJECTIVE: a single authorized, checkable deliverable
   SOURCE: exact repository, baseline and assigned files/inputs
   LIMITS: preserve current writer, credentials and existing effects
   ACCEPTANCE: tests/artifact hashes, falsifier and compact return
   WORK_PACKET
   ```
   This is a *shape*, not an executable prefilled commission. Supply actual
   stable IDs, source scope, and the installed adapter path at use time.
4. Retrieve `status`, bounded `wait`, and retained `result` by that same
   ID. For generated source, follow the installed adapter's manifest and
   artifact-export/review flow. Exit code zero alone is not acceptance.
5. The Meta-CEO remains productive on integration/risk decisions while
   separate workers run. Record review, authorized repairs and next action
   through the *existing* parent/carrier. `RUN_EXISTS`, effect uncertainty,
   and undelivered results demand original-ID reconciliation, not a new run.

A native Codex `spawn_agent` is **not** a paid Fabric worker. Use a native
child only for a genuinely needed coordinator/reasoning role, never routine
C0/C1 implementation/research when an admitted Fabric leaf is available.
Full-history native forks may inherit frontier context/model/effort and are
not a context-economy shortcut.

## Claude: equivalent principle, same authority

The existing external Fabric/Executive path remains preferred for bounded
independent company work. The selected parent model is not a child model.
Native `Agent/Task` delegates follow their *actual* scoped routing guards,
and are not silently counted as Fabric labor. Do not rewrite older active
native tasks or pretend a provider-facing adapter is available without
installation and real admission proof.

For both harnesses: the **role is assigned by current intent and current
RuntimeBinding**, never automatically inferred from a model label or from
historical chat membership. Keep the same original root and current
workspace/host/provider constraints. An explicit failure or permission
denial is not permission to spawn a native fallback.

## Prevent Meta-CEO context exhaustion

Treat an expensive principal's context as a **decision log**, not a build log.
Give each leaf a bounded packet, not the principal's entire transcript.
Ordinary return to the principal is limited to:

```text
ORIGINAL_ROOT / CHILD_RUN_ID / SOURCE_SHA
STATUS: DONE | PARTIAL | BLOCKED | EFFECT_UNKNOWN
RESULT: decisive outcome (short)
EVIDENCE: exact artifact refs and deterministic tests/review
GAPS: unknowns, regressions and unverified assertions
EFFECTS: mutations, leases, custody and release state
NEXT: parent decision or bounded repair
```

Keep full process logs, traces, diffs, screenshots, and test output in
existing worker artifacts; read selectively when deciding acceptance.
Checkpoint material mission decisions in canonical Agent OS records and
source/PR evidence, not in a parallel memory service. This reduces
frontier-context churn; it does **not** guarantee a model never compacts.
A fresh chat cannot inherit or transfer a live worker lease.

## Admission and proof ruler

- Use actual **ready and non-overlapping** work, provider/model economics,
  provider quotas, per-root fair-share, global descendants, thermal/load/disk,
  workspace custody and the principal's return-review capacity. The configured
  Ubuntu lane ceiling is **not a target** and not available model budget.
- Prefer a small productive wave, consume at least one real result, review it
  against the commission, and only then expand. A worker start is not a result,
  and a result is not merged or accepted production work.
- Compare like-for-like assigned Codex and Fable principals with actual
  root-bound accepted leaf count, delegable-unit offload rate, time-to-first
  admitted worker, valid return rate, principal direct-build tool share,
  frontier context growth, reviews/repairs, and resource refusals. Label
  missing attribution as **UNKNOWN**, not Codex or Claude by filename.
- **Production adoption proof:** an actually assigned fresh Codex principal
  loads the updated repository instructions; makes a lawful same-root
  paid Fabric leaf request through the already-installed adapter;
  observes START and retained result; checks evidence; and records its
  parent acceptance. A merged document, a passing static check, or the
  presence of an adapter cannot substitute for that proof.

This procedure changes no existing permissions, subscription settings,
native agent model defaults, host thresholds, admission/watcher ownership,
CI/merge protection, or private Codex installation.
