## 1. Intent and first acceptance outcome

The investor should be able to tell whether a company's reported growth reflects its disclosed organic demand, pricing/mix, currency or other effects, and whether reported and company-adjusted earnings tell materially different stories. The reader should inspect the exact dated evidence, understand what is not established, and continue to the existing company/research workflow. The machine must produce that explanation from compatible native facts without creating a second financial store or allowing the explanation to change a stock recommendation.

The first production-path issuer is **P&G**. Its next eligible release is chosen through the incumbent source/identity owners at implementation and release time. The July29,2026 release is a reviewed design/regression example, not a permanent current snapshot. One event can exercise reported versus organic sales, volume/price/mix, reported versus core EPS, and quarter-versus-year binding. The first slice is not a global coverage claim or an investment preference for PG.

Hershey's February6,2025 release is a historical regression control for reported and adjusted EPS moving in opposite directions. It must be displayed only in a deliberately historical test/research view, never as current Hershey coverage. R2's Celsius/Simply Good Foods/Hill's/Clorox candidates remain subsequent expansion/regression material; narrowing CDV-1 does not delete those obligations.

Real acceptance requires one authentic release through native source binding, private publication, the existing shared dossier journey, exact source opening and return to the company workflow. A mock, an empty panel, a schema or a successful isolated parser is insufficient. Current inputs must be truthful, optional missing inputs must be clear, and the original theme/entry/rank/portfolio behavior must remain unchanged.

## 3. Alternatives and selected architecture

**Independent Consumer Defensive database and universal rerating engine:** rejected. It duplicates fact, identity, clock, valuation and publication ownership before proving useful output.

**Inject detailed facts and inferred exposure into the existing public company teaser or free-text highlights:** rejected. The teaser is closed and does not supply the needed economic semantics; hiding a data model in prose loses validation and privacy boundaries.

**Selected: native earnings observations, a bounded derived interpretation and an accepted shared display, published through the existing private earnings owner.** Extend the incumbent issuer-profile seam. Preserve native event/workspace identities and generation history. Add an explicitly versioned economic projection to the private earnings record, not another standalone store. The shared dossier renders it. Current financial, GMI and market services contribute only through their supported native interfaces.

CDV-1 requires no generalized K1 cross-owner security recipe. It uses native earnings event/issuer evidence and legal company links. Optional GMI/market context may render as separately typed owner-local sections; an unresolved cross-type join remains visibly unresolved and cannot look like successful unified security analysis. General identity-bridge work stays with its current owner.

## 4. Data path and responsibility

1. Existing collector discovers an eligible source and retains its actual bytes through the approved document owner. Bind the issuer, CIK/accession, exhibit, fiscal period and source revision. A copied research paragraph is not an eligible live source.
2. Existing `event_workspace_build.build_event_workspace` calls an approved PG issuer profile. Native literal facts receive byte-replayable source spans and typed absence when unavailable or ambiguous.
3. A pure bounded interpretation function under the existing Earnings Intelligence/narrative owner consumes selected native facts plus their accepted semantic definitions. It performs permitted comparisons and generates deterministic explanatory blocks. It fetches no internet data and writes no source facts.
4. The existing private earnings publisher validates the native workspace/source references and interpretation, publishes them inside its existing immutable generation transaction, verifies required objects, and promotes its existing pointer last. The public earnings workspace publisher must not receive protected additions.
5. The existing authenticated earnings API reads the private generation after entitlement. The shared STSI/F04 dossier mounts the typed interpretation and provides existing company/source navigation. Browser code performs rendering only.
6. Existing source/revision and publication owners invalidate/rebuild the dependent interpretation when source bytes, mapping or interpretation code change. No new watch service, queue, scheduler or correction store is created.

A stage failure cannot manufacture its predecessor's proof. A valid data object is not proof of source retention; an authenticated API is not proof that another mirror is private; a rendered panel is not proof of correct financial meaning.

## 5. Native observation contract and scope

### 5.1 Bounded source observations

The target native shape remains `event_fact.v1`: fact_id, event_id, metric, value, unit, period, basis and source_span, or the existing typed-absence form. The outer `event_workspace.v1` remains backward-readable. No arbitrary additional top-level fields, JSON encoded in metric names or source values copied into a rival financial ledger.

The first metric selection is bounded to reported revenue growth, issuer-defined organic growth, disclosed volume/price/mix and related bridge components, reported/core EPS with their comparable prior values, and optionally the five reported segment organic-growth observations. There is no requirement to fill every optional metric. Cap the selected display at 24 native observations, four source workspace revisions and 24 comparison rows; these are conservative first-release design bounds, not claims about existing API limits. Final implementation may tighten them after measurement, never silently expand them without owner review.

Source fiscal scope is mandatory. A release containing both Q4 and full-year tables must bind the selected fact to its actual column and interval. A symbol, number or adjacent heading alone cannot establish that scope. Source-defined rounding remains visible. An em dash becomes a numeric zero only where the source's statement/table convention explicitly establishes neutral/zero meaning and the approved profile records that interpretation; an absent cell is not zero.

Metric definitions reside with the existing issuer/financial semantic owner and identify value type (level, growth rate or contribution), unit/scale, organic/reported/perimeter basis, pure versus mixed components, source-native scope and permitted comparisons. They are code-reviewed profile semantics, not a new global sector registry. No claim that these new definitions are already enrolled is made.

### 5.2 Native validation must be strengthened for these inputs

The inspected workspace validator enforces outer structure and selected restrictions but does not prove all nested economic semantics. New PG profile facts therefore require an opt-in strict native validation path with exact keys, finite numeric values, native event parity, source-span/body binding, required period/unit/basis, recognized metric semantics and mutually exclusive present/absent state. It must run before private staging and again at the trusted read boundary. Old accepted workspace behavior must remain unchanged unless an independently accepted migration says otherwise.

A genuine multi-dimensional measure that cannot be expressed by the accepted native event, scoped metric definition, period, basis and receipt is unsupported in CDV-1. Do not approximate a global company/brand identity or insert opaque scope JSON. A subsequent native-owner versioned extension is the gate for broader business-purity or channel observations.

### 5.3 Raw and derived measurements

Literal source-reported growth remains a native observation. A rate calculated from two amounts is a derived comparison, with its formula and input handles. They may differ because the displayed amounts are rounded; preserve both and explain precision rather than overwrite the source rate. No amount-to-growth conversion creates a new filed fact.

For a derived year-over-year rate, require a positive nonzero prior value, matching measure/unit/accounting scope and an explicitly valid pair of comparison periods. Negative or near-zero earnings can still be displayed as levels; a misleading percentage is refused. A year-over-year comparison has different dates by design, so validation checks the expected fiscal pair and duration rather than requiring identical start dates. Cross-basis display is allowed, but it is not a like-for-like subtraction or a choice of a more truthful measure.

## 7. Deterministic interpretation rules

The minimum useful release does not require an LLM call. Use an ordered, source-linked rule library under the existing interpretation owner:

- Positive reported sales growth with source-reported flat or negative organic growth supports the statement that headline growth is not evidence of positive growth in the company's organic measure. It does not prove consumer volumes fell, and rounded flat values are described as reported flat.
- Positive organic growth with disclosed non-positive pure volume supports separating pricing/mix contribution from unit expansion. A combined volume/mix field cannot be used as pure unit volume.
- Reported and core EPS changes in opposite directions are shown as different defined earnings trends. The system does not automatically label core better, cleaner or recurring; it links the company's actual reconciliation and states what adjustments are known.
- A positive gross-margin change without compatible operating/cash measures does not establish operating-profit or cash improvement. These panels stay unavailable rather than infer the missing bridge.
- Segment observations may expose disagreement within the same issuer, but five segment rows do not establish broad category or sector participation.
- Missing licensed consensus produces a clear absence; no management-range or year-over-year comparison becomes a consensus beat. Current `event_workspace` beat/miss restrictions remain intact.

Each output sentence is labeled by derivation class: source disclosure, attributed management explanation, deterministic comparison or proposed research question. Unsupported causal language is excluded. Selection priority is explanatory importance within this one event, not a ranking of securities.

Optional model-written paraphrase is a later capability, not required for CDV-1. It would consume admitted facts, retain claim references and deterministic fallback, use the existing model router, and have no effect authority. A source document is untrusted content; instructions embedded in it never become tool actions or authorizations.

## 8. Time, currentness and corrections

Retain source-document publication separately from SEC acceptance, native first observation, fiscal interval, accepted generation and display build. The existing builder's `source_available_at` means its native SEC-acceptance input and is not silently moved to an earlier website date. Unknown date/time granularity stays unknown.

For the current view, compare the selected accepted event with the incumbent collector's relevant newest-known source state. If a newer source is known but not successfully parsed, show the prior accepted interpretation as dated evidence with current refresh pending. An unchanged successful render does not renew the source's economic freshness. If the collector/currentness reference is itself unavailable, label latest accepted with currentness unverified, not up to date.

Source correction, parser correction, semantic-profile change and interpretation-code change are distinct causes of a new result. Preserve their predecessor references through existing native histories. Old source bytes and accepted as-known results are not overwritten. A historical user query must not fall back to the newest source when the requested vintage is absent. The current quarterly alias selector is not assumed to provide every annual/historical selection mode.

Freshness deadlines come from accepted source/owner schedules and market calendars; no universal number of calendar days is invented for every company and metric. Existing liveness/projection owners receive the exact failed stage and last accepted reference. No dedicated Consumer Defensive daemon or retry plane.

## 9. Privacy, retention and error behavior

All new detailed native/interpretation content defaults protected until existing rights/publication owners authorize its classification. Crucially, reuse of `event_workspace` semantics does not imply publishing the new record through the current public R2 workspace reader. New profile admission must bind to the existing private publication policy; public builders must reject protected fields and objects rather than strip their protection.

Use the current `require_user` then `enforce_site_full(always=True)` order. Entitlement occurs before private storage reads or revealing whether a private event exists. Preserve private/no-store, Vary Authorization, nosniff and noindex/noarchive on success and error. Normal malformed/missing/unavailable outcomes use the existing safe error conventions. No storage credentials, raw object paths, source body or private record existence leaks through an error.

Do not embed protected data in public Git, static HTML/JSON, source maps, a public R2 origin, preload, localStorage, IndexedDB, service-worker caches, analytics or application logs. A paywall on the visible page is not sufficient. Source drilldown must use a current authorized native document binding and honor source display rights; a full source body is not exposed simply because a byte span exists.

Retain source bytes only through the existing approved document/Research Vault owner. A URL or source SHA by itself is not a verified retained artifact. If retention is unknown, research may continue but the live evidence claim is held. Public editorial examples in this research PR do not constitute the protected production snapshot.

## 10. Shared UI and user workflow

The initial mount belongs on the existing US Staples dossier route under the accepted shared STSI/F04 shell. It is an economic research section, not a new primary hero, universal risk label or changes to existing timing. Theme Tracker should link compactly rather than host the full report. Implement no Consumer Defensive-specific duplicate layout system while #7777/shared work is pending.

At desktop width, present a short explanation followed by demand and earnings sections. Every number carries its period and basis. Segment detail is optional/expandable. A single evidence drawer opens the exact source context and native reference, with adjustment and precision notes. Unknown expectations or valuation are plainly labeled without visually dominating the useful explanation.

At narrow width, use stacked labeled rows and an accessible table alternative. Keyboard focus must reach the source drawer and return to the triggering item. Color is supplementary, and reported versus adjusted distinctions survive grayscale. English/Chinese labels retain fiscal dates, units and source-defined terms. No browser calculation may change numeric or qualitative owner conclusions.

A company link requires the existing validated native issuer/listing bridge. A GMI membership link requires an admitted relationship. Without those, the page may show a source-native company name and a limited section, but no purported security-linked portfolio context. Current market-state data and economic evidence preserve their own clocks; a displayed difference can be a scope/time split rather than an error.
