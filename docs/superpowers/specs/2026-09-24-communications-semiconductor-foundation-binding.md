## 4. Compatibility requirements that cannot be assumed solved

### 4.1 Signed financial measures

The inspected codec rejects any value below zero even under `REPORTED_FINANCIAL_MEASURE`. Communications has legitimate losses, cash outflows and negative changes. The existing numerical amendment is still necessary.

Request one shared, definition-bound signed-financial branch. Preserve negative physical-count refusal, finite-number checks, bounded source precision and legacy encoded-byte identity. Do not convert a negative number to its absolute value, hide the sign in prose, or create a Communications codec. The source definition, accepted numeric domain and consumer comparison rule must agree before signed arithmetic is allowed.

### 4.2 Source-only research without fabricated canonical membership

The shared schema currently requires `scope.canonical_theme_id` to be a nonempty string, and `source_ref_for` embeds it. The Communications design deliberately does not mint an advertising theme merely to render research. An arbitrary string that passes JSON validation is not a canonical admission.

Request an owner-accepted representation for source-local/industry research anchors, including immutable reference construction, reader selection and K1 subject handling. Preserve all existing canonical references unchanged. This review does not choose a new URI namespace, sentinel theme ID or global entity allocator. Until an accepted representation exists, hold the affected native assertion admission; continue research and synthetic consumer cases without masquerading as admitted evidence.

### 4.3 Measurement, bounds and comparison identity

The closed shared payload cannot accept arbitrary new root fields. The Communications `measurement_context` proposal must be reviewed into that one payload or mapped losslessly to an equivalent accepted shared representation. Requirements include currency/scale, exact reporting population and interval, definition identity, value/bound meaning, supported rounding, expectation kind and accounting basis. Neither `industrial_context` nor a free-text limitations field is a substitute for enforceable financial meaning.

Keep the existing F04-owned reviewed comparison rule, exact input references and cash-component roles. They are consumer calculation semantics, not a second observation store. Different definition IDs compare only through the exact reviewed relation; a correction invalidates only the results and interpretations that depend on it. Unknown rounding does not become exact; source-signed outflows are not subtracted twice.

### 4.4 Guidance history and owner clocks

Consume the accepted `engine/company_intelligence/guidance_history.py` path where its actual currency, measure, fiscal period, event and comparability contract supports A1. File presence does not establish qualified Meta/Alphabet/TTD/Magnite inputs. Do not create a parallel guidance archive or label a company-outlook comparison analyst consensus. Original-guide versus latest-pre-result-guide meanings remain explicitly separate.

Native evidence blocks remain separately qualified until the existing K1 identity bridge supports more. Source history and system replay remain different modes. Do not fabricate native identity, source-retention or timestamp precision to pass a shared validator.
