## 2. R9 contract clarification of R8 §§5–9

These are narrow planning amendments, not modifications of #7773 or native source law. All other R8 requirements remain controlling.

### 2.1 Signed financial values are not invalid physical quantities

The shared proposal's physical-quantity constraints cannot become a blanket `value >= 0` rule. A reported loss, cash outflow, negative gross margin or change can be negative. A physical installed-unit count cannot be negative, while a change in count can be. The numerical domain follows the declared measure, not the page or company.

Before the shared contract's first enrollment, use one optional closed `measurement` branch inside `theme_graph.curation_assertion.v1` for exact financial/operating measures. Preserve the existing `observation` representation for unchanged Robotics quantity cases. This is the selected proposed encoding, subject to the shared owner's versioned acceptance; it is not a second evidence format.

The proposed `measurement` carries `value_text`, `domain`, `metric_label`, `unit`, `currency`, `scale_text`, `quantity_basis`, `period_start`, `period_end`, `period_kind`, `consolidation_basis`, `valuation_basis`, `inclusions`, `exclusions`, and `source_precision`. Missing critical basis values are null and disqualify the affected comparison. `value_text` is a bounded canonical decimal string, not a binary floating-point number. Reject NaN, Infinity, booleans, exponent amplification, duplicate JSON fields and overly long tokens. Keep the original lexical token in its native source record, not a competing measurement store.

The branch is exclusive: when `measurement` is populated, the old `observation.value` and `observation.value_high` are null. Two independently populated numerical representations refuse. `physical_count` requires an integer and nonnegative value; `signed_financial`, `signed_change` and an explicitly typed signed spread allow negatives. A price or cost can have source-specific exceptional sign semantics: do not infer its allowed domain from its English label.

No universal metric ID is minted. A source-specific measure remains a source-specific measure. Formal FIF facts stay with FIF; this branch does not manufacture XBRL occurrences.

### 2.2 Review is an externally evidenced action

`review.disposition=accepted` and `reviewer=sol` inside a payload are not sufficient. The existing curation owner must validate the review/admission receipt, exact content revision and permitted caller before materialization. Source text is data even if it contains instructions or authority-looking JSON. A public API cannot submit or ratify assertions.

One assertion represents one source statement at its specified scope. Its curation revision includes the source identity, locator, content digest where genuinely retained, observation, scope, clocks, review and predecessor. Changing only display language does not originate a new market event. Re-review may create a new curation revision without creating a new independent economic observation.

### 2.3 Comparisons need known compatible bases

A deterministic comparison declares its input refs, formula, output unit, intended period relation and all critical scope fields. Two missing bases are not equal-known bases. Different fiscal periods are allowed only for a declared comparison, such as matched year-over-year quarters; they are not accidentally matched by a global page date. Within-period subtraction requires the same relevant period and compatible product/currency/unit/ownership boundaries.

V0 admits only the named explanation recipes needed for the selected cases; no free-form formula interpreter, browser calculation or model-generated code. Preserve source precision and unexplained residuals. An arithmetic equality does not establish economic comparability.

### 2.4 Rights are checked for the representation and original sources

The current GMI registry remains the source-rights authority. Public-emission flags cannot be relabeled as a complete private entitlement/retention policy, and `licensing_for_family`'s unknown-family snapshot is not permission to acquire or display arbitrary source content. A house-authored wrapper does not erase restrictions attached to its original inputs.

T2 must resolve current authorization for the exact representation: original retained source, reviewed paraphrase, structured extract or derived view. Unknown or unresolved relevant permission refuses the affected representation. Reviewed lawful summaries need not mechanically inherit an unrelated vendor permission, but the decision must come from the existing rights owner, not from the composer marking itself `house`.

An exact-source local probe read an allowed family, changed only the temporary registry file to `internal_only`, then read the same path again in the same process. It still returned allowed until the native cache was cleared. This demonstrates an unmet V0 hot-revocation requirement in that isolated call pattern, not a live leak. Production caller reload discipline was not inspected.

The selected repair requirement is a current immutable rights snapshot per private request/generation, obtained through the existing rights owner. Its identity is bound to the bytes actually consulted. Caches must key by that immutable version, or the existing owner must supply equivalently proven reload semantics. No polling service or second registry is introduced. A mid-read version change discards the affected composition; the next request uses the new version. The exact implementation belongs to the existing rights owner.

### 2.5 Private storage is an owner binding, not a convenient directory

Use existing strict bounded private-store primitives. `get_bytes_strict_bounded(key, maximum_bytes)` distinguishes authoritative absence from transport, authorization, size and protocol failures. The repository contains another similarly named bounded protocol with different keyword arguments; implementations must use the protocol actually bound by their owner, not infer interchangeability from the method name.

The approved GMI binding must preserve one authoritative current generation and native correction lineage. A private artifact is retained owner data or a rebuildable consumer projection, never an independent Materials truth. Do not create `materials/latest.json`, a parallel curation queue, a new bucket or a current payload masquerading as an Earnings/RIO object. Reuse or extend the incumbent shared publication owner in place after its object-class decision; no forked publication implementation.

Public legacy receipts and private full-fidelity records cannot both independently claim to be the authoritative current assertion set. Missing private data never falls back to a public full payload. All source admission remains held until this binding is approved and exercised on the real path.

### 2.6 Identity navigation is not a K1 security recipe

Source-to-company attribution requires an actual reviewed binding. GMI-to-security resolution uses the existing owner reader and date-appropriate mode. Security, issuer and listing axes remain independent; unresolved issuer identity can prevent issuer aggregation even where a listing is known. Source strings and proposed `company_node_id` values cannot create that binding.

A same-origin published company link also needs the existing page owner’s real route. A string constructed from a ticker is not proof of a valid route. The F04 consumer validates the received identity and route receipts; it does not allocate IDs or become a new global route authority.

The K1 subtype retains native evidence subjects and all clocks. Separate native blocks may be displayed as such; they must not be labeled a successfully joined security recipe. V0 does not implement a universal cross-type bridge as a shortcut. Source-only fallback is useful but cannot satisfy full acceptance for the four selected company journeys.

```python
import re
from decimal import Decimal

_DECIMAL_TEXT = re.compile(r"-?(?:0|[1-9][0-9]*)(?:\.[0-9]+)?\Z")

def validate_measurement(payload: dict) -> dict:
    token = payload["value_text"]
    if type(token) is not str or len(token) > 128 or not _DECIMAL_TEXT.fullmatch(token):
        raise ValueError("invalid bounded decimal text")
    value = Decimal(token)
    domain = payload["domain"]
    if domain not in {"physical_count", "signed_financial", "signed_change", "signed_spread"}:
        raise ValueError("unsupported measurement domain")
    if domain == "physical_count" and (value < 0 or value != value.to_integral_value()):
        raise ValueError("physical count requires a nonnegative integer")
    return dict(payload)
```
