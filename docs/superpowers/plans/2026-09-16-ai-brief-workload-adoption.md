1. Validate the original trusted config through the existing decide_workload
   before legacy translation inserts defaults. Empty/invalid/native profiles and
   custom endpoints return typed refusals before credentials or custom clients.
2. Build eligible providers through existing llm_auth. Policy refusals propagate
   out of its existing waterfall; they are not provider failures or retry grants.
   Recheck before each actual invocation. A profiled SDK TypeError is ambiguous,
   never permission to resend without seed or switch provider.
3. Reuse the existing reply-cache directory. Profiled hashes bind the policy
   receipt and configured model selectors; legacy hashes/text remain unchanged.
   A closed profiled envelope retains actual served-model and provider identity.
   Wrong receipts/origins are misses, never authority. No account-generation claim.
4. Reject observed policy changes during a call/rewrite; do not publish or cache
   the obsolete return. A request already sent cannot be undone by this check.
5. Existing refresh intervals retain a prior artifact only when current policy
   and model identity still match. Recheck after translation before publication.
   A refusal clears model prose and translations while preserving input dates.
6. Existing producer writes the same payload to data/regime and site. The existing
   template shows a bounded English/Chinese notice, not internal refusal codes.

Default/unprofiled operation is deliberately unchanged. This source does not
activate a profile on the VPS and does not qualify arbitrary custom endpoints.
