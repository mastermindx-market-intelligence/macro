## Model routing (STANDING — token economy)

The main session may run a frontier model (Fable/Opus). **Never let fan-outs inherit it.** Workflow `agent()` calls and Agent-tool spawns inherit the session model unless you pass `model:` explicitly — under ultracode that silently burns frontier tokens on mechanical work. Route every spawn:

| Tier | Use for | Never for |
|---|---|---|
| **fable** (main loop + gated spawns/stages) | planning, adjudication, rulings, merges, final synthesis; taste-as-deliverable design (heroes, new visual language) via the gate below; spawns ONLY via `orchestrator` + FABLE-WHY; workflow stages ONLY with a script-level FABLE-WHY (see below) | bulk ×N mechanical fan-outs, ungated workflow stages, anything passing the draft-and-review test |
| **opus** | reviews, judge/red-team critics, stats/math review, hard debugging, user-facing design/UI work (via `designer`) | bulk census, mechanical non-code sweeps |
| **sonnet** | **building code/PRs/refactors/tests (via `builder`)**, census/exploration lanes, mechanical non-code fan-out, doc drafts | final adjudication, user-facing design surfaces (route to `designer`) |
| **haiku** | trivial extraction/format sweeps | anything needing judgment |

Also set `effort: 'low'` on mechanical workflow stages; reserve high effort for verify/judge stages. Rule of thumb (operator 2026-08-17 — reverses the 2026-07-21 "no more sonnet building code" order): **Sonnet builds (via `builder`); Opus reviews and designs; Fable (main loop) plans/adjudicates/merges.**

**Design lane (operator order 2026-07-18 — "design sessions degraded"):** user-facing design/UI work is judgment work, never mechanical — do NOT route it to sonnet builders. Default home = `designer` (opus-pinned agent type; auto-loads the frontend-design skill + DESIGN_DOCTRINE.md). Taste-as-deliverable surfaces that fail the draft-and-review test (hero sections, new visual language, flagship page revamps) → do the design in the main loop, or spawn fable via the existing `orchestrator` gate with `FABLE-WHY: creative: <reason>`. The `builder` agent (sonnet-pinned again, see Build lane below) may implement a *fully specified* design (exact markup/CSS handed to it) — the choice of palette, type, layout, and copy is what must stay with `designer`/Fable. This design-lane restriction is a separate 2026-07-18 ruling and is UNCHANGED by the build-lane reversal below.

**Build lane (operator order 2026-08-17 — reverses the 2026-07-21 "sonnet design and building suck too much for our purposes" order):** code implementation — writing code, PRs, refactors, tests — routes back to **Sonnet**. The `builder` agent type is re-pinned Sonnet (spawns using it pass the guard without a `model:` param); Opus keeps reviewing (`reviewer`). A fully-specified design may still be implemented by the Sonnet `builder`, but design *choices* stay with `designer`/Fable (Design lane above, unchanged — that is a separate 2026-07-18 ruling). Masterplans that say "Opus builds via `builder`" now route to Sonnet automatically — the agent type is unchanged, only its model tier moved back down. **Out of scope for this reversal:** the autonomous metabolism build loop (`scripts/metabolism_build.py`, R-V4-2) stays Opus-pinned unless separately amended — this order covers interactive/orchestrated `builder` spawns only. Recorded as `agentos/decisions/DEC-SONNET-BUILDS-AGAIN.md`, which supersedes `DEC-OPUS-BUILDS-SONNET-EXPLORES-FABLE-GATED`.

**Fable spawn exception (gated):** a single `Agent` spawn may run fable ONLY as the triple `subagent_type: 'orchestrator'` + explicit `model: 'fable'` + a `FABLE-WHY: <orchestration|brainstorm|creative>: <specific reason>` line in the prompt (hook-enforced). Legit = fails the **draft-and-review test** — Sonnet-draft + Opus/main-loop-review would NOT recover the quality: open-ended judgment steering major downstream work, long-horizon orchestration with irreversible mid-task decisions, or taste-as-deliverable creative work. Topic importance alone does NOT qualify (important-but-mechanical → sonnet; critique of an existing artifact → opus). Never fable ×N mechanical fan-outs. **Workflow stages may route to fable (operator re-enable 2026-07-18, "fable ultracode") ONLY when the script carries the same `FABLE-WHY: <category>: <specific reason>` line** — reserve fable stages for judge/synthesis work where the draft-and-review test fails; default synthesis home remains the main loop after the workflow returns. FABLE-WHY lines are the audit trail: grep them periodically for drift.

Enforcement: a PreToolUse hook (`.claude/hooks/model_routing_guard.py`, wired in `.claude/settings.json`) denies Agent/Task spawns without an explicit model, `fable` spawns outside the orchestrator+FABLE-WHY gate, fable-pinned agent frontmatter outside that gate, and Workflow scripts whose `agent()` calls carry no `model:`/`agentType` routing (or route to fable without a script-level FABLE-WHY line). Model-pinned agent types are available: `builder` (sonnet, build lane restored 2026-08-17) for build stages, `reviewer` (opus) for review stages, `designer` (opus) for design stages — spawns using them pass the guard without a `model:` param; `orchestrator` (opus floor; fable only via the gate above, always with explicit `model:`).

**Direct-spawn routing (hook-enforced amendment, 2026-08-17 — semantic ROUTE contract):** every direct Agent/Task spawn declares a semantic `ROUTE: <class>` line; `.claude/agent-routing.json` (execution-policy registry, NOT a strategic control plane) maps each route to its ONE canonical custom agent and model — `extract`→`extractor`(haiku), `census`→`scout`(sonnet), `research`→`researcher`(sonnet), `draft`→`drafter`(sonnet), `analysis`→`analyst`(opus), `debug`→`debugger`(opus), `build`→`builder`(sonnet), `review`→`reviewer`(opus), `design`→`designer`(opus), `judgment`→main loop ONLY (never spawned), `orchestration`→`orchestrator`. The orchestrator seat runs either explicit `model: 'fable'` + FABLE-WHY (unchanged gate, work failing the draft-and-review test) or — for easier orchestration that does not need frontier judgment — explicit `model: 'opus'` with a prompt directive to load the `fable-mode` skill (`.claude/skills/fable-mode`), at roughly half Fable's price and with no FABLE-WHY because no fable is spent; the same skill lets an Opus MAIN session hold the orchestrator role. `model_routing_guard.py` denies missing/unknown routes, route↔agent/model mismatches, under-specified commissions (each route's required `SECTION:` labels live in the registry), and bypass via `general-purpose`/`Explore`/`Plan`/`fork`; a `SubagentStop` hook (`.claude/hooks/agent_return_guard.py`) blocks a routed worker ONCE if its final message misses the STATUS/RESULT/EVIDENCE/GAPS/DEVIATIONS packet, then lets the second stop through (no loops). Treat a guard rejection as feedback — fix the route or commission, never evade the registry to obtain a different model. Frontmatter pins are the runtime truth; `tests/test_agent_routing_control.py` keeps registry↔frontmatter from drifting.
