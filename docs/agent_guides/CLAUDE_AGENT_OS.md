## Agent OS — the company knowledge plane (STANDING)

`agentos/` in THIS repo is the canonical cross-session, cross-model organizational memory for all three repos (macro / terminal / mastermind): workstreams `WS-*`, decisions `DEC-*`, discoveries `DSC-*`, handoffs. **Read `agentos/README.md` before writing there** (schemas: `agentos/schema/`; handoff protocol: `research/MASTERMIND_AGENT_HANDOFF_PROTOCOL.md`). It is a KNOWLEDGE plane, never a control plane (invariant I1): nothing in it gates, dispatches, schedules, or proves liveness — execution stays with the fleet hooks (sessions) and Mastermind `control_plane/` (processes), and a `claim:` is an advisory author's note, never evidence a worker is alive (`DEC:AGENTOS-CLAIMS-ARE-NOT-LIVE-ACTIVITY`). Never create a second store or a local mirror in another repo (`DEC:AGENTOS-HOME-IS-MACRO` — real cross-repo write friction is grounds to supersede that record, never to mirror silently).

- **Task start:** if the task belongs to an existing workstream (check `agentos/workstreams/`, or `grep -rl "<path you'll touch>" agentos/workstreams/` against `owns_paths`), read its `WS-*` record, its latest `agentos/handoffs/<WS-KEY>-*.md`, and the `DEC:`/`DSC:` records they cite. `do_not_redo` entries are binding unless refuted with new evidence. This is context, not permission — Charter, strategic state, authority map, DNR, fleet law, and the assigned directive still govern.
- **During work:** mint a `DSC-<KEY>` when you verify a durable, non-obvious fact future sessions materially need and no canonical doc already records (requires BOTH `falsifier` and `so_what`, else it is a log line); mint a `DEC-<KEY>` when an actual choice with durable consequences is taken — question, answer, rationale, alternatives rejected, evidence, reversibility. Not session logs, not trivia. Account-local memory is NOT company memory: cross-session facts graduate to `DSC-*`.
- **At stop:** a session that claimed a workstream, minted `DEC`/`DSC` records, or leaves work in a state another session must resume writes `agentos/handoffs/<WS-KEY>-<YYYY-MM-DD>.md` in the same PR — cold-stranger test; every `verified:` claim names its command; `do_not_redo` and `danger_areas` populated. The natural moment is right before the session stops. Update the `WS-*` record only when durable state materially changes (status/`next_action` at wave boundaries, not per commit). NOT paperwork: a one-file fix that merges clean with nothing learned needs no records.
- **Hygiene:** `python3 scripts/agentos.py validate` must exit 0 (schema is fail-closed; joins fail open). Cite as `WS:<KEY>`/`DEC:<KEY>`/`DSC:<KEY>` — the colon form, never row/line numbers. Never hand-edit the generated `docs/AGENT_OS_STATE.md` / `data/governance/agent_os_state.json` (nightly is the sole regenerator, `DEC:AGENTOS-NIGHTLY-IS-THE-ONLY-REGENERATOR`); never write `created`/`updated` fields — the generator derives them from git.
