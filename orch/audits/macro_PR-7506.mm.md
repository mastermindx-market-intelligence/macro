## Diff content (exact, scoped to this PR)

**`engine/prophet_candidate_state.py` (+20 / −1)** — additive projector carry + closed-validator round-trip:

- **New import** (top-of-file): `from engine.us_candidate_episode import EpisodeContractError, _parse_episode_id as _parse_b1_episode_id`. The aliasing keeps B3 distinct from B1 even though both reach for the same parser.
- **`_row()` projector** (around line 317): one new line `identity_epoch = _text(episode.get("identity_epoch"), "identity_epoch")` and one new key `"identity_epoch": identity_epoch` in the row dict. All other projector lines (`episode_id`, `security_id`, `company_id`, `candidate_generation_id`, `episode_lifecycle`, `emergence_state`, `maturity_state`, etc.) are byte-identical.
- **`validate_candidate_state_projection()` closed validator**: adds `"identity_epoch"` to the required-key list, then calls `_text(row.get("identity_epoch"), "identity_epoch")`, then re-parses `episode_id` via `_parse_b1_episode_id(episode_id)` and asserts `episode_security_id == security_id` and `episode_identity_epoch == identity_epoch`. A mismatch raises `CandidateStateContractError("candidate identity does not match canonical B1 episode identity")`; a parse failure raises `CandidateStateContractError("episode_id is not a canonical B1 candidate episode identifier")`. The `seen.add(episode_id)` / "duplicate episode_id" check is unchanged. The `duplicate episode_id` raise is unchanged in semantics — it still uses the same key — but the `_text(row.get("security_id"), "security_id")` assignment is now bound to a local `security_id` for the round-trip equality (was previously inline-discarded).

**`tests/test_prophet_candidate_state.py` (+85 / −20)** — fixture helpers + 3 new tests + key rename:

- New helper `cid(label, identity_epoch="epoch_0")` builds a canonical `pe:SEC:US-XNAS-AAPL:<identity_epoch>:sa:<hex digest>:1` B1 episode identifier from a short label. The helper lets existing tests reuse short labels without re-implementing the digest rule.
- Existing `ep()` helper gains an optional `identity_epoch` kwarg and an idempotent prefix guard (`if not str(eid).startswith("pe:SEC:"): eid = cid(str(eid), identity_epoch)`), so all existing `ep("pe:1", …)` calls now flow through `cid()`.
- All hard-coded `"pe:N"` lookups in tests are replaced with `cid("N")` calls — pure renaming, identical semantics. Affected tests: `test_lifecycle_mapping_preserves_source_truth_and_supersession_precedence`, `test_maturity_maps_only_explicit_incumbent_stage_words`, `test_legacy_live_forming_does_not_manufacture_b3_emergence`, `test_projection_is_deterministic_sorted_and_has_no_authority`, `test_validator_rejects_rehashed_trigger_without_source_provenance`, `test_validator_rejects_rehashed_incoherent_maturity`. The maturity test's `topping` (lowercase) source token and its `"UNESTIMABLE"` mapping are unchanged.
- **NEW** `test_projection_preserves_b1_identity_epoch_for_b4_keying`: projects two episodes with distinct identity epochs (`epoch_0`, `epoch_1`) and asserts each row's `identity_epoch` matches the B1 episode.
- **NEW** `test_validator_rejects_rehashed_missing_or_empty_identity_epoch`: projects one episode with `identity_epoch="epoch_0"`, then asserts the validator rejects (a) `row.pop("identity_epoch")` after rehash, (b) `row["identity_epoch"] = ""` after rehash.
- **NEW** `test_validator_rejects_rehashed_identity_epoch_mismatch_with_b1_episode_id`: projects one episode with `identity_epoch="epoch_0"`, mutates `row["identity_epoch"] = "epoch_999"` after rehash, asserts validator raises `CandidateStateContractError`.
