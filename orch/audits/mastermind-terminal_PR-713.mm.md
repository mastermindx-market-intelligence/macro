2. **State + effects** (lines ~38–67):
   - `id = useId()` for `aria-labelledby` pairing.
   - `root = useRef<HTMLElement>(null)` for the panel element.
   - `search = useRef<HTMLInputElement>(null)` for focus/search control.
   - `pendingFocus = useRef<{ removed: string; next: string | null } | null>(null)` for removal focus retention.
   - `query` state + `filtered` memo: filter is `entry.label + " " + entry.tag`, lower-cased, no other field touched; trimmed query (`term = query.trim().toLocaleLowerCase()`); matching is `String.includes(term)`. The filter never edits studies or preferences.
   - **Mount effect** (the popover promotion + focus): records the opener via `document.activeElement` (only when it's an `HTMLElement`), `media = window.matchMedia("(max-width: 860px)")` with feature detection, `syncLayer` promotes the SAME `<section>` element into `popover=manual` on narrow viewports and tears the attribute down + `hidePopover()` on media-change back to desktop — no remount, no portal, no React-tree duplication, no global z-index. Cleanup restores focus to the opener (`opener?.focus({ preventScroll: true })`) only if the opener is still connected. `search.current?.focus({ preventScroll: true })` is called once on mount per the PR body §"real consumer" promise that "search receives focus on open". Reduced-motion is opt-in via CSS media query, not JS.

3. **Removal focus-retention effect** (lines ~70–77): reads `pendingFocus` after each `entries` change; if the removed key is no longer present in `entries`, focus moves to `data-layer-eye` of the removed key's next sibling (falling back to the previous), falling back to the search input if no such row exists.

4. **`remove(key)` helper**: pre-computes the next-focus target (`filtered[index + 1] ?? filtered[index - 1]`) BEFORE the mutation callback fires, then triggers the existing `onRemove(key)` (which performs the actual removal via the parent). No behavior change in the parent contract.

5. **`clear()` helper**: clears `query` state and re-focuses the search field. Bound to the search cancel-`×` button and the "Clear filter" no-match-state button; bound to `Escape` first (clears the filter only) and then on the second `Escape` to `onClose()`.

6. **Rendered surface** (`<section ref={root} className={`ot-root ${styles.root}`} aria-labelledby={`${id}-title`} onKeyDown={…}>`):
   - **Header** — `<h2 id={…}>{t("objectTree")}</h2>` + `<p>{symbol} · {entries.length} {t("smIndicators")}</p>` + persistent close button with explicit `aria-label={t("smClose")}` and `title={t("smClose")}`.
   - **Search field** — magnifier SVG + `<input ref={search} type="search" value={query} aria-label={`${t("drawSearch")} ${t("smIndicators")}`} placeholder={`${t("drawSearch")} ${t("smIndicators")}`} … />`. A cancel-`×` appears only when `query` is truthy. The `::-webkit-search-cancel-button` is hidden via CSS, so the cancel control is the SAME one across browser engines. `aria-label` and `placeholder` both address the search-by-its-meaning rather than "filter" jargon.
   - **Main series row** — quiet symbol card with the candlestick icon, `t("ctvMainSeries")` small label + `<strong>{symbol}</strong>`, and a `t("isTabVisibility")` count badge `visible}/{entries.length}`. The row is non-removable by its parent contract (`noRemove: true` implied for the main series, never carries a remove button).
   - **Grouped study rows** — one `<section aria-labelledby={…}>` per `kind` (`overlay`, `pane`); each group's heading is `t("ctvOverlays")` / `t("ctvSubPanes")` plus a count chip. Each `<li>` has `data-layer-key={entry.key}` + `data-hidden={entry.hidden}`, an icon, the label (wrapping rather than truncating, with the tag shown in small only when it differs from the label), and **two named buttons**:
     - Eye-toggle: `aria-label={`${t(hidden ? "lgShow" : "lgHide")} ${entry.label}`}` + `data-layer-eye={entry.key}` + onClick = existing `onEye(key)`. Hide/show reflects existing `entry.hidden`; the icon swaps between `EYE` and `HIDDEN`.
     - Remove: only rendered when `!entry.noRemove`. `aria-label={`${t("remove")} ${entry.label}`}` + `onClick` = new `remove(key)` wrapper. Protected studies (the existing `noRemove: true` path) never acquire this button — explicitly guarded in JSX, asserted in the seventh component test.
   - **Empty state** — two distinct paths: (a) `filtered.length === 0` while `entries.length > 0` → renders `<p>` with `t("scr2EmptyTitle")` ("No matches") + a "Clear filter" button; (b) `entries.length === 0` → renders `<p>` with `t("ctvNoIndicators")` ("No indicators active.") and NO clear-filter button (clearing an empty entries list is meaningless). The two states share the same DOM role (`role="status"`) so screen readers report either as an SR-friendly status region.
