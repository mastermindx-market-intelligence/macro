## Diff content (scoped to this PR)

**`terminal/components/prophet/SignalCard.tsx` (MODIFIED, +141 / −1 around lines 96–628)** — the structured opportunity band:

1. **Plan shape extension (lines 96–110)** — two new optional fields on `PlanSummary`:
   - `entry_zone?: { low?, high?, chase_above?, zone_class?, stance?, basis?, basis_zh? } | null` — the **structured** producer-owned entry band. Terminal displays it; it never re-derives it. All fields are nullable so a missing zone preserves the prior `ENTRY` rendering byte path.
   - `entry_zone_state?: { state?, stance?, sessions_remaining? } | null` — the **nightly state** of that band. Only a still-live band (`state === "live"`) is drawn as a current opportunity; filled/converted historical bands are not relabelled as a current opportunity.

2. **`entryZoneView(plan, lang)` helper (lines 256–297)** — a pure function returning `{ range, stance, chase, window, aria, color } | null`. Decision tree:
   - Returns `null` if `zone` or `state` is missing, or `state.state !== "live"`, or `planRecommendedAction(plan) !== "wait"`, or `zone.high == null || !Number.isFinite(zone.high)`. The HOLD/TRAIL/INVALIDATED exclusion is the load-bearing branch: a still-live unfilled band disappears once management advances, so it never claims a current action when one no longer exists.
   - `low` falls back to `high` when `zone.low` is null/non-finite (avoids an undefined display when the producer ships an open-ended band).
   - `range = "$${low.toFixed(2)}–$${zone.high.toFixed(2)}"` — two-decimal tabular formatting, locale-independent.
   - `stance` uses a `Record<string, [string, string]>` literal — `{ wait: ["Wait","等待"], starter: ["Starter","试探仓"], accumulate: ["Accumulate","分批建仓"] }` — selected by `pick(lang === "zh", en, zh)` (the `pick(cond, a, b)` helper returns `a` when `cond`, else `b`; used elsewhere in the file). The stance enum is local to this helper (not in `prophetStrings.ts`); PR body §"Non-goals" makes the disjoint-from-`prophetStrings.ts` choice explicit.
   - `chase` is `null` when `chase_above` is null/non-finite; otherwise `"No chase > $X"` (EN) / `"不追高 > $X"` (ZH) with the same `pick(...)` mechanism.
   - `window` is `null` when `sessions_remaining` is null/non-finite/negative; otherwise `"{n} sessions left"` (EN) / `"剩余 {n} 个交易日"` (ZH) — ZH form uses `个交易日` (sessions/trading days), the canonical ZH counter.
   - `aria` is `zone.basis_zh` when `lang === "zh"`, else `zone.basis`, falling back to `undefined` (so `aria-label` is still set via the wrapping `<div>`'s fallback below).
   - `color` is a stance-derived token string: `"var(--up)"` for `accumulate`, `"var(--brand-2)"` for `starter`, `"var(--warn)"` for `wait` (and any unknown stance). These three tokens are already used elsewhere in the component (e.g. stance chips, phase tone).

3. **Wire-in to `SignalCard` (line 350 area)** — `const entryZone = entryZoneView(plan, lang);` immediately below `const origination = planOriginationNote(plan, lang);`. The helper is called once per render and its return is reused for both the relabel and the new panel — no double-evaluation, no `useMemo` needed for a pure synchronous function over a small object.

4. **`entryLabel` → `Plan anchor` relabel (lines 401–403)** — the `<span className="obs-lbl">` becomes `{entryZone ? pick(lang === "zh", "Plan anchor", "计划锚点") : t("entryLabel")}`. The dollar entry value below it (`$${plan.entry.toFixed(2)}`) is unchanged. So when a live zone exists, the row reads `Plan anchor / $50.30` (EN) / `计划锚点 / $50.30` (ZH); when no live zone exists, the prior `entryLabel / $X` rendering is preserved exactly.

5. **New `<div className="obs-prophet-entry-zone">` panel (lines 421–446)** — rendered only when `entryZone` is non-null. Structure:
   - `<div style={ENTRY_ZONE} aria-label={...}>` — outer container with `aria-label = "${Opportunity box / 机会区间}. ${basis}"` when `aria` is present, else `"Opportunity box"` / `"机会区间"`. The label is read aloud as a single sentence (`机会区间. 入场阶梯已经显示的回踩区间`) so screen readers get both the chrome label and the producer-supplied basis.
   - `<div style={ENTRY_ZONE_TOP}>` — top row: label `<span style={ENTRY_ZONE_LABEL}>Opportunity box / 机会区间</span>` + stance pill `<span className="obs-tag" style={{ ...ENTRY_ZONE_STANCE, "--c": entryZone.color }}>{entryZone.stance}</span>`. The `--c` CSS variable on the tag is the same `--c` mechanism the file already uses for stance chips (see the existing `obs-tag` style pattern in this file).
   - `<div style={ENTRY_ZONE_MAIN}>` — main row: range `<span className="num" style={ENTRY_ZONE_RANGE}>{entryZone.range}</span>` + meta `<span style={ENTRY_ZONE_META}>{[entryZone.chase, entryZone.window].filter(Boolean).join(" · ")}</span>` (only when at least one of `chase` or `window` is non-null). The dot-separator (` · `) matches the canonical ZH/EN separator already used elsewhere in this file (e.g. phase meta rows).
   - When `chase` and `window` are both `null`, the meta span is not rendered at all (no trailing dot, no empty cell).

6. **Seven new `React.CSSProperties` constants (lines 579–626)** — component-scoped:
   - `ENTRY_ZONE`: container card with `marginTop: 8, padding: "8px 9px", border: "1px solid var(--line-2)", borderRadius: "var(--r-md)", background: "color-mix(in srgb, var(--panel) 76%, var(--bg))"`.
