## Diff content (exact, scoped to this PR)

**Engine (1 file, +19 / −5)**

`engine/risk_radar_backtest.py` (+19 / −5): two surgical correctness repairs to the EXISTING replay evaluator. (i) `state_accuracy`: requires `type(H) is int and H > 0` (was `int = 21` default only); changes the forward-min window condition from `i + 1 < len(spy)` to `i + H < len(spy)` so a forecast at index `i` only counts when `H` COMPLETE future observations exist; selects from `fdd.index` (non-null outcomes) BEFORE boolean thresholding converts NaN to False, then intersects with `fdd.dropna().index` for the actually-scored population; reports `n_unscored` (count of in-window rows that lacked complete outcomes); returns `None` metrics + `n_unscored` when the scored population is empty instead of dividing-by-zero or fabricating a 0/0 F1. (ii) `compare_calib`: requires all four `base/proposed × full/y2020` F1 values to be `int | float`, finite, in `[0, 1]` — i.e. they must be a numeric measurement, not a `bool`, not a NaN, not an infinite value; sets `out["comparison_ready"] = bool(ready)` so callers see whether the comparison has the evidence to even be evaluated; the complete-data improvement rule `(pf >= bf - 1e-9) and (p20 >= b20 - 1e-9) and legs_ok and (pf + p20) > (bf + b20)` is unchanged.

**Tests (1 file, +76 / −0)**

The fixtures are synthetic — a fixed `30-close / 21-session` series where only 9 sessions have complete 21-day forward windows, plus malformed-score cases (NaN, inf, bool, out-of-band). The tests exercise the new `n_unscored` field, the empty-population null return, the `comparison_ready` field, and the malformed-score refusal.
