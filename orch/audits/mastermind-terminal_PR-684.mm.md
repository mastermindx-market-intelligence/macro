**`terminal/lib/indicator-canvas/render.ts` (MODIFIED, +47 / −7 around `drawCloud`, lines ~510–582)** — the cloud-fill primitive refactor:

1. **Monotonicity pre-pass (loop body)** — a new `let monotonicX = true; let prevX = -Infinity;` is hoisted before the existing projection loop. Each `px[i]` write is now followed by a `if (point) { if (!(point[0] > prevX)) monotonicX = false; prevX = point[0]; }` check. If any two valid `x` coordinates are non-strictly-increasing, `monotonicX` is locked to `false` for the rest of the call and the fallback branch is taken. The check uses `point[0] > prevX` (strict) so equal consecutive `x` (degenerate horizontal runs) correctly miss the fast path.
2. **`CloudRun` type + `runs` collector (new abstraction)** — `type CloudRun = { color: string; seg: Array<[number, number, number]> };` and `const runs: CloudRun[] = [];`. The historical `while (s < n - 1)` loop's "xVisible + push polygon" branch is replaced with `if (xVisible(m, seg[0][0], seg[seg.length - 1][0])) runs.push({ color, seg });` — i.e. the historical segmentation logic is preserved verbatim; only the side-effect changes from "append a `<polygon>` node now" to "record a run for later dispatch". The `if (!px[e]) { s = e + 1; continue; }` valid-endpoint rule is preserved.
3. **Monotonic-fast-path branch** — when `monotonicX === true`, builds `groups: Array<{ color: string; parts: string[] }>`, keyed by color in first-seen order via a `Map<string, number>` (`groupByColor`). Each run's path is built as `M${seg[0][0]} ${seg[0][1]}` for the upper trace, `L${seg[i][0]} ${seg[i][1]}` for subsequent upper points, `L${seg[i][0]} ${seg[i][2]}` for lower points traversed in reverse, then `Z`. All subpaths for one color are concatenated into a single `d` attribute and emitted as one `<path>` with `fill-opacity: alpha` and `stroke: "none"`. Two SVG nodes are produced regardless of how many disjoint runs share a color — one node per distinct color.
4. **Non-monotonic fallback branch** — when `monotonicX === false`, the historical polygon-per-run emission is preserved verbatim (`points: pts.trimEnd()`, `fill: color`, `fill-opacity: alpha`, `stroke: "none"`). Color order matches the input `segColors` exactly.
5. **Final `g.firstChild` early-out is moved** — the historical `if (!g.firstChild) return null;` is removed (now subsumed by `if (!runs.length) return null;` after the segmentation loop). The fragment append and the return are unchanged.

The change does NOT touch `ChartPanel.tsx`, the suite kernel, the signal/event logic, the tooltip hit-testing path, the gradient-stroke path, the gradient-stroke round caps, any CSS, any HTML, any i18n, any chart-pane ownership, or any data authority. The `_` empty-runs early-out is structurally identical to the prior `_` empty-polygon early-out: zero visible runs return `null` and add nothing to the fragment in either world.
