## Diff content (scoped to this PR)

**`terminal/components/levels/LevelsView.tsx` (MODIFIED, +148 / −30 around lines 160–727)** — the collision-free rung layout:

1. **`LEVEL_RUNG_MIN_GAP = 26 / 360` and `LEVEL_RUNG_EDGE_GUTTER = 14 / 360` (new module-level constants, lines 160–161)** — these are the canonical rung/edge gap values expressed as fractions of the rendered board height (i.e. `26px` min gap and `14px` edge gutter at a `360px`-tall board). The numeric scale matches the prior `RUNG` `height: 22` so a `26/360` minimum visible gap preserves the rung's own `translateY(-50%)` without overlap.

2. **`spreadLevelYs(rawYs: readonly number[]): number[]` (new helper, lines 167–192)** — a pure function that takes the projected Y of each located weighted node and returns a parallel array of "display" Ys that are guaranteed not to crowd:
   - Clamps each `raw` to `[floor, ceiling] = [EDGE_GUTTER, 1 − EDGE_GUTTER]` and replaces non-finite values with `0.5`.
   - Sorts the items by `(raw, index)` so the placement algorithm is deterministic and stable (the `index` tiebreak ensures equal raw Ys preserve their relative input order).
   - Computes a `gap = min(LEVEL_RUNG_MIN_GAP, (ceiling − floor) / (sorted.length − 1))` — this is the **hard contract**: gap can never be smaller than `LEVEL_RUNG_MIN_GAP`, and is also shrunk if the canvas simply cannot fit `n` items at the minimum gap.
   - Forward pass: `placed[i] = max(sorted[i].raw, placed[i − 1] + gap)` — every subsequent rung is placed **at least** `gap` below the previous one, but never below the raw price.
   - Backward correction if the forward pass overflows the ceiling: clip the last item to `ceiling`, then walk backward enforcing `placed[i] ≤ placed[i + 1] − gap`. This guarantees both the minimum gap and the ceiling constraint at the cost of one extra pass over `sorted.length` items.
   - Re-projects back to input order via `out[item.index] = placed[index]`.
   - The output array length equals the input length; the output values are in the same `[floor, ceiling]` range as the (clamped) input.

3. **`terrainLayout = useMemo(...)` (new memo, lines 304–313)** — replaces the prior direct `terrainNodes.map(n => projY(n.strike))` use inside the JSX. The memo dependency array is `[projY, terrainNodes]`; the helper returns an array of `{ node, index, rawY, displayY }` so the JSX can render both the exact-price anchor and the readable rung with one map. `projY` is already memoized upstream (the prior code uses it in `voidNodes` etc.), so the new memo does not introduce a new render trigger.

4. **JSX change (lines 477–542)** — the prior single `<button>` per located weighted node is replaced with a `<React.Fragment>` containing three conditionally-rendered children:
   - `RUNG_LEADER` (`<span data-testid="levels-rung-leader" aria-hidden="true">`) — rendered only when `shifted = Math.abs(displayY − rawY) > 0.002`. A 1-pixel-tall vertical line from `min(rawY, displayY)` to `max(rawY, displayY)`. Its `background: rgba(${rgb}, 0.42)` reuses the same `rgb` triple the historical rung uses; the alpha is a one-off for the leader so it reads as a thin connector, not a full rung.
   - `RUNG_ANCHOR` (`<span data-testid="levels-rung-anchor" aria-hidden="true">`) — rendered always when `band` is non-null.
