**`terminal/components/fin/ResearchWorkspaceNav.tsx` (NEW, 248 lines)** — the new compact hierarchy component:

1. **Imports.** `useCallback`, `useEffect`, `useMemo`, `useRef`, `useState` from React; `FinPage` type from `./finPages`; `pick` from `../../lib/finFormat`; and from `./finPageFamilies` the new helpers `defaultPageForFamily`, `familyForPage`, `FIN_FAMILY_ORDER`, `FIN_FAMILY_PAGES`, `FinFamily` type. No other module is imported.
2. **`FAMILY_LABELS: Record<FinFamily, [string, string]>`** — the seven family labels, each as an `[en, zh]` pair: `overview→["Overview","概览"]`, `intelligence→["Intelligence","公司情报"]`, `financials→["Financials","财务"]`, `earnings→["Earnings","盈利"]`, `market→["Market","市场"]`, `ownership→["Ownership","持仓"]`, `lab→["Lab","实验室"]`.
3. **`LOCAL_LABELS: Record<FinPage, [string, string]>`** — the per-page labels, each `[en, zh]`. The mapping deliberately preserves the prior flat-tab labels: `statements→["Statements","报表"]`, `statistics→["Statistics","统计"]`, `revenue→["Revenue","营收"]`, `dividends→["Dividends","股息"]`, `earnings→["Results","结果"]`, `forecast→["Analyst","分析师"]`, `transcripts→["Transcripts","电话会"]`, `technicals→["Technicals","技术面"]`, `seasonals→["Seasonality","季节性"]`, `insider→["Insider","内部交易"]`. Single-page families (`overview`, `intelligence`, `ownership`, `lab`) reuse the family label as their local label — there is no second-control naming the same thing.
4. **`pickLabel(labels, zh)`** — local helper, identical contract to the existing `pick` (returns `labels[1]` if `zh`, else `labels[0]`). Defined here so the component can avoid the `pick` import on the trivial `Record<…, [string, string]>` lookups that `FAMILY_LABELS[family]` already returns.
5. **`chooseFamily(family)` / `chooseLocal(next)`** — both call `onPage(...)`; `chooseFamily` also closes the mobile sheet via `setFamilySheetOpen(false)`. No state mutation beyond the open/close of the sheet.
6. **`moveFamilyFocus(family, key)` / `moveLocalFocus(current, key)`** — keyboard arrow-navigation helpers. Both implement the same `ArrowRight / ArrowLeft / Home / End` rotation contract the prior flat tab bar used (`moveTabFocus` in `MegaPane.tsx`, which is now removed). The helpers call `chooseFamily` / `chooseLocal` to mutate the page state and then `requestAnimationFrame` to focus the new active tab by id — preserving the ARIA tab contract the prior code maintained.
7. **Escape-close effect for the mobile sheet.** When `familySheetOpen` is true, the component adds a `{ capture: true }` keydown listener that calls `setFamilySheetOpen(false)` and re-focuses the trigger. This mirrors the existing drawer/Escape handling pattern in `MegaPane.tsx` (PR body comment §"`handleKeyDown` is installed at the document scope and checks `isDrawerOpenRef.current` so its handler early-returns while a drawer is open").
8. **JSX structure** (rendered as a `<>...</>` fragment with three top-level children):
   - **`<nav className="fin-research-nav" aria-label>`** — the desktop/tablet family+local bar. Contains:
     - `.fin-family-tabs` (role="tablist") with one `<button role="tab">` per family, indexed by `id={"fin-family-" + family}`, `data-fin-family={family}`, `aria-selected={active}`, `tabIndex={active ? 0 : -1}`, `aria-controls="fin-active-panel"`, and the same `ArrowLeft/Right/Home/End` keyboard handler the prior flat bar used.
     - Conditional `<span className="fin-research-nav-divider" aria-hidden />` + `.fin-local-label` (uppercase tracked label, e.g. `FINANCIALS`) + `.fin-local-tabs.fin-local-tabs--desktop` (role="tablist") with one `<button role="tab">` per local page, indexed by `id={"fin-local-" + local}`, `data-fin-local={local}`, `aria-selected={page === local}`. The `localPages.length > 1` guard hides the divider+label+local-tabs row for the four single-page families (`overview`, `intelligence`, `ownership`, `lab`) so they do not render a redundant one-item local row.
     - `.fin-family-mobile-tablist` — hidden on desktop/tablet, visible at `≤860px` per `fin.css`. Contains the single `.fin-family-mobile-trigger` button (`aria-haspopup="dialog"`, `aria-expanded={familySheetOpen}`) with the family label + `⌄` glyph.
   - **Conditional `.fin-local-tabs-mobile`** (visible only at `≤860px`) — a fixed bottom-nav strip (`position:absolute; bottom:0; min-height:72px; padding-bottom:max(12px,env(safe-area-inset-bottom))`) with one `<button role="tab">` per local page. The wrapper rule `.fin-pane:has(.fin-local-tabs-mobile) .fin-body{padding-bottom:96px}` (in `fin.css`) reserves the bottom nav height so body content does not scroll under it.
   - **Conditional `.fin-family-sheet-layer`** (visible only when `familySheetOpen && ≤860px`) — the mobile family map:
     - `.fin-family-sheet-scrim` — full-bleed `var(--pop-scrim)` click-catcher; `aria-label={pick(zh,"Close company page menu","关闭公司页面菜单")}`.
     - `<section className="fin-family-sheet" role="dialog" aria-modal="true" aria-label>` — a 18px-rounded bottom sheet (`max-height:min(72vh,560px)`; `min(78vh)` at `≤420px` to keep the sheet ≥22% of the viewport at narrow phones), containing a `.fin-family-sheet-handle` (38×4 drag-handle pill), a `<header>` with the family sheet title + a `.fin-family-sheet-close` (`×`) button (`aria-label={pick(zh,"Close","关闭")}`), and a `.fin-family-sheet-grid` (`grid-template-columns:repeat(2,minmax(0,1fr))`; `1fr` at `≤420px`) with one `<button data-fin-family-sheet={family}>` per family. Each grid button shows the family label + a `·`-joined local-view label list (`FIN_FAMILY_PAGES[family].map(local => pickLabel(LOCAL_LABELS[local], zh)).join(" · ")`) so the user sees both the family and its local views in one tap.
9. **No state owner outside `familySheetOpen`.** The component owns only one `useState` (`familySheetOpen`) and one `useRef` (`familyTriggerRef`) — both scoped to the mobile sheet UX. All navigation state lives in `page` (the existing `FinPage` prop) and the `onPage` callback the parent passes in. This is the canonical projection-over-state pattern the PR body §"What changes" + §"Collision / ownership boundaries" require.

**`terminal/components/fin/finPageFamilies.ts` (NEW, 44 lines)** — the closed family→page mapping + helpers:

1. **`FinFamily` type** — a closed string-literal union: `"overview" | "intelligence" | "financials" | "earnings" | "market" | "ownership" | "lab"`.
2. **`FIN_FAMILY_ORDER: readonly FinFamily[]`** — the canonical display order, `as const`. Seven entries.
3. **`FIN_FAMILY_PAGES: Readonly<Record<FinFamily, readonly FinPage[]>>`** — the closed mapping:
   - `overview: ["overview"]`
   - `intelligence: ["intelligence"]`
   - `financials: ["statements", "statistics", "revenue", "dividends"]`
   - `earnings: ["earnings", "forecast", "transcripts"]`
   - `market: ["technicals", "seasonals"]`
   - `ownership: ["insider"]`
   - `lab: ["lab"]`
   Each tuple's first entry is the family's default page (`defaultPageForFamily` returns it).
4. **`familyForPage(page)`** — linear scan over `FIN_FAMILY_ORDER` returning the first family whose `FIN_FAMILY_PAGES[family]` includes `page`. **Throws on an unmapped `FinPage`** with the literal `Unassigned Research Workspace page: ${page}`. The throw is load-bearing (the comment explicitly says "Keep a hard fallback instead of silently creating another navigation authority if a future page is added without being assigned to the Research Workspace hierarchy"). This is the right discipline: a closed union mapping that fails closed on drift is preferable to a silent default that creates a phantom family.
5. **`defaultPageForFamily(family)`** — returns `FIN_FAMILY_PAGES[family][0]`.
